# Luminous 产品调研与改版决策库

> 目的：回答「Luminous 从竞赛产品转型为真实用户产品」的三个生死问题——
> ① 用户是否愿意用少量、断续记录换取一个真正了解自己的长期健康伙伴；② 哪些主动建议有用而不烦，用户是否信任跨日、跨月上下文 AI；③ 现有功能哪些是真、哪些是假、怎么改。
> 产出日期：2026-08-15。本目录为调研快照，不随代码演进自动更新。

## 阅读顺序（决策链）

1. **先读方向结论**：`01-产品方向/01-大方向结论与改版策略.md` —— 当前定位、已定取舍、待验证假设和北极星指标。这是本库的枢纽；五个 Tab 尚未作长期决策。
2. **再读市场调研**（`00-市场调研/`，支撑方向决策的证据）：长期健康伙伴用户价值验证 → 原短期事件/用药需求研究 → 竞品 → 商业模式 → 合规。原用药研究只证明用药领域需求，不再外推为整个产品定位。
3. **需要动手时读功能盘点**（`02-功能盘点/`，每个功能点的真伪判定与改造方案）与**路线图**（`03-路线图/`，阶段排期与决策门）。

## 判定基准（本库所有审计统一遵守）

- `Luminous/plans/` 与 `Lucent/plans/` 下的计划**视为已执行完毕**（含法律合规页等），审计只评产品价值与真伪，不评「是否完成」。
- 真伪判定均经抽样读代码验证（AI/分析类功能重点核查是否真接后端、是否占位数据）。
- 结论模板：现状描述 → 实际作用 → 真伪判定（真实现/部分实现/假实现/死代码）→ 结论（保留/改造/删除）→ 改造方案（含 P0/P1/P2）。
- 立场：面向真实用户的生产级产品，不考虑历史投入成本。

## 快速结论

| 问题 | 结论 | 出处 |
|---|---|---|
| 产品方向 | 长期健康伙伴：饮食、饮水、睡眠、心情、症状、活动和用药平级；事件是可选密集介入模式，不是产品总单位 | 01-产品方向 |
| 需求是否成立 | 外部证据可支持低负担输入、个性化反馈和用户可控上下文值得验证；是否愿意长期使用 Luminous 尚无一手用户证据 | 00-市场调研/05 |
| 北极星指标 | 暂定为「有足够数据的用户中，每周至少获得一条有用个性化建议的用户占比」；事件完成数降为场景指标 | 01-产品方向 |
| 变现 | 未决。原事件付费与 CPS 仅保留为历史假设，不进入当前首发默认路径 | 00-市场调研/03 |
| 合规 | 上线必做项按既有计划视为完成；产品红线仍是不诊疗、不开方、不宣称诊断，新增数据用途或渠道时重新审查 | 00-市场调研/04 |
| 真伪总况 | 事件、用药、餐食、提醒和就诊摘要等已有闭环多为真实现；它们是可复用供给能力，不自动构成用户价值。残留假实现集中于本地开关无执行器、死代码、断链和伪临床信息 | 02-功能盘点 |
| 优先级 | 先完成可信输入 → 个人上下文 → 日/周/月洞察 → 主动建议/上下文问答 → 反馈学习的最小伙伴闭环，再做种子验证 | 03-路线图 |
