# 2026-08-16 功能盘点改造决策记录

Updated: 2026-08-16

本文件记录对本批十份功能盘点改造计划已达成的一致决策。十份计划第六节已同步为「已决边界与延期项」；若仍有冲突，以本文件为准。后续若涉及新的医疗判断、外部供应商、用户数据结构或部署成本，须另建任务计划并重新 grill。

优先级继续以各计划既有的 P0/P1/P2 为准。`0.1.0 后`是独立的排期标签，不改变优先级；被明确放到该版本后的事项，应在所属计划项旁标注该标签。

## 产品表面与延期策略

- ADR-0012 已接受：Flutter Desktop 与 PC Flutter Web 停止产品扩展；0.1.0 后启动独立 Next.js + Tauri 桌面工作台 MVP，两者同步交付，不追求手机功能对等。
- GenUI 与桌面高级能力冻结；其余未进入近期排期的能力进入 0.1.0 后 TODO。
- Apple 与微信 OAuth 只在前端隐藏入口；后端回调、既有身份绑定和数据不删除。QQ、微博、Google 继续保留。

## 通知、环境与同步

- 同一用药或建议升级事件最多一次打扰：前台仅应用内提示；后台本地通知优先，失败或不可达才 JPush；站内信只保留记录，不另行弹出。
- 本地通知展示后以稳定通知实例 ID 幂等回写 `local/delivered` 投递记录。
- JPush 密钥、真机到达、未读数刷新和通知页跳转闭环均为 0.1.0 发布门槛；缺任一项不得发布。
- 环境数据只提供用户手选城市的真实天气/AQI 上下文；首次未选城市如实提示；不采集或展示花粉、UV，不作为 Today 主卡，不使用定位、IP 或默认城市推断。
- 健康平台自动同步：首次回补最近 30 天，之后按上次成功点增量同步，并在应用启动时补一次增量。平台与手工记录并列保留来源，不互相覆盖。
- 睡眠提醒接入本地通知执行器，每日只在就寝时间触达；起床时间继续作为记录/分析偏好，不作为闹钟。

## 真实数据、健康规则与 Today

- Lucent 是档案完整度、缺口与 `ObservedMetric` 的权威计算方；客户端只展示。`ObservedMetric` 必须区分 `observed`、`unknown`、`degraded` 和来源/覆盖率，0 不得代替未知。
- 当前硬编码假过敏移除，并在 0.1.0 前接入 Lucent 档案完整度合同。
- 个人基线至少基于 14 天窗口中 7 个有效记录日，采用滚动 28 天中位数；数据不足不推断、不通知。建议升级通知每天最多一条。
- R2 事件期为创建日至结束日；未结束事件持续有效。仅事件期内连续 3 天至少 2 次 check-in 为「加重」，或新增症状记录时，才可触发。
- 回顾图表有数据即展示，无数据不显示；趋势结论至少需要两个不同日期的有效点。
- 普通饮水、餐食、睡眠、心情记录在近 7 天至少 3 条有效记录，或相对个人基线变化至少 50% 时才可进入 Today Analysis 生成队列；所有来源共用每天 3 次分析预算。
- Today 采用数据层 `degraded` + 页面分 section 状态呈现；服务端分析上首屏后，前端本地拼装 bullets 退役。空数据只展示不含 LLM、不计入建议或通知的冷启动引导卡。
- 饮水目标由 `user-settings` 管理；各客户端消费该偏好与 `ObservedMetric`，不自建默认目标。
- 每周纵向洞察只有在至少一个指标存在真实序列时才生成；单点可展示事实，不作趋势结论；完全无观测时不生成、不通知。

## 助手

- 现有受控提案卡的 `confirm` 端点在服务端原子完成真实写入；这不解冻 GenUI。
- SSE 断流保留现有内容，由用户明确点击「继续生成」，不自动重连。
- 长期记忆采用 LangGraph Store 作为持久化/检索层：归档后以后台防抖任务显式提取可删除的结构化摘要或偏好；最多检索 5 条相关记忆；医疗事实仍从业务数据库读取；每条记忆保留 `sourceConversationId`。
- 重新生成/重新发送使用 LangGraph time travel；实现前须核实 Lucent 当前 LangGraph 图、checkpoint 与 message 定位是否满足该能力。
- time travel 第一版仅重生当前会话最后一条助手消息：从 `respond` 前 checkpoint 重放，旧答案保留为修订；须持久化 message→checkpoint 映射和幂等键，不开放任意历史消息分支。

## 用药、扫码与搜索

- 提醒三通道分工遵循本文件通知规则；本地投递历史由客户端幂等回写。
- 纯数字查询不在当前前后端追加特判，移入 0.1.0 后 TODO，待有可验证的条码/批准文号语义再处理。
- 扫码/搜索候选按稳定药品 ID 在客户端去重并合并。
- Today 的 `skip_dose` 使用幂等的 dose-log `mark` 接口：建议卡携带提醒槽位、日期和 `status: skipped`，不依赖既有 dose log 的 `PATCH`。
- AI 药品识别移除硬编码 `0.9` 置信度与百分比呈现；只说明「AI 识别结果，需核对药品名、批准文号和规格」。OCR 或精确条码匹配仅展示各自真实来源说明。
- 0.1.0 前新增加药前风险预检：客户端只提交药品库可信 `source/id`，服务端读取标准成分和规格并与当前药箱比对；失败时只提示加入后可在风险检查中查看，不输出安全判断。

## 报告与导出

- 0.1.0 前移除任意综合健康评分：同步删除服务端 Dashboard 评分计算、PDF 评分卡与 Flutter legacy 模型；保留逐维真实指标和数据不足状态。
- 0.1.0 前让就诊摘要六个开关全部真实生效。每个已选字段严格控制 API、预览、PDF 与公开分享内容；未选 section 不返回、不渲染、不分享。
- 档案、过敏和疾病归入「事件概览」的就诊基础资料；未选择事件概览时不输出。
- 饮水仅输出可解析 ml 的逐日事实；睡眠仅输出正数时长；单点不作趋势，至少两个不同日期才计算趋势。
- 备注默认关闭；显式选择时导出日期、记录类型和原文。创建公开分享链接前必须说明持有链接者可看到备注原文。
- 数据导出当前定义为就诊报告 PDF。0.1.0 前完成 PIN 未启用引导、文案校正及「移入更多」的路由重排；原始健康数据导出列入 TODO。
- 设置页导出入口迁至「设置 → 更多 → 导出就诊报告 PDF」；报告页内导出入口保留。

## 工程与运营

- 队列权威口径为 12 条 Queue 实例：6 条继承 `BaseAsyncQueueService`、4 条业务直建、2 条调度队列；工程文档据此修正，不做队列重构。
- 漏斗 API 暂不建设消费面，移入 0.1.0 后 TODO，目标为受保护的周报或简表，不建设实时 Admin Dashboard。
- 微博与 Google OAuth 图标显示问题列入 TODO。

## 版本标签与恢复规则

- 0.1.0 前：助手 P0 信任项与 P1 一致性/记忆项；扫码详情断链与候选药品风险预检；Today Analysis 主闭环及其诚实性修复；档案假数据治理；报告评分、六字段和 PDF 导出边界；设置的 PIN、通知、会话、导出与 support 清理；用药详情、ObservedMetric 与风险 unknown 呈现；记录摘要/饮水目标；健康事件详情、触发记录与事件通知；通知投递记录、JPush 真机闭环、队列/Admin 文档事实修正与健康平台手动导入小修。
- 0.1.0 后：环境真实化、health_sync 自动同步、助手 P2 呈现/归档项、记录餐食分层与 vital 基建、H-4 事件类型/症状标签、conditions 扩展、处方 OCR 与归档语义增强、桌面 SaaS/monorepo、Worker 分离、rnacos 热配置与运营漏斗报表。
- Flutter 3.47 升级仍受上游 3.47.1 可用性触发，不作为 0.1.0 门槛。
- 0.1.0 后的非冻结事项按既有 P0→P1→P2 和全局依赖顺序恢复；涉及新的医疗判断、外部供应商、用户数据结构或部署成本时，开始前补一页任务计划并重新 grill。GenUI 与桌面高级能力仍需单独解冻。
- 2026-08-16 十份功能改造计划全部完成、验证、追加迁移日志、通过文档检查并按生命周期删除后，才启动错误处理硬切（fpdart + LucentFailure + RFC 9457）；启动前冻结新功能并按 Luminous ADR-0008 与 Lucent ADR-0012 执行双仓契约迁移。
