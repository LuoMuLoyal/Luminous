# Luminous 界面质量差距总账（问题状态 + 目标状态）

> 本文件**只写两件事：现在错在哪、正确应该是什么样**。
> 不写改造步骤、不写迁移顺序、不写代码怎么写——那是执行时的事，不是决策时需要争论的事。
> 每条问题都必须能在当前代码里被指认；每条目标状态都必须可以被判定「达成 / 未达成」。

## 这份文档的回答方式

- **问题**：用「现状」列 + 「证据」列描述，不夹带吐槽。
- **目标状态**：用「应该是」列描述终态契约，是**可验收的命题**，不是愿望。
- **等级**：沿用 impeccable 的 P0–P3（P0 = 阻断或对用户说谎，P1 = 显著伤害，P2 = 困扰，P3 = 打磨）。
- **判定口径**：凡是写着「数量」的地方，都是可被脚本重新计数的；凡是写着「无」的地方，就是该项在代码里应当为 0。

## 一、总分

| 维度 | 现状得分 | 备注 |
| --- | --- | --- |
| Nielsen 十项可用性 | **25 / 40** | 主因：一致性 1–2 分、帮助 2 分、错误恢复 2 分 |
| 技术质量五维（可访问性 / 性能 / 主题 / 平台 / 自适应） | **10 / 20** | 可访问性 1 分是全库最低项 |
| 认知负荷八项 | **4 项直接失败、3 项部分失败、1 项通过** | 唯一通过的是「分组」，且是最近才引入的 |
| 设计特异性 | 中等偏上 | 有真实的产品语汇（剂量、依赖、预警、覆盖率），但视觉语言换到任何「健康/记账/理财」App 都成立 |

**一句话总账**：这个 App 的**数据层、状态模型、错误语义**做得比大多数产品好；**第一公里（新用户为什么相信它）、最后一公里（通知 → 确认 → 失败告知）以及视觉词汇层**是它掉分的地方，而且掉分集中在「用户已经做出了决定之后」的那一段。

## 二、P0 — 阻断与说谎

### P0-1 新用户没有进入产品的路径

| | |
| --- | --- |
| **现状** | 冷启动直接落在今日页，没有首次启动流程；`onboardingCompleted` 字段在客户端**无任何写入方**。健康上下文（过敏、既往、在服药物）只存在于「我的 → 个人档案」，新用户在自己主动记录的那一刻不会被请求提供。 |
| **证据** | `lib/app/router.dart:130`（`initialLocation`）、`lib/features/mine/data/repositories/lucent.dart:173-175`（自述「无任何写入方」） |
| **为什么重要** | 每一个依赖健康上下文的能力（剂量安全、趋势覆盖、完成度）都建立在一组从未被主动收集的信息上，而完成度进度条对所有新用户都从 0% 起步。用户唯一被引导的时机是他已经决定要用了之后。 |
| **应该是** | ①首次启动有明确的第一步，只收最小必要信息；②健康上下文在用户主动记录的那一刻被请求，而不是藏在「我的 → 个人档案」；③完成度表达「还差什么、点哪里补」，而不是只给一个百分比。 |
| **验收** | 新用户完成首次记录所需的点击次数可从图表画出；完成度里每一项缺失都能一键到达对应的表单。 |

### P0-2 点通知进不来，服药闭环断在「已送达」

| | |
| --- | --- |
| **现状** | 用药提醒通知的 payload 只有 `{reminderId, date, time}`；本地通知路由只识别 `action == ai_today_summary` 一种，提醒 payload 没有 `action`，因此**不导航、不弹确认、什么都不发生**。通知点击被记录成「已送达」，永远不是「已服用」。 |
| **证据** | `lib/features/medicine/domain/services/reminder_notification_payload.dart:31-35`、`lib/core/push/message_handler.dart:104-126`（只处理一个 action）、`:20-22`（`medicineReminder → 通知列表`）、`lib/features/medicine/application/.../reminder_delivery_reporter.dart:52-58` |
| **为什么重要** | 这是一个吃药提醒 App 的核心回路：**提醒 → 点开 → 确认**。这一环断掉，App 就退化成「一个会响的日历」；也直接解释了为什么服药依从率只有 82%。 |
| **应该是** | 点开提醒后直接进入这一次剂次的确认面（已服 / 跳过 / 稍后），且确认后通知不再重复；点开的路径与从药盒里点进去**是同一条**，不是两个界面。 |
| **验收** | 从通知点击到剂次状态变更，交互次数 ≤ 2，且中途不出现 tab 根页面。 |

### P0-3 离线写会静默丢数据，且报告成功

| | |
| --- | --- |
| **现状** | `daily_record.create` 离线重放时用乐观本地行序列化，**附件字段丢失**；`daily_record.update` 重放分支注释写「拉取最新并重放」，代码实际是**删掉本地行然后什么都不做**。两者都不报错。 |
| **证据** | `lib/features/record/data/repositories/lucent_daily.dart:251`、`lib/app/composition/record/record_access.dart:43-58`（create）、`:64-72`（update，`deleteById` 后无后续） |
| **为什么重要** | 用户在离线时拍了张照片并保存，联网后照片没了；离线编辑后联网，记录从自己手机里消失而服务端停在旧版本。这是**数据事故**，不是体验问题。 |
| **应该是** | 离线写入的重放必须提交用户当初提交的**完整请求**；任何无法完整重写的状态一律不得进入队列，应在入队时就暴露；重放失败不得删除本地数据。 |
| **验收** | 离线新建（含附件）/ 离线编辑 / 离线删除三类操作在断网-联网循环后，本地与服务端的结果一致。 |

## 三、P1 — 显著伤害

### P1-1 已入队的写入被告诉成「未保存」

| | |
| --- | --- |
| **现状** | 所有 repository 在网络失败时**先入队再 rethrow**，调用方 toast 一律是「未保存」。`PendingSyncDao.pendingCount()` 有实现、**零调用方**——待同步这件事在 UI 上不可见；唯一的同步失败横幅挂在「我的」tab（第 5 个 tab）。 |
| **证据** | `lib/features/medicine/.../dose_marking.dart:74-79`、`lib/features/record/.../create.dart:315-324`、`lib/core/database/daos/sync/pending_sync.dart:211-218`、`lib/features/mine/presentation/components/catalog.dart:64` |
| **为什么重要** | 用户被告知没保存，于是重录一遍——服务器上真的出现了两条记录。**「失败提示」直接制造了脏数据**。 |
| **应该是** | 「已存本地，等待同步」「保存失败」「已同步」是**三种不同的可见状态**，各自有独立的措辞与位置；待同步项在受影响的条目上可见，不必去第 5 个 tab 找。 |
| **验收** | 断网状态下完成一次写入，界面上能同时看到该条目与「待同步」状态，且不出现「未保存」。 |

### P1-2 可访问性：名字、播报、字号三处缺失

| | |
| --- | --- |
| **现状** | ①36 个图标按钮只有 7 个带语义标签；承载全 App 顶栏按钮的共享组件 `IconActionButton` 接收 `tooltip` 却**不转发为 `semanticsLabel`**；②全库 `liveRegion` 与 `SemanticsService` 均为 **0**，保存 / 删除 / 失败 / 可撤销全是 1.8 秒 toast，读屏完全沉默；③系统字号被**主动钳死在 1.2（移动）/ 1.15（桌面）**，用户选多大都没用。 |
| **证据** | `lib/core/widgets/common/control/icon_action_button.dart:27-37`、`back_button.dart:29`、`lib/features/shell/presentation/page.dart:43-44`、`lib/app/bootstrap.dart:125-134`、`lib/core/feedback/toast.dart:55-80` |
| **为什么重要** | 目标人群里老年用户占比不低。这三项合起来意味着：读屏用户不知道按钮叫什么、不知道操作成没成、想看大字也放不大。 |
| **应该是** | ①每一个纯图标控件都有且只有一个可读名称，名称来源于它已有的 `tooltip`，不靠调用方记得补；②每一次异步结果都有可被读屏接收的播报；③系统字号 1.0–2.0 全区间可用，布局按**重排**应对而不是钳制。 |
| **验收** | 用系统最大字号跑通五条主路径不截断；语义名覆盖率 100%；在真实读屏下完成一次保存并听到结果。 |

### P1-3 反馈体系断了：状态富，表达贫

| | |
| --- | --- |
| **现状** | 同步层有结构化错误（`kind/code/statusCode/message/traceId`）、有 backoff、有永久失败停放、有 409 语义；到了界面只剩「重试 / 丢弃」两个按钮和一句泛化文案。重试全部**无二次确认**，丢弃**有**——不对称。冲突没有「保留我的 / 保留服务端」的概念。 |
| **证据** | `lib/core/database/models/pending_sync_error_details.dart:51-66`、`lib/core/providers/network/pending_sync_access.dart:98-117`、`lib/features/mine/.../sync/sync_failures.dart:216-233` |
| **为什么重要** | 用户唯一能做的选择是「重试到天荒地老」或「丢掉我的数据」。冲突本应是最需要人类判断的场景，却把判断权藏起来了。 |
| **应该是** | 少数几类错误有专属呈现（网络 → 稍后自动；鉴权 → 重新登录；冲突 → 两版对照后选择；非法数据 → 明确说哪一条不合法）；「重试全部」有确认；失败指示是**全局**的，不绑定某个 tab。 |
| **验收** | 任意一次 409 与一次 400 在界面上不是同一个界面。 |

### P1-4 一致性：同一个东西有五种长得不一样的实现

| | |
| --- | --- |
| **现状** | 空态：20+ 个私有实现，其中 3 个类都叫 `_EmptyView`，共享 `StateMessageView` 覆盖率不到一半。错误态：8 个功能级自绘错误视图绕开共享组件。状态徽章：**34 个** `*Badge*/*Pill*/*Chip*/*Tag*` 类，唯一公开的那个被塞在 `features/medicine/` 里，于是 review / today / notification 各写一遍。section 标题：7 种。骨架屏：5 个 tab 各写 212–340 行。top bar：3 份。 |
| **证据** | 见 §六「重复实现清单」（含逐项文件行号） |
| **为什么重要** | 这是「五合一产品」观感的真实来源——不是配色，是**骨架**。同一个「进行中」在 review 里是 FBadge 大小，在 medicine 里是 pill 大小，用户学到的规则每次都要重学。 |
| **应该是** | 存在一个**领域无关的原语层**（徽章 / 分组标题 / 空态 / 指标块 / 骨架块 / 顶栏），五个 tab 都从它取件；feature 自行发明同类组件在门禁上没有合法性。 |
| **验收** | `lib/features/**` 下不再出现 `*Badge*/*Pill*/*Chip*` 的私有声明；空态实现数为 1。 |

### P1-5 排版是「手抄的」而不是「命名出来的」

| | |
| --- | --- |
| **现状** | `fontSize:` 全库 1 处（很好），但 `fontWeight:` **295 处**、`letterSpacing: 0` **21 处**，全部手写在调用点。文档宣布「两档字重 w400/w700，没有第三档」，代码里有 5 处 w500/w600，且都在**共享组件**里。行高被统一压到 1.0，字间距却没有任何 token 承载。 |
| **证据** | `docs/reference/design-system.md:64-65`（规则）、`lib/core/widgets/common/control/surface_title_button.dart:40`、`lib/core/widgets/auth/required_dialog.dart:82`、`lib/features/customizer/presentation/pages/page.dart:250` |
| **为什么重要** | 「区块标题是 body.sm + 粗」这条产品决定，现在物理上散落在 144 个文件里。改一次要 grep 全库，不改就永远有第五种写法。 |
| **应该是** | 排版以**角色**命名（区块标题 / 正文强调 / 徽章文字 / 指标数值 / 页面标题），角色自带字重与字距；调用点不再传 `fontWeight:` / `letterSpacing:`。 |
| **验收** | `lib/features/**` 中 `fontWeight:` 与 `letterSpacing:` 出现次数为 0。 |

### P1-6 布局决策读的是「窗口宽」，不是「这一段有多宽」

| | |
| --- | --- |
| **现状** | `MediaQuery.sizeOf(context).width` **115 处 / 72 文件**；`LayoutBuilder` 只有 16 处。桌面端 CRUD 被塞进 560dp 侧面板时，页面仍然按整个窗口宽度判断该不该排双列。 |
| **证据** | `lib/app/router_helpers.dart:81-103`（侧面板）、`lib/features/record/presentation/widgets/sections/dashboard/calendar_panel.dart:279-280`、`lib/features/shell/presentation/page.dart:34-36` |
| **为什么重要** | 同一个页面在「全屏推入」和「侧面板」里是两个产品，而且窄容器里那个是被裁掉的那一个。 |
| **应该是** | 「该用什么布局」由**所在容器给到的约束**或唯一的窗口尺寸档位决定，调用点不再自己读窗口。 |
| **验收** | 在 560dp 侧面板内打开记录详情，渲染结果与 560dp 全屏一致。 |

### P1-7 顶栏一个，但页面标题两套

| | |
| --- | --- |
| **现状** | 今日 / 回顾的顶栏标题居中且字号略小；用药 / 记录 / 我的标题居中且更大；子页（登录、主题、AI 对话）标题居中且有 back 箭头。同一个 App 里存在「tab 根页」和「子页」两套标题规格，同时今日页右侧把「AI 对话」做成**文字按钮**、回顾页同一个功能做成**纯图标**。 |
| **证据** | 渲染截图（今日 / 用药 / 回顾 / 登录 / 主题 / AI 对话）；`lib/features/today/presentation/widgets/shared/top_bar.dart:41-77`、`lib/features/review/presentation/pages/page.dart:200-209` |
| **为什么重要** | 顶栏是用户每次切换都会重新读的区域。标题忽大忽小、同一入口忽文忽图，等于每次都在重新教用户「这一屏是什么级别」。 |
| **应该是** | 一套顶栏规格：根页一种、子页一种（back + 标题 + 可选动作），同一动作在所有页面使用同一形态与同一可读名称。 |
| **验收** | 五个根页的标题排版一致；跨页面出现同名动作时形态一致。 |

### P1-8 页面内部没有主次：所有区块同级

| | |
| --- | --- |
| **现状** | 今日 8 个组件同级平铺；用药 4 个区块同级；回顾默认布局 **16 个挂载点**，而它自称的主职「趋势」排在第 13、14 位。每块都是「标题 + 白卡」，标题字重一样大。唯一真正的主操作（今日服药）被放在卡片内部、指标条下方。 |
| **证据** | `lib/features/today/presentation/components/catalog.dart:41-65`、`lib/features/review/presentation/components/catalog.dart:129-131`、`lib/features/medicine/presentation/components/catalog.dart:34-41`；渲染截图（用药页：3 张白卡等宽等高） |
| **为什么重要** | 主次不靠视觉靠滚动位置，用户得先滚完才知道重点在哪。回顾页直接违背了自己的命名：说要看趋势，先给 12 块别的东西。 |
| **应该是** | 每个表面有一个明确的**第一优先内容**，视觉重量（位置 + 尺寸 + 对比度）都指向它；其余内容是第二、第三层。回顾页的「趋势」在第一屏可见。 |
| **验收** | 遮住文字只看灰度图，仍能指出哪个是当前页面的主内容。 |

### P1-9 表单：一次只报一个错，脏检查漏掉一半字段

| | |
| --- | --- |
| **现状** | 记录新建页最多 16 个输入框（睡眠类多 8 个）在一条不分组的长滚动里；校验**第一个失败就 return**，所以两个字段都错时用户要提交两次才知道；`_isDirty` 只看 4 个文本控制器与图片，**时间、日期、类型、7 个睡眠字段都不算脏**，改完这些按返回直接丢弃且不提示。提醒表单的校验错误用 **toast** 报，且服务端返回的具体原因被替换成固定文案；该页有 9 个本地状态却**没有返回拦截**。 |
| **证据** | `lib/features/record/presentation/pages/create.dart:256-279,444-456`、`lib/features/record/presentation/widgets/forms/record_create_form.dart:97-160`、`lib/features/medicine/presentation/pages/reminder/edit.dart:75-79,258-270,464-468` |
| **为什么重要** | 用户在「已经填完了」之后才被逐个驳回，最消耗耐心；改完睡眠时间再返回，输入直接蒸发且系统认为你没改过。 |
| **应该是** | 一次显示全部错误且贴在字段上；脏检查覆盖所有可变字段；有未保存内容时返回必须给用户一个选择；错误文案使用服务端给出的具体原因。 |
| **验收** | 两个字段都非法时一次提交即可看到两处错误；仅修改睡眠时间后返回，出现放弃确认。 |

### P1-10 搜索：失败态给出的出路是死路

| | |
| --- | --- |
| **现状** | 搜索是**提交式**不是即输即搜；切换数据源会清空结果并**要求用户再按一次搜索**，而「0 结果」页面提供的恢复按钮「切换数据源」正是这个动作——点完回到空页，查询词还在但没被执行。移动端结果卡片**不可点进药品详情**，只有桌面端可以。 |
| **证据** | `lib/features/search/presentation/providers/medicine_search.dart:96-122`、`lib/features/search/presentation/widgets/views/results.dart:203-205,280-284,377-433` |
| **为什么重要** | 这是使用频率最高的路径，而它最常见失败状态（搜不到）的出口是个循环。同时最需要看禁忌的地方（详情页）在手机上根本到不了。 |
| **应该是** | 切换数据源自动执行当前查询；0 结果直接给出可执行的下一步（换源重搜、改用拼音、拍照识药）；结果与详情之间的关系在所有端一致。 |
| **验收** | 从 0 结果到有结果，用户不需要手动再触发一次查询。 |

### P1-11 架构门禁在红灯上

| | |
| --- | --- |
| **现状** | `--clean-layers` 当前 **26 条违规**（跨 feature 24 + 目录文件数 2）。AGENTS.md 把它写成 pre-push 真门禁，因此现状等价于「本地推送全靠 `--no-verify`」。 |

## 七、Token 逸出底账

| 类别 | 现存 token | 逸出量 | 结论 |
| --- | --- | --- | --- |
| 颜色 | `SemanticColor` 6 × 10 档 = 60 | 特征代码内 `Color(0x…)` 20 处（其中 15 处是品牌/协议色，10 处是主题预览表） | **基本合格**；问题在「预览表与运行时不一致」而非「用了 hex」 |
| 间距 | `Spacing` 12 档 | `EdgeInsets` 数字字面量 19 | 合格 |
| 圆角 | Forui `borderRadius.*` | `BorderRadius.circular(n)` 字面量 1 | 合格 |
| 字号 | Forui `typography.*`（734 次引用） | `fontSize:` **1** | 优秀 |
| 字重 | 无 token | `fontWeight:` **295** | **不合格 — 没有角色层** |
| 字距 | 无 token | `letterSpacing: 0` **21** | **不合格 — 约成被抄成惯例** |

| 图标尺寸 | `IconSizeTokens` 8 档 | 字面量 21 | 部分不合格 |

| 渐变 / 阴影 | `GradientTokens` / `ElevationTokens` | 内联各 1 | 合格 |

## 九、做得好、要保住的部分

写在这里是为了防止后续整改把好的部分一起拆掉：

1. **读状态模型**：`PageViewState` 六态（加载 / 刷新中 / 陈旧 / 致命错误 / 数据不足 / 就绪），失败刷新**保留旧数据**，离线和陈旧各自有横幅且不挤压布局，超 6 秒给的「加载较慢」提示。多数 App 会把它塌缩成一个转圈。
2. **破坏性操作纪律**：11 处删除/注销全部走共享确认对话框，没有一次点击就删的地方。
3. **i18n**：2193 条消息，英中**零缺口**，widget 里硬编码文案 **0** 处（6 处 `Text()` 字面量全是数字拼接）。分片 ARB → 合并 → gen-l10n 的流程是真的在跑。
4. **图标族收敛**：`FLucideIcons` 2254 次，iconMind 已彻底退场，语义注册表 178 条、662 个调用点——「一个语义一个字形」这条纪律真的在守。
5. **回顾页与「我的」页的空态**：都说清了「缺什么、缺多少、点哪里补」。这是全 App 最好的两个空态，P0-1 的正确形态可以以它们为蓝本。
