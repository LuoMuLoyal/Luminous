# Record 快速记录 UX 优化计划

Last updated: 2026-07-28

## 目标

把 Record 页快速记录区从“点入口后仍然要填小表单”改为真正的快速记录：

- 单击优先直接完成一个合理的默认动作。
- 需要用户选择时，用轻量 sheet/dialog，点击选项后尽快完成。
- 无确认的即时写入动作提供底部可撤销 toast；已经过明确确认的写入不强制撤销。
- Record 负责“事实发生了什么”；Medicine 负责“药物计划、安全解释和风险边界”。

## 当前代码/合同事实

- Record 当前快速入口在 `lib/features/record/presentation/widgets/sections/quick_entry_panel.dart`。
- 当前快速选项弹窗在 `lib/features/record/presentation/widgets/dialogs/fast_entry_dialog.dart`。
- `DailyRecordKind` 没有 medication；Record 的用药入口是 `RecordEntryType.medication`。
- daily record 已支持 `create/update/delete`，所以饮水、症状、情绪、餐食、睡眠等撤销可以真实删除刚创建的记录。
- Medicine dose log 前端已有 `mark/update/create` 包装；Lucent OpenAPI 已暴露 `DELETE /api/v1/user/medicine-dose-logs/{id}`，所以用药撤销也应走真实回滚，而不是跳编辑。
- 餐食图片链路已有 `image_picker`、压缩、`uploadImage`、attachments 和 meal analysis 字段，快速餐食应复用这条链路。
- 睡眠完整记录已有 `payload.durationMinutes/startAt/endAt/quality/deepMinutes/lightMinutes/remMinutes` 结构。

## 已确认决策

### 实施策略

采用全量重构方案，而不是只做渐进增强。

- 重构目标不是单纯拆文件，而是建立快速记录的行为内核、可撤销写入机制、设置模型和类型专属交互。
- 可以接受实现阵痛，但必须分阶段验证，避免一次性改坏 Record 页主流程。
- `quick_entry_panel.dart` 当前过大，重构时应把布局、设置入口、快捷项状态、动作执行和各类型 sheet 拆到清晰边界。

### 架构边界

快速记录重构拆成 4 层：

1. `QuickEntryPanel`：只负责网格、角标、header 设置入口、长按入口等展示。
2. `QuickEntryController / QuickEntryExecutor`：接收动作并决定直接写入、打开 sheet、请求相机、跳设置或跳添加药品。
3. `QuickEntryUndoService`：统一处理可撤销 toast，记录本次动作创建/修改的对象，并按类型回滚。
4. 类型专属 flow：`water_flow`、`medication_flow`、`symptom_flow`、`meal_flow`、`sleep_flow`、`mood_flow` 分别处理各自 UX 和边界。

目标是让快速记录成为可扩展动作系统，而不是分散在 panel/page/dialog 中的按钮回调。

### 撤销语义

撤销必须是真正回滚，不是跳转到编辑页，但不是所有写入都必须显示撤销 toast。

- 无确认的即时写入必须显示底部可撤销 toast，例如单击饮水直接加 `250 ml`、单击一种药直接标记已服、单击开始睡眠。
- 已经过 sheet/dialog 明确确认后才写入的动作，不强制显示撤销 toast；可以只显示普通成功反馈，避免重复打扰。
- daily record：撤销删除刚创建的记录。
- dose log：撤销回滚刚才的变更。若操作前没有 dose log，则删除新建 log；若操作前已有 log，则恢复旧状态。

### 用药入口的数据源

Record 用药入口读取“当前用药盒”为基础，叠加“今日提醒计划”增强。

- 药箱决定可快速记录哪些药。
- 今日提醒计划决定默认选中哪些药、是否绑定 reminder slot、Medicine 今日计划如何同步。
- 不只读取提醒计划，因为很多用户会添加药品但不会设置提醒；只按提醒计划会让快速用药对这类用户失效。

### 多药默认选择

多药情况下，不默认全选药箱全部药品。

- 如果当前时间附近存在 pending reminder slot，默认选中这些 slot 对应的药。
- 如果没有明确 slot，默认不选中，由用户点选。
- 可以提供“全选”操作，但不能把药箱全部药品作为默认确认内容。

### 当前时间附近 slot 窗口

用药快捷入口判断“当前时间附近 pending reminder slot”的窗口为：当前时间前 30 分钟到后 2 小时。

- 允许用户略早服药。
- 覆盖用户忙完后补确认的真实场景。
- 超出窗口的计划不默认选中，避免把早晚不同药物误选进同一次服药。

### 无当前用药时的用药入口

0 种当前用药时，首版不允许创建无归属手动用药记录。

- 点击 Record 用药快捷入口时弹出轻量确认提示：当前没有药品，询问是否去添加药品。
- 主操作为“添加药品”，取消则关闭提示。
- 添加药品后应尽量能回到本次快速记录流程，减少用户重新找入口的成本。
- 不创建无归属用药事实，避免 Medicine 风险检查、依从统计、提醒联动和 Report 解释出现低质量数据。

### 睡眠临时记录 payload

睡眠开始/醒来使用临时 sleep event payload；合并后使用现有完整 sleep payload。

开始睡眠：

```json
{
  "sleepEvent": "start",
  "eventAt": "2026-07-28T23:15:00.000Z"
}
```

醒来：

```json
{
  "sleepEvent": "wake",
  "eventAt": "2026-07-29T07:10:00.000Z",
  "startedRecordId": "record-sleep-start-123"
}
```

合并后的完整睡眠记录：

```json
{
  "durationMinutes": 475,
  "startAt": "2026-07-28T15:15:00.000Z",
  "endAt": "2026-07-28T23:10:00.000Z"
}
```

- `sleepEvent` 避免和完整睡眠的 `startAt/endAt` 混淆。
- 临时记录可在时间线显示为“开始睡眠 / 醒来”。
- 合并确认后删除临时记录并生成标准 sleep payload。

### 饮水默认动作

饮水快捷入口单击默认记录 `250 ml`。

- `250 ml` 兼顾低摩擦和可统计性，比 `1 次` 更适合 Today/Report 汇总到饮水目标。
- 快速记录设置中允许用户改为 `1 次`、`500 ml`、`1 杯` 等。
- 更多饮水选择通过长按捷径或快速记录设置页进入；首版不做双击入口。

## 初步交互方向

### 手势原则

确认原则：单击承载主路径；长按只做设置/更多操作捷径；首版不做双击核心交互。

- 单击是唯一必须可发现、可依赖的快速记录动作。
- 长按可以作为进入单项快捷设置的加速方式，但同一设置必须能从 Record header 的快速记录设置页进入。
- 双击在移动端可发现性弱，且容易和单击延迟/误触冲突；首版不作为快捷记录能力。
- 每个快捷项的默认行为应该可配置，但配置项不要暴露成“单击/双击/长按三列表格”。设置页应按记录类型组织，例如“饮水默认值”“餐食默认打开相机”“睡眠单击开始/结束记录”。

### 用药

- 0 种当前用药：显示轻量确认提示，引导去添加药品，不创建无归属记录。
- 1 种当前用药：
  - 单击直接记录当前时间已服用。
  - 若当前时间附近有 pending slot，调用 slot-aware mark 并同步 Medicine 今日计划。
  - 若没有提醒计划，也创建/标记一条归属于该 current medicine 的 dose log。
  - 这是无确认即时写入，成功后底部 toast 可撤销。
- 2+ 种当前用药：
  - 打开选择 sheet。
  - 当前时间附近有 pending slot 时默认选中对应药；否则默认不选。
  - 用户确认后批量写入 dose logs。
  - 用户已明确确认，不强制显示撤销 toast。

### 症状

- 单击入口打开常见症状 sheet。
- 默认单选：点一个症状立即按当前时间保存。
- sheet 内提供多选入口；进入多选后点症状只切换选中状态，底部显示确认/取消。
- 单选点症状即保存时显示底部可撤销 toast；多选确认后不强制撤销。

### 饮水

- 单击按用户默认动作直接记录一次，首版默认 `250 ml`。
- 默认动作可配置，例如“1 次”“250 ml”“500 ml”“1 杯”。
- 快速记录水入口右上角显示今日饮水次数/数量角标。
- 更多饮水选择通过长按捷径或快速记录设置页进入；首版不做双击入口。
- 单击即时写入成功后显示底部可撤销 toast；经选择/确认后的写入不强制撤销。

### 餐食

- 单击优先调用相机。
- 拍照后回到 Record，打开轻量确认 sheet，用图片辅助 meal analysis。
- 无图片轻量表单通过长按捷径或 sheet 内备用入口进入；首版不做双击入口。
- 经过轻量确认 sheet 保存后不强制显示撤销 toast。
- 餐食撤销不承诺删除云端图片文件；前端只回滚 record 和 attachment 元数据，远端对象清理由后端合同或异步清理承担。

### 睡眠

- 单击没有进行中睡眠时：立即创建“开始睡眠”记录，并 toast 可撤销。
- 快速入口角标显示“正在记录睡眠”。
- 再次单击时：先创建“醒来”记录，再展示确认合并 sheet。
- 合并 sheet 展示入睡时间、醒来时间、总时长，支持跨天夜间睡眠和不跨天午休。
- 用户确认合并：删除/替换临时记录，生成一条完整 sleep record。
- 用户取消合并：保留开始/醒来两条事实记录。
- 即时创建 start/wake 时显示底部可撤销 toast；合并确认后不强制撤销。

### 情绪

- 入口打开情绪选择 sheet。
- 点某个情绪立即按当前时间保存。
- 成功后 toast 可撤销。

## 设置入口方向

新增 Record 自己的快速记录设置入口，而不是把所有设置塞在 quick panel header。

- Record header 放主入口；用户初步想法是 header 左侧设置图标。
- Settings 放次入口。
- Mine 不放入口；这属于设置职责，不应让 Mine 变成杂物入口。
- 原动态排序/手动排序迁移到该设置页。
- 水的默认单击行为放到该设置页。
- 快速区原 header 的动态排序位置改为帮助/提示按钮。
- 提示按钮说明单击、双击、长按等默认行为，降低认知成本。
- 长按可以作为快捷进入单项设置的增强手势，但不应是唯一入口。

### 快速记录设置页

设置页命名为“快速记录设置”，只管理 quick entry，不承担整个 Record 页设置。

- Record header 主入口放右侧，与 NLP/sparkles 入口并列；不放左侧，避免和返回/页面层级语义冲突。
- Settings 放次入口。
- 手动排序使用独立子页或子 sheet，不在设置页原地切 reorder mode。

设置页结构：

- 排序：
  - 动态排序开关。
  - 手动排序入口。
  - 重置为默认顺序。
- 默认动作：
  - 饮水：单击记录 `250 ml`。
  - 餐食：单击打开相机。
  - 用药：按当前提醒默认选中。
  - 睡眠：单击开始/结束睡眠记录。
  - 症状/情绪：点击选项即保存。
- 显示：
  - 饮水角标：显示今日累计量 / 今日次数 / 不显示。
  - 睡眠进行中标记：默认开启。
- 帮助：
  - 单击执行默认动作。
  - 长按进入更多/设置。
  - 首版不提双击。

首版可配置项：

- 动态排序开关。
- 手动排序。
- 重置默认排序。
- 饮水默认量。
- 饮水角标显示方式。
- 睡眠进行中标记开关。

首版仅展示规则说明、不提供配置的项：

- 用药：按当前药箱和当前时间附近提醒 slot 智能选择。
- 餐食：单击打开相机，确认后保存。
- 症状：单选点选即保存，多选需确认。
- 情绪：点选即保存。
- 睡眠单击开始/结束规则若“进行中标记”关闭，行为仍保持不变，只是不显示角标。

这些说明应做成简短状态行/说明行，避免长篇说明书式文案。

当前轮次暂无已识别的阻塞问题；下一步把架构、交互、设置和异常态整理成完整设计草案。

## 异常态规则

### 全局规则

- 无确认即时写入失败：必须 toast 明确失败，不更新角标/进行中状态，不显示撤销。
- sheet/dialog 确认写入失败：保留 sheet/dialog，不关闭；显示内联错误或 toast，让用户能重试或取消。
- 部分成功：提示“已记录 N 项，M 项失败”，失败项留在 sheet 里可重试。
- 撤销失败：toast 提示撤销失败，并刷新数据，不假装撤销成功。
- 离线/入队成功：如果 repository 是 optimistic/pending sync，用户层可以视为“已记录”，撤销也应能撤本地 pending 记录；实现时需确认 dose log delete 是否支持 pending sync。

### 饮水

- 保存失败：toast 提示记录失败，请重试。
- 快速连点：允许连续点，每次单独创建记录；角标按成功结果刷新。
- 撤销：只撤最近这一次，不撤连续多次全部。

### 用药

- 药箱加载中：tile 进入 loading/禁用，点击不执行。
- 药箱加载失败：弹错误 sheet，提供重试/去 Medicine。
- 0 药：确认框引导添加药品。
- 多药确认部分失败：成功项禁用或标记，失败项保留可重试。
- 当前 slot 已被标记 taken：不重复写入，提示已记录，并刷新 Medicine 状态。
- 撤销失败：刷新 dose logs，提示失败。

### 餐食

- 相机权限拒绝：弹引导，提供去系统设置和手动记录。
- 用户取消拍照：不写入，不 toast。
- 图片处理/上传失败：停留在确认 flow 或回到手动表单，提示可重试。
- meal analysis 失败：不阻塞记录保存，记录仍保存，详情页显示分析失败。

### 睡眠

- 找不到进行中 start：单击创建 start。
- 找到一个 start：单击创建 wake，然后弹合并确认。
- 找到多个 start：弹选择 sheet，让用户选要结束哪一段，不自动猜。
- start 和 wake 时间相同/负时长：不合并，提示异常，保留事实记录。
- 跨天：按实际 ISO 时间计算，不按当前选中日期猜。

### 症状/情绪

- 选项保存失败：不关闭 sheet，保留可重试。
- 多选部分失败：失败项保持选中，成功项标记已记录。
- 情绪不做多选。
