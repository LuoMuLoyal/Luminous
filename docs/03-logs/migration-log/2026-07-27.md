### 🔴 严重：`_parseOptionalDateTime` 未捕获 `FormatException`（`lib/features/auth/data/datasources/auth.dart`）

## 新增 EnvelopeInterceptor：拦截器层统一校验业务 envelope

### 背景

`response.data!.data` 强制解引用存在两层风险：
1. **业务错误 `data: null`**：后端返回 HTTP 200 + `{ code: 401001, data: null }` 时，生成的 `fromJson` 因 `@JsonKey(required: true)` 抛出 `CheckedFromJsonException`，此异常未被 `ErrorInterceptor` 捕获，以原始 `DioException(type: unknown)` 传播到调用方。
2. **空响应体**：后端返回 HTTP 200 + 空 body 时 `response.data` 为 null，`response.data!` 直接崩溃。

根因：拦截器链 `[AuthInterceptor, RetryInterceptor, ErrorInterceptor]` 全部只实现 `onError`，缺少 `onResponse` 校验。

### 改动

- 新增 `EnvelopeInterceptor`（`lib/core/network/interceptors/envelope_interceptor.dart`）：
  - `onResponse` 中检查 HTTP 200 响应的 envelope `code` 字段
  - `code != 0` → reject 为 `DioException(type: badResponse)`，携带 `LucentApiException`（`networkErrorCode: businessFailure`），阻止业务错误响应到达生成代码的反序列化阶段
  - 响应体为 null + 2xx 状态码 → reject 为 `LucentApiException(networkErrorCode: emptyResponse)`
  - 支持 `skipEnvelopeCheck` extra 选项跳过（预留文件下载等场景）
  - 非 envelope 响应（无 `code` 字段的 Map）直接放行

- 注册到拦截器链（`lib/core/network/dio_client.dart`）：
  ```
  [AuthInterceptor, RetryInterceptor, ErrorInterceptor, EnvelopeInterceptor]
  ```
  Dio 响应处理为逆序，`EnvelopeInterceptor` 最先执行 `onResponse`；reject 后错误正向流经 `ErrorInterceptor.onError` → `RetryInterceptor.onError` → `AuthInterceptor.onError`，复用现有错误处理管线。

- 从 `lib/core/network/api.dart` 导出。

### 效果

到达调用方的成功响应保证 `code == 0` 且 body 非 null，全项目 20+ 处 `response.data!.data` 不再有崩溃风险。

### 测试

新增 8 个测试覆盖：
- `code == 0` 正常放行
- 非 envelope Map 响应放行
- `code != 0` reject 为 `LucentApiException`（验证 code/message/statusCode/networkErrorCode）
- envelope message 为空时使用 fallback
- `data: null` + `code != 0` 在反序列化前被拦截（关键场景）
- 空响应体 reject 为 `emptyResponse`
- `skipEnvelopeCheck` 选项正常工作

来源：排查用户报告的用药 tab 加载失败问题

### 问题

`GET/POST /api/v1/medicines/risk-check` 和 `GET /api/v1/medicines/safety-tips` 三个端点的 `@ApiResponse` 类型缺少 `{ code, message, data }` 信封包裹。后端 `ApiEnvelopeInterceptor` + `successEnvelope()` 会将返回值包装为信封格式，但 OpenAPI spec 中响应类型定义为原始 DTO（`MedicineRiskCheckRecordsDto`、`MedicineRiskCheckRecordDto`、`[MedicineSafetyTipResponseDto]`），导致生成的 Dart 客户端反序列化失败（`CheckedFromJsonException`），用药 tab 加载报错。

### 修复

- **后端 (Lucent)**：新增 `MedicineRiskCheckRecordsResponseDto`、`MedicineRiskCheckRecordResponseDto`、`MedicineSafetyTipListResponseDto` 信封包裹 DTO，更新控制器 `@ApiResponse` 类型。
- **OpenAPI**：重新导出 `docs/openapi.json`，三个端点的响应类型已指向信封包裹 DTO。
- **Dart 客户端**：重新生成 `generated/lucent_api`，API 方法返回类型改为信封包裹 DTO。
- **前端数据源**：
  - `risk_check_remote.dart`：`response.data!` → `response.data!.data` 解包信封。
  - `safety_tips_remote.dart`：`response.data!` → `response.data!.data` 解包信封。
