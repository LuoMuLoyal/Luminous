## Luminous — 架构审查改进 #6：Riverpod provider 声明风格统一

- **来源**：`plans/2026-07-16-architecture-review.md` 第 6 项
- **目标**：统一 Riverpod provider 声明风格，修正 ADR-0006 完成宣称与事实不符

### 背景

ADR-0006 引入 `riverpod_generator` 后，分三批迁移了 network_providers、authGuarded 接入、
feature datasource/repository provider。但约 20 处手写 `Provider<T>` / `FutureProvider<T>` /
`FutureProvider.family` 仍散落在 presentation 和 data 层，且 `Current_State.md` 的宣称给人
「全部迁移」的印象。同时约 25 处 `NotifierProvider` / `AsyncNotifierProvider`（Notifier 类）
保持手写，缺乏明确的取舍标准。

### 改动内容

**手写 Provider/FutureProvider 全部迁移为 `@riverpod` 注解（~20 处）**：

- `data/repositories/lucent.dart`（4 个 feature：support/settings/notification/legal）：
  `final xxxRepositoryProvider = Provider<XxxRepository>((ref) { ... })` → `@riverpod XxxRepository xxxRepository(Ref ref) { ... }`
- `presentation/providers/` 中的 dashboard 查询（today/record/mine/medicine/report）：
  `final xxxDashboardProvider = FutureProvider<XxxDashboard>((ref) { ... })` →
  `@Riverpod(keepAlive: true) Future<XxxDashboard> xxxDashboard(Ref ref) { ... }`
- `health_context/data/providers/health_context.dart`：`healthContextSnapshotProvider` 迁移
- `medicine/presentation/providers/risk_check.dart`：`medicineRiskCheckProvider` + `redFlagAlertsProvider` 迁移
- `medicine/presentation/providers/reminders.dart`：4 个 FutureProvider 迁移（list/todayLogs/deliveryLog/detail family）
- `medicine/presentation/providers/reminder_notification_coordinator.dart`：`medicineReminderNotificationSyncProvider` 迁移
- `notification/presentation/providers/notification.dart`：`notificationUnreadCountProvider` + `notificationDetailProvider` 迁移
- `legal/presentation/providers/legal.dart`：`legalDocumentsProvider` + `legalDocumentProvider` 迁移
- `support/data/providers/resources.dart`：`supportResourcesProvider` + `appInfoProvider` 迁移
- `today/presentation/providers/suggestion.dart`：`suggestionHistoryProvider` + `suggestionExplanationProvider` 迁移
- `record/data/providers/record_access.dart`：`dailyRecordDetailProvider` 迁移
- `report/presentation/providers/dashboard.dart`：`reportDashboardProvider` 迁移

**Notifier 类保持手写声明（~25 处）**：

`Notifier` / `AsyncNotifier` 类使用手写 `NotifierProvider` / `AsyncNotifierProvider` 声明。
原因：riverpod_generator 从类名推导 provider 名（`MyFormNotifier` → `myFormNotifierProvider`），
但项目约定使用简短名（`myFormProvider`），两者不匹配。在 `state-management.md` 中明确文档化
此取舍标准。

**文档更新**：

- `docs/02-reference/state-management.md`：重写，新增完整的 Provider 声明风格取舍标准
  （`@riverpod` 函数 vs 手写 NotifierProvider）、选型矩阵（8 种场景 × 声明方式 ×
  autoDispose 策略）、ephemeral UI state 边界说明。
