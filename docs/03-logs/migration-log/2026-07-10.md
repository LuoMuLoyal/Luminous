## ADR-0006 实施第二批：Feature 数据 provider 接入 authGuarded

将 ADR-0006 中定义的 `authGuarded` helper 函数接入全部 feature 数据 provider，消除 14 处重复的 auth session 检查模式。

### authGuarded 函数修正

- **关键修复:** 将 `authGuarded` 从 `async` 改为非 `async` 函数。原因：`async` 函数中的 `throw` 会被转换为 rejected Future，导致 Riverpod 的 `FutureProvider` 异步设置 error 状态（而非同步）。非 `async` 版本让 `throw AuthRequiredException()` 在调用方的同步上下文中执行，保持与原有手写代码一致的 error 传播行为。
- `session_gate_test.dart` 的 "signed out dashboard providers use local data only" 测试验证了此修正的必要性。

### 迁移的 Provider 清单（14 处）

| Feature | Provider | 模式 | signedOutFallback |
|---------|----------|------|-------------------|
| mine | `mineDashboardProvider` | A (signedOut → fallback) | `signedOutDashboard` |
| record | `recordDashboardProvider` | A | `signedOutDashboard(date, filterType:)` |
| today | `todayDashboardProvider` | A | `signedOutDashboard` |
| today | `todaySuggestionProvider` (AsyncNotifier) | D (null fallback) | `() async => null` |
| today | `suggestionExplanationProvider` (autoDispose family) | D | `() async => null` |
| medicine | `medicineWorkspaceProvider` | A | `previewWorkspace` |
| medicine | `medicineReminderListProvider` | B (throw) | 无 |
| medicine | `medicineTodayDoseLogsProvider` | B | 无 |
| medicine | `medicineReminderDeliveryLogProvider` | B | 无 |
| medicine | `medicineRiskCheckProvider` | B | 无 |
| health_context | `healthContextSnapshotProvider` | B | 无 |

**模式说明:**

- **D:** `isRestoring` → pending（行为改进：原来直接返回 null）；`isConfirmedSignedOut` → null；authenticated → fetch

### 行为改进

- `todaySuggestionProvider` 和 `suggestionExplanationProvider` 在 session restoring 期间现在返回 pending（loading）而非 null。这是更正确的行为——session 恢复期间不应显示"无建议"，而应显示加载状态。

### 未迁移的 Provider（不适用 authGuarded 模式）

以下 provider 的 auth 检查模式不适合 `authGuarded`，保持原样：

- `TodayAiAnalysisController` / `ReportAiSummaryController` — Notifier（非 FutureProvider），auth 检查返回 idle 状态而非 Future/throw
- `SettingsProfileSyncNotifier._syncPreferencesToBackend` — Notifier 方法，auth 检查为 no-op return
- UI 页面中的 `ref.watch(authSessionProvider)` — 用于条件渲染，非数据获取

## ADR-0007 实施：网络层职责分离

ADR-0007 状态从 `proposed` 转为 `accepted`，完成全量实施。将 `LucentDioClient` God Class 拆分为三个独立拦截器，新增 `lucentClientProvider` 统一 API 访问入口。

### 新增拦截器文件

- **`lib/core/network/interceptors/auth_interceptor.dart`** — Token 注入（onRequest）+ 401 检测/刷新/重试（onError）+ Session 清理 + `onSessionExpired` 回调。从 `LucentDioClient._buildInterceptors()` + `_shouldRefresh()` + `_refreshTokens()` + `_doRefresh()` + `_retry()` 提取。持有主 Dio 实例用于重试，refreshDio 用于刷新调用。
- **`lib/core/network/interceptors/error_interceptor.dart`** — `DioException` → `LucentApiException` 映射。从 `LucentDioClient._mapToApiException()` + `_fallbackMessage()` 提取。放在拦截器链最后，确保 auth-refresh 和 retry 已有机会恢复请求后再映射错误。
- **`lib/core/network/interceptors/retry_interceptor.dart`** — 5xx / 超时自动重试（指数退避）。默认仅重试 GET 请求，支持 `extra['retryEnabled']` opt-in/opt-out。可重试状态码：408, 429, 500, 502, 503, 504。

### `dio_client.dart` 精简

- 从 ~367 行降至 ~100 行，仅保留 Dio 实例配置 + interceptor 注册 + `dio`/`client` getter + `onSessionExpired` setter（委托到 `AuthInterceptor`）+ `dispose()`。
- 移除 18 个 API getter（`healthApi` / `authApi` / `medicinesApi` 等）、session 代理方法（`writeSession` / `readAccessToken` / `readRefreshToken` / `clearSession`）、`medicinesHeaders` / `medicinesBypassCacheHeader`。

### `network_providers.dart` 更新

- 新增 `lucentClientProvider`（`@Riverpod(keepAlive: true)`）— 返回 `LucentClient`，作为全部 feature 代码的统一 API 访问入口。

4. **`runAuthAction` 保持向后兼容**：标记 `@Deprecated` 但不删除，内部委托到 `runGuarded`，现有 auth form providers 无需修改。

### 关键设计决策

1. **Mixin 命名规则**: go_router_builder 4.x 生成的 mixin 名为 `$ClassName`（如 `$RecordDetailRoute`），非文档中提到的 `_$RouteName`。通过 build_runner 首次运行发现的错误信息确认。
2. **`go_router_builder` import 可省略**: `@TypedGoRoute` 注解由 `go_router` 包 re-export，routes.dart 中无需显式 import `go_router_builder`。
3. **camelCase → kebab-case 自动转换**: go_router_builder 4.x 将 camelCase 字段名自动转换为 kebab-case query parameter（如 `returnTo` → `return-to`）。所有 test 文件中的 `queryParameters['returnTo']` 同步更新为 `queryParameters['return-to']`。
4. **`@TypedQueryParameter` 不可用于字段**: 该注解仅适用于方法参数，不适用于类字段。对于 `state` 字段与 `GoRouterState state` 参数的 shadowing 冲突，通过在 `buildPage` 中将参数重命名为 `goState` 解决。
5. **枚举 query param 自动映射**: `DailyRecordKind` 枚举由 go_router_builder 自动生成 `_$DailyRecordKindEnumMap`，使用 `.name` 序列化，与现有 `dailyRecordKindFromName()` 兼容。
6. **`buildPage` 保留自定义动画**: 覆写 `buildPage` 返回 `slidePage` / `fadePage`，而非使用默认 `build` 返回 `Widget`（会丢失自定义过渡动画）。
7. **嵌套路由通过 `routes` 参数声明**: `@TypedGoRoute<ParentRoute>(path: '/parent', routes: [TypedGoRoute<ChildRoute>(path: 'child')])` — 子路由类不加 `@TypedGoRoute` 注解，但需要 `with $ChildRoute` mixin。

- Wheel 0 — 时段（上午=0 / 下午=1）

- Wheel 2 — 分钟（0-59）

- `_confirmTimePicker` / `_enterTimeAndConfirm` — 接受 `hour` / `minute` int 参数，计算 12 小时制对应的 period/hour/minute index 后调用上述方法

调用方也相应更新：`_confirmTimePicker(tester)` → `_confirmTimePicker(tester, hour: 23, minute: 0)`，`_enterTimeAndConfirm(tester, hour: '7', minute: '0')` → `_enterTimeAndConfirm(tester, hour: 7, minute: 0)`。
