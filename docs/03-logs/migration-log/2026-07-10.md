## 前端审查修复

基于 Lucent `plans/` 中三份审查文档（增量审查、全仓库审查、回查纠正）识别的 Luminous 问题，进行以下修复：

### P1: 次级建议错误状态静默修复

- **文件:** `lib/features/today/presentation/widgets/sections/suggestion_section.dart`
- **问题:** `TodaySecondarySuggestionsSection` 的 `error` 状态返回 `SizedBox.shrink()`，用户无法感知次级建议加载失败。
- **修复:** 新增 `_SecondarySuggestionErrorState` widget，在 error 状态显示错误图标 + 提示文案 + 重试按钮，点击重试时 `ref.invalidate(todaySuggestionProvider)`。

### P1: 图标映射硬编码提取

- **文件:** 新增 `lib/features/today/presentation/widgets/shared/suggestion_icon_mapping.dart`
- **问题:** `_iconFor()` 在 `suggestion_section.dart` 底部硬编码 11 个图标字符串映射，新增后端图标类型需同步修改前端。
- **修复:** 提取为独立 `SuggestionIconMapping` 类，使用 `Map<String, IconData>` 存储映射，提供 `resolve(String icon)` 方法，未知图标回退到 `FLucideIcons.sparkles`。`suggestion_section.dart` 中所有 `_iconFor()` 调用替换为 `SuggestionIconMapping.resolve()`。

### P2: 反馈提交后状态更新

- **文件:** `lib/features/today/presentation/widgets/sections/suggestion_section.dart`
- **问题:** 反馈提交成功后仅显示 Toast，未更新本地 UI 状态，用户可能在 provider re-fetch 期间重复操作。
- **修复:** `_SuggestionFeedbackRowState` 新增 `_submittedFeedback` 字段，提交成功后设置该字段，UI 切换为只读的「已反馈」指示器（check 图标 + 文案），替代交互式按钮组。

### 🔴: AI 解释重试次数限制

- **文件:** `lib/features/today/presentation/widgets/sections/suggestion_section.dart`
- **问题:** `_SuggestionAiExplainButton` 解释请求失败后显示重试按钮，但未限制重试次数，用户连续点击可能导致 LLM API 被频繁调用。
- **修复:** 新增 `_retryCount` 和 `_maxRetries = 3` 常量，每次重试递增计数。达到上限后显示 `_AiExplainUnavailable` widget（info 图标 + 「AI 解释暂时不可用，请稍后再试」文案），不再提供重试按钮。同时在 `aiGenerated == false` 的 data 分支也应用相同的重试上限逻辑。

### 🟡: Dashboard 超时可配置化

- **文件:** `lib/features/today/presentation/providers/dashboard_provider.dart`
- **问题:** `_todayDashboardTimeout` 硬编码为 `Duration(seconds: 5)`，弱网环境下可能频繁触发超时。
- **修复:** 改为 `int.fromEnvironment('DASHBOARD_TIMEOUT_SECONDS', defaultValue: 5)`，支持通过 `--dart-define=DASHBOARD_TIMEOUT_SECONDS=10` 编译时覆盖。

### ⚠️ 误判纠正: 反馈提交防抖

## ADR-0006 实施第一步：riverpod_generator 引入与 network_providers 迁移

ADR-0006 状态从 `proposed` 转为 `accepted`，开始分批实施。

### 依赖新增

- `riverpod_annotation: ^4.0.3` → `dependencies`（`lib/` 源码 import 注解）
- `riverpod_generator: ^4.0.4` → `dev_dependencies`（build_runner codegen）
- 项目已有 `build_runner`，`bootstrap_generated_sources.dart` 无需修改（已包含 `dart run build_runner build`）

### authGuarded helper 函数

- **新增文件:** `lib/core/providers/auth_guarded.dart`
- **作用:** 封装 auth session 检查 + `pendingAuthSessionResolution` + `AuthRequiredException` 模式，消除 `mineDashboardProvider`、`reportDashboardProvider`、`healthContextSnapshotProvider`、`todayDashboardProvider` 等 5+ 处重复 auth guard 逻辑
- **设计决策:** 实现为普通函数（非 generated provider），因为泛型 `authGuarded<T>` 作为 generated family provider 不适用于不同 feature 各自传入不同 `fetch` 函数的场景。各 feature 的 `@riverpod` 函数在函数体内调用 `authGuarded(ref: ref, fetch: ..., signedOutFallback: ...)`

### network_providers.dart 迁移

- **文件:** `lib/core/network/network_providers.dart`
- **变更:** 20 个手写 `final xxxProvider = Provider<Xxx>((ref) { ... });` 全部改为 `@riverpod` / `@Riverpod(keepAlive: true)` 注解形式
  - 3 个核心基础设施 provider（`lucentBaseUrl`、`lucentSessionStore`、`lucentDioClient`）使用 `@Riverpod(keepAlive: true)`
  - 17 个 API accessor provider（`lucentAuthApi`、`lucentHealthApi` 等）使用 `@riverpod`（autoDispose，因为它们是轻量 getter，底层 `LucentClient` 由 keepAlive 的 `lucentDioClientProvider` 持有）
- **import 优化:** 移除 `flutter_riverpod` import（`riverpod_annotation` 已导出 `Ref`/`Override`）；将 `api.dart` barrel import 拆分为具体文件 import（`dio_client.dart`、`session_store.dart`、`base_url.dart`），消除循环依赖
- **provider 名称兼容:** 函数名保留 `lucent` 前缀（如 `lucentAuthApi`），生成的 provider 名为 `lucentAuthApiProvider`，与现有代码引用完全兼容，零破坏性变更
- **新增产物:** `lib/core/network/network_providers.g.dart`（gitignored，由 `build_runner` 生成）
