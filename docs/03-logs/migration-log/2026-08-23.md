## 收口网络失败边界

错误迁移 Task 1：固定网络层错误分类、重试与 token refresh 的唯一语义（LucentErrorMapper → RetryPolicy → AuthInterceptor），全部收敛到 `LucentFailure`。

- **error_mapper 契约**：确认并锁定 HTTP 错误必须先校验 `application/problem+json` 再解析；缺少 body、错误媒体类型、字段类型不符（如 `code` 非字符串、`retryAfter` 为负/小数）保持 `FormatException`（协议不变量，不转业务 LucentFailure）；连接/超时/证书类无 response 错误映射为 `LucentFailure.network`。`target_error_contract_test.dart` 补充对应契约测试。
- **refresh 触发条件**：`AuthInterceptor._shouldRefresh` 从「401 且不在黑名单」改为白名单语义——仅当 Problem Details `code == 'AUTH_TOKEN_EXPIRED'`（`LucentFailure.isTokenExpired`）才触发 refresh；`AUTH_REQUIRED`、`AUTH_REFRESH_TOKEN_INVALID`、`AUTH_WRONG_PASSWORD`、普通 401/403 一律不刷新（401 清 session 并通知，403 保留 session）。保留 `skipAuthRefresh`/`hasRetriedAfterRefresh` 短路、`_refreshFuture` 并发去重，以及 refresh 明确认证失败（401/403）清 session 并把原始请求错误传回调用方、临时失败（网络/5xx/空 body）保留 session 的既有行为。
- **重试边界**：确认 `RetryPolicy` 写请求必须显式 `retryEnabled == true` 且带非空 `Idempotency-Key`；`retryable=false` 禁止重试；`retryable=true` 不扩大客户端允许的状态集合。`Retry-After` 只接受非负整数秒，负数/小数/HTTP-date 回退指数退避（`retry_policy_test.dart` 补充用例）。运行时链上 `RetryInterceptor` 注册于 `ErrorInterceptor` 之前，`onError` 决策时先经 `LucentErrorMapper` 映射失败（畸形 body 捕获 `FormatException` 视为无 hint）再交给 `RetryPolicy` 判断，使 `retryable=false` 与 `retryAfter` 在生产链上真正生效；最终错误仍由 `ErrorInterceptor` 映射，职责划分不变（`retry_interceptor_test.dart` 补充拦截器链测试验证）。
- **遗留类型**：`LucentApiException` 仅加遗留类型文档注释（不新增构造点、不加 `toAppError` 调用）。

## 迁移认证 repository 到 TaskEither

错误迁移 Task 2：Auth/session repository 与 provider 迁移到 fpdart `TaskEither<LucentFailure, T>`。

- **repository 边界**：`AuthRepository` 全部方法与 `AuthSessionsRepository.listSessions/revokeSession` 签名改为 `TaskEither<LucentFailure, T>`；`LucentAuthRepository`、`LucentAuthSessionsRepository` 实现用 `TaskEither.tryCatch(() => datasource 调用 + DTO 映射 + session 持久化, (error, stackTrace) => LucentErrorMapper.fromObject(error))` 包裹，datasource 仍只负责 Future 传输并抛出 DioException。空响应体 `_requireBody` 按 today `ai_remote.dart` 先例改为抛 `LucentFailure.network(networkErrorCode: NetworkErrorCode.emptyResponse)`（保留 operation 上下文）；sessions 列表结构不符的 `StateError` 属协议不变量，保持抛出并经 mapper 转 `Left(unknown)`，非 problem+json 畸形 HTTP body 仍由 mapper 抛 `FormatException` 从 `.run()` 直接传播。
- **注销语义**：移除 `logout()` 的 `finally` 无条件 `_sessionStore.clear()`——远程注销成功（或无 refresh token 可注销）才在 Right 路径清本地 session；远程注销失败返回 Left 且不清本地 session、不写 token holder。`changePassword`/`deleteAccount` 成功清 session 的既有行为保留在 Right 路径内。登录成功后的 `_persistSession` 位于 Right 路径（持久化失败则整操作 Left）。
- **refresh 语义**：`refreshSession` 的 Left 保留服务端 Problem Details 的 code/status，`AUTH_REFRESH_TOKEN_INVALID` 时 `LucentFailure.isRefreshTokenInvalid == true`，不会被转成普通网络错误；网络类失败仍映射为 `LucentFailure.network`。
- **provider 消费**：`session_provider.restore()` 用 `run()` + Left 分类重写（快速恢复 fetchAccount → 认证类失败回落 refresh、网络连接错误保留 session store、其余清 store），`logout()` 改为 Right 清 UI 状态、Left 投影 errorMessage 且不误登出；`forms/{login,register,password_reset}.dart` 用 `run()` + switch 投影到既有 form state，不再引用 `Result`/`runGuarded`/`AppError`；`oauth_login.dart`、`account.dart`、`presentation/providers/sessions.dart`、`wechat_oauth.dart` 消费 `TaskEither.run()`（`_resolve` 适配器把 Left 重抛进既有 action-state 处理路径，等价投影）。widget 层（pages/widgets）不导入 fpdart、不读 DioException、不解析 code/status。
- **elevation 语义**：检查 `security_elevation.dart`、`security_elevation_token_holder.dart`、`security_elevation_interceptor.dart` 后确认无需改动——`verify()` 失败不写 token holder、401/403/网络失败与意外异常均返回 false 保持 Unverified；账户操作里的 403 elevation 失败由 `_isSecurityElevationFailure` 标记 `requiresSecurityElevation` 并清空本地 token，不吞成"普通未登录"；既有 `security_elevation_test.dart` 与 `account_provider_test.dart` 已锁定该语义。elevation token holder 与 session_store 未改动。
