## 收口网络失败边界

错误迁移 Task 1：固定网络层错误分类、重试与 token refresh 的唯一语义（LucentErrorMapper → RetryPolicy → AuthInterceptor），全部收敛到 `LucentFailure`。

- **error_mapper 契约**：确认并锁定 HTTP 错误必须先校验 `application/problem+json` 再解析；缺少 body、错误媒体类型、字段类型不符（如 `code` 非字符串、`retryAfter` 为负/小数）保持 `FormatException`（协议不变量，不转业务 LucentFailure）；连接/超时/证书类无 response 错误映射为 `LucentFailure.network`。`target_error_contract_test.dart` 补充对应契约测试。
- **refresh 触发条件**：`AuthInterceptor._shouldRefresh` 从「401 且不在黑名单」改为白名单语义——仅当 Problem Details `code == 'AUTH_TOKEN_EXPIRED'`（`LucentFailure.isTokenExpired`）才触发 refresh；`AUTH_REQUIRED`、`AUTH_REFRESH_TOKEN_INVALID`、`AUTH_WRONG_PASSWORD`、普通 401/403 一律不刷新（401 清 session 并通知，403 保留 session）。保留 `skipAuthRefresh`/`hasRetriedAfterRefresh` 短路、`_refreshFuture` 并发去重，以及 refresh 明确认证失败（401/403）清 session 并把原始请求错误传回调用方、临时失败（网络/5xx/空 body）保留 session 的既有行为。
- **重试边界**：确认 `RetryPolicy` 写请求必须显式 `retryEnabled == true` 且带非空 `Idempotency-Key`；`retryable=false` 禁止重试；`retryable=true` 不扩大客户端允许的状态集合。`Retry-After` 只接受非负整数秒，负数/小数/HTTP-date 回退指数退避（`retry_policy_test.dart` 补充用例）。运行时链上 `RetryInterceptor` 注册于 `ErrorInterceptor` 之前，`onError` 决策时先经 `LucentErrorMapper` 映射失败（畸形 body 捕获 `FormatException` 视为无 hint）再交给 `RetryPolicy` 判断，使 `retryable=false` 与 `retryAfter` 在生产链上真正生效；最终错误仍由 `ErrorInterceptor` 映射，职责划分不变（`retry_interceptor_test.dart` 补充拦截器链测试验证）。
- **遗留类型**：`LucentApiException` 仅加遗留类型文档注释（不新增构造点、不加 `toAppError` 调用）。
