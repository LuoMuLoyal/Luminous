# Migration Log — 2026-07-22

## 审查报告问题修复

### main.dart — Zone mismatch 修复

- 之前的改动将 `WidgetsFlutterBinding.ensureInitialized()` 移到 `runZonedGuarded` 外部，
  导致 Flutter 抛出 "Zone mismatch" 异常：binding 初始化的 zone 与 `runApp` 的 zone 不一致。
- 弃用 `runZonedGuarded`，改用 `PlatformDispatcher.instance.onError` 捕获异步未捕获错误。
  这是 Flutter 3.x+ 推荐的现代模式，同时满足：
  - `ensureInitialized` 在 root zone（同步异常正常崩溃，不被静默吞咽）
  - `runApp` 也在 root zone（无 zone mismatch）
  - 异步未捕获错误仍通过 `PlatformDispatcher.instance.onError` 上报到 Sentry
- 移除了 `dart:async` import（`runZonedGuarded` 不再使用）。

### luminous-cd.yml — CI/CD secrets 校验步骤

- 新增 "Validate required secrets" 步骤，在 Flutter 构建前检查 `LUCENT_BASE_URL` 和 `SENTRY_DSN` 两个 GitHub secrets 是否已配置，未配置时 `exit(1` 中断流水线，防止空字符串注入 `--dart-define`。

### dialog_test.dart — 测试 group 名称同步

- `group('AppDialogShell', ...)` 更新为 `group('DialogShell', ...)`，与类名一致。

### Android 模拟器网络连接修复

- **问题**：在 Android 模拟器上点击发送验证码时报 `DioException [connection error]`，后端已正常运行。
- **根因 1**：`127.0.0.1` 在 Android 模拟器上指向模拟器自身的 loopback，而非宿主机。需要使用 `10.0.2.2` 才能访问宿主机的 localhost。
- **根因 2**：Android 9+（API 28+）默认禁止明文 HTTP 流量，而 `debug/AndroidManifest.xml` 未声明 `android:usesCleartextTraffic="true"`。
- **修复 1**：`android/app/src/debug/AndroidManifest.xml` 新增 `<application android:usesCleartextTraffic="true"/>`，允许 debug 构建下的明文 HTTP（release 不受影响，使用 HTTPS）。
- **修复 2**：`lib/core/network/base_url.dart` 的 debug 回退 URL 改为平台感知——Android 返回 `http://10.0.2.2:3000`，其他平台保持 `http://127.0.0.1:3000`。
- **修复 3**：`lib/core/config/developer_settings_controller.dart` 的 `resolvedBaseUrl` getter 对 `ApiEndpoint.local` 做平台适配——Android 返回 `10.0.2.2`，其他平台返回 `127.0.0.1`。

### Record 页面分页参数验证失败修复

- **问题**：登录后跳转 record 页面时，后端返回 400 验证错误：`page must be an integer number; pageSize must be an integer number` 等全部分页验证失败。
- **根因**：后端 `QueryDailyRecordDto` 的 `page`/`pageSize` 缺少 `@Type(() => Number)` 装饰器，`class-transformer` 未将查询字符串转换为 `Number` 类型，导致 `@IsInt()` / `@Min()` / `@Max()` 验证全部失败。
- **修复**：后端 DTO 添加 `@Type(() => Number)` 装饰器（`Lucent/src/modules/daily-records/dto/query-record.dto.ts`），重新导出 OpenAPI 并重新生成 Dart 客户端。

### 健康档案可空枚举反序列化失败修复

- **问题**：登录后获取健康档案时，`UserHealthProfileDto.sexAtBirth` 反序列化报 `CheckedFromJsonException`，程序卡在 Mine 页面。
- **根因**：`openapi_retrofit_generator` 对 `nullable: true` + `allOf` + `$ref` 模式的枚举字段生成非空类型。后端返回 `null` 时 `v as String` 崩溃。
- **修复**：后端 `response.dto.ts` 和 `update-profile.dto.ts` 中枚举字段的 `@ApiPropertyOptional` 移除 `nullable: true`（该标志反而导致生成器生成非空类型）。重新运行 `openapi_retrofit_generator` + `build_runner` 重新生成客户端。`lib/features/health_context/data/mappers/mapper.dart` 三处 `.name` 改为 `?.name`。
