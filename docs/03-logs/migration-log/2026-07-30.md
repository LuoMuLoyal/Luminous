## Scan 模块 — 07-30 审查问题修复

### 修复 1：PaddleOcrEngine 初始化失败后状态不一致

- **文件**: `lib/features/scan/domain/services/paddle_ocr_provider.dart`
- **变更**: 提取 `ensureInitialized()` 公共方法，init 失败时 `_initialized` 重置为 `false` 并 rethrow，允许下次调用重试。`recognize()` 改为调用 `ensureInitialized()` 而非内联 init。
- **原因**: ONNX 模型加载失败（存储空间不足、模型文件损坏、so 库加载失败）时，`_initialized` 保持 `true` 导致引擎卡在不一致状态，当前应用生命周期内 OCR 功能永久不可用，必须杀进程重启。

### 修复 2：OCR 入口 ABI 预检

- **文件**: `lib/features/scan/presentation/pages/box_scan.dart`
- **变更**: 用户选择 OCR 方式后、打开相机前，调用 `ensureInitialized()` 预检。init 失败时显示 `_showOcrUnavailableDialog` 对话框，提供关闭和"使用 AI 识别"两个操作。
- **原因**: Android `abiFilters` 仅打包 `arm64-v8a`，非 arm64 设备（模拟器、32 位 ARM）安装后运行正常但进入 OCR 扫描时 native 库加载失败。原流程让用户拍照后才发现不可用，体验差。
- **新增 l10n 键**: `scanOcrUnavailableTitle` / `scanOcrUnavailableMessage` / `scanOcrUnavailableUseAi`（`medicine_zh.arb` / `medicine_en.arb`）

### 修复 3：批准号正则精确化

- **文件**: `lib/features/scan/domain/services/medicine_ocr_extractor.dart`
- **变更**: `_approvalNumberPattern` 中 `\w{7,9}` 改为 `[A-Za-z0-9]{7,9}`，排除下划线。
- **原因**: `\w` 匹配 `[a-zA-Z0-9_]`，国药准字批准号格式为字母+数字，不应包含下划线。虽然实际 OCR 结果中极难出现下划线，但正则语义不精确。

- **文件**: `android/app/build.gradle.kts`
- **变更**:
  1. 将 `packaging { jniLibs { ... } }` 块从 `android { ... }` 外部移入内部（原错误放置在 `android` 块关闭之后，导致 Gradle 脚本编译报 20 个 "Unexpected symbol" / "Unresolved reference" 错误）。

- **原因**: `packaging` 块结构错误导致 Android 构建完全失败；`paddle_ocr_native` 要求 minSdk 26 而 Flutter 默认为 24。

## Android 构建修复 — abiFilters 统一支持手机 + 模拟器架构

- **文件**: `android/app/build.gradle.kts`
- **问题**: 原 `abiFilters` 仅 `arm64-v8a`，且 `packaging.jniLibs.excludes` 显式排除 `lib/x86_64/**`，导致 x86_64 模拟器安装后启动即崩溃（无 native 库）；同时 release 也需要支持国内外常见手机架构。
- **变更**:
  1. `defaultConfig.ndk.abiFilters` 设为 `listOf("arm64-v8a", "x86_64")`，debug 和 release 统一生效。
  2. 删除 `packaging { jniLibs { excludes += ... } }` 块（excludes 会覆盖 abiFilters，阻止 x86_64 库打包）。
  3. 删除 `buildTypes.debug` 特殊处理（不再需要按 build type 区分架构）。
- **原因**: `arm64-v8a` 覆盖所有现代 64 位 ARM 手机（国内外主流）；`x86_64` 覆盖 Android 模拟器开发调试。底层依赖（ONNX Runtime 1.21、OpenCV 4.13）均提供全部四种架构的 .so，app 层 abiFilters 是最终过滤关口。
- **验证**: `flutter build apk --debug` + `flutter build apk --release` 均成功；release APK `aapt dump badging` 确认包含 `arm64-v8a`、`armeabi-v7a`、`x86_64` 三种架构。
