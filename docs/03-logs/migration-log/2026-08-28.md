## perf(apk): APK 体积优化 — PaddleOCR 模型按需下载 + split-per-abi + 代码混淆

### 变更范围

- **PaddleOCR 模型从 APK 中移除（~30MB 节省）**：将 `paddle_ocr_native` 从 pub.dev 依赖改为本地 `pkgs/paddle_ocr_native-0.1.1` 路径依赖，移除其 `pubspec.yaml` 中的 ONNX 模型 assets 声明（`det/inference.onnx` 9.4MB + `rec/inference.onnx` 20.2MB）。
- **Android 原生层改造**：`PaddleOcrNativePlugin.kt` 改为从 Dart 侧接收 `modelPaths`（文件系统绝对路径），调用新增的 `PaddleOCR.createFromFile()` 方法。`ORTSessionManager` 新增 `loadModelsFromFiles()` 方法从文件系统读取 .onnx 文件。`ModelConfig` 新增 `parseFromFile()` 方法从文件系统读取 yml 配置。`OCREngine` 改为 sealed `ModelSource` 模式，统一支持 asset 和 file 两种模型来源。
- **Dart 层改造**：`PaddleOcr.init()` 新增 `required ModelPaths modelPaths` 参数。`ModelPaths` 类包含 `detModelPath` / `recModelPath` / `recConfigPath` 三个文件路径字段。平台接口和 MethodChannel 实现同步传递 `modelPaths`。
- **模型下载管理器**：新增 `lib/features/scan/domain/services/ocr_model_manager.dart`，负责检测模型是否已下载、从 GitHub releases 下载模型文件（含进度回调）、从 plugin assets 复制 yml 配置文件、管理本地存储路径。使用 `getApplicationSupportDirectory()` 存储，路径为 `<app_support>/paddle_ocr_models/`。
- **OCR 引擎 provider 改造**：`paddleOcrProvider` 从 `Provider<PaddleOcrEngine>` 改为 `FutureProvider<PaddleOcrEngine>`，依赖 `ocrModelManagerProvider`。`PaddleOcrEngine` 构造函数改为接受 `OcrModelManager`，`ensureInitialized()` 先检查模型是否已下载，如未下载抛出 `OcrModelsNotDownloadedException`。
- **box_scan.dart 弹窗流程**：OCR 方法被选择时，先检查模型是否已下载；未下载时弹窗提示用户确认下载（标注 ~30MB 体积）；用户确认后显示处理 overlay 并下载模型；下载失败弹窗提供重试。新增 `_showModelDownloadDialog` 和 `_showModelDownloadFailedDialog` 两个弹窗。
- **l10n 新增 7 个字符串**（中英文）：`scanModelDownloadTitle`、`scanModelDownloadMessage`、`scanModelDownloadConfirm`、`scanModelDownloadCancel`、`scanModelDownloadFailedTitle`、`scanModelDownloadFailedMessage`、`scanModelDownloadRetry`。
- **CI 构建命令优化**：`luminous-ci.yml` 的 release 构建从 `flutter build apk --release` 改为 `flutter build apk --release --obfuscate --split-debug-info=build/symbols`。代码混淆减小 Dart AOT 编译产物体积，调试符号分离到 `build/symbols` 目录。`--split-per-abi` 因与 `abiFilters` 冲突未使用，改用 `abiFilters` 直接限制 release 只构建 `arm64-v8a`。
- **Android release ABI 收窄**：`build.gradle.kts` 的 `abiFilters` 从 `["arm64-v8a", "x86_64"]` 改为 `["arm64-v8a"]`，release 包不再包含模拟器用的 x86_64 原生库，所有原生 .so 文件（ONNX Runtime、OpenCV、JPush、ML Kit 等）只保留 arm64-v8a 一份。

### 验证结论

- `flutter analyze lib/features/scan/` 无告警。
- 优化后 release APK 体积: **81.9MB**（从 ~225MB 降至 81.9MB，减少 ~143MB / 63.7%）。
- APK 内部构成（arm64-v8a only）:
  - `lib/arm64-v8a/`: 75.75MB（OpenCV 22.86MB + ONNX Runtime 17.08MB + libapp.so 14.56MB + libflutter.so 11.20MB + ML Kit barcode 4.72MB + sqlite3 1.65MB + 其余 ~8.7MB）
  - `classes.dex`: 6.26MB
  - `assets/`: 4.05MB（字体 + ML Kit tflite 模型 + paddle_ocr yml）
  - 其余: ~1.7MB
- 优化项贡献:
  - PaddleOCR ONNX 模型移除: ~30MB（det 9.4MB + rec 20.2MB）
  - x86_64 + armeabi-v7a 原生库移除: ~120MB（Flutter Gradle 插件忽略 abiFilters，通过 packagingOptions.jniLibs.excludes 排除）
  - 代码混淆: Dart AOT 产物 libapp.so 从 ~17MB 降至 ~14.6MB
- **关键发现**: Flutter Gradle 插件会覆盖 `abiFilters` 设置，将所有 ABI（arm64-v8a, armeabi-v7a, x86_64）的 .so 都打包进 APK。`abiFilters` 在 `defaultConfig.ndk` 中设置无效，必须用 `packagingOptions.jniLibs.excludes` 显式排除非目标 ABI 的 .so 文件。

## fix(ui): _LoadingTimeoutWrapper 在无界高度容器中的布局崩溃

- 根因：`_LoadingTimeoutWrapper` 在 6 秒后显示 "loading slow" hint banner 时，用 `Column(mainAxisSize: MainAxisSize.min, children: [banner, widget.child])` 包裹子 widget。当子 widget 内部使用了 `Expanded`（如 `_MedicineMobileShell` 的 `Column > Expanded > ListView`），`mainAxisSize.min` 的 `Column` 不提供有限高度，`Expanded` 导致 `RenderFlex` 布局异常。
- 影响范围：`medicine/page_test`、`today/page_test`、`mine/page_test`、`record/page_test` 的 error state 测试（`pumpAndSettle` 推进时间超过 6 秒触发 hint banner 后崩溃）。
- 修复：`lib/core/widgets/common/page_state.dart` 的 `_LoadingTimeoutWrapper.build` 用 `LayoutBuilder` 检测父级是否提供有限高度——有限高度时用 `Column(mainAxisSize: max, children: [banner, Expanded(child: widget.child)])`；无界高度时回退到 `Column(mainAxisSize: min, children: [banner, widget.child])`，不强制 `Expanded`。
