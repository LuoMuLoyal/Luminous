## 审查报告修复（luminous-review-2026-07-11）

基于 `plans/luminous-review-2026-07-11.md` 回查报告中未修复的 🟡/🔴 问题，进行以下修复：

### 🟡: mine 页面统一使用 SignInHintBanner

- **文件:** `lib/features/mine/presentation/pages/page.dart`
- **问题:** `MinePage` 在 `isPreview`（未登录预览）场景下未显示 `SignInHintBanner`，与其他四个 Tab 页面（Today/Record/Medicine/Report）UX 不一致。7-8、7-9、7-11 连续三次审查未修复。
- **修复:** `readyBuilder` 中检测 `isPreview`，在 `MineDashboardView` 上方插入 `SignInHintBanner`，`onSignIn` 回调导航到 `loginRouteForCurrentLocation(context)`。新增 `required_dialog.dart` 导入。

### 🟡: `_stateColor` 为不同状态添加颜色区分

- **文件:** `lib/features/medicine/data/repositories/lucent_workspace_repository.dart`
- **问题:** `_stateColor` 对 `taken`/`skipped`/`pending` 三种状态全部返回 `SemanticColor.primary`，用户无法一眼识别待服用药物。
- **修复:** `taken` → `SemanticColor.success`（绿色，已完成）；`skipped` → `SemanticColor.neutral`（中性色，已跳过）；`pending` → `SemanticColor.warning`（警告色，待服用）。

### 🔴: 移除 `updatedAt` 前端不必要的 fallback

- **文件:** `lib/features/medicine/data/datasources/dose_log_remote_data_source.dart`
- **问题:** 后端 `DoseLogItemDto` 已新增 `updatedAt` 字段并正确返回，但前端 `_fromJson` 仍保留 `json['updatedAt'] as String? ?? json['createdAt'] as String` fallback，属于不必要的兼容代码。
- **修复:** 移除 fallback，直接使用 `json['updatedAt'] as String`。

### 🟡: SearchBar 固定高度改为 ConstrainedBox + minHeight

- **文件:** `lib/features/medicine/presentation/pages/page.dart`
- **问题:** `_MedicineMobileSearchBar` 使用 `SizedBox(height: 56)` 固定高度，在系统字体放大场景下可能截断文字。
- **修复:** 改为 `ConstrainedBox(constraints: BoxConstraints(minHeight: 56))`，允许内容超出时自动扩展高度。

### 🔴: 移除 `_slotStatusForReminder` 单提醒 fallback

- **文件:** `lib/features/medicine/data/repositories/lucent_workspace_repository.dart`
- **问题:** 当药品只有 1 个提醒且 dose log 精确匹配（`reminderId|timeLabel`）失败时，回退到药品级别的 `fallbackStatus`（`medicineId → status`）。用户新增提醒后 `reminderCount` 从 1 变为 2，fallback 不再触发，已服药的旧 slot 会错误回退为 `pending`，造成状态误判。
- **修复:** 移除 `reminderCount == 1 && fallbackStatus != null` 分支，slot 状态完全依赖精确的 `doseStatusBySlot` 匹配，匹配失败则返回 `pending`。同时清理 `_slotStatusForReminder` 中不再需要的 `reminderCount` 和 `fallbackStatus` 参数。`fallbackStatus` 仍保留用于 `slots.isEmpty`（无提醒时）的药品级状态展示。

## Sentry 生产错误上报集成

### 背景

Talker 日志系统此前设置了 `enabled: !kReleaseMode`，release 构建完全禁用日志，
且无任何远程崩溃上报机制。app 崩溃后日志全部丢失，无法事后排查。

### 方案

保留 Talker 作为日志基础设施，新增 Sentry 作为生产环境错误上报通道，
通过 `TalkerObserver` 桥接两者——Talker 的 error/exception 事件自动转发到 Sentry。

### 改动文件

#### 1. `pubspec.yaml`

- 新增 `sentry_flutter: ^9.0.0` 依赖

#### 2. `lib/core/config/env_keys.dart` + `env_reader.dart`

- 新增 `EnvKey.sentryDsn`（`SENTRY_DSN`），通过 `--dart-define-from-file=.env` 注入
- `.env.example` 补充 `SENTRY_DSN=` 占位

#### 3. `lib/core/logger/sentry_talker_observer.dart`（新建）

- `SentryTalkerObserver extends TalkerObserver`
- `onError(TalkerError err)` → `Sentry.captureException(err.error, stackTrace: err.stackTrace)`
- `onException(TalkerException err)` → `Sentry.captureException(err.exception, stackTrace: err.stackTrace)`
- 仅转发 error/exception 级别，info/warning/debug 日志不转发

#### 4. `lib/core/logger/app_logger.dart`

- `_globalTalker` 配置从 `enabled: !kReleaseMode` 改为 `enabled: true`
- 控制台输出仍仅 debug 模式（`useConsoleLogs: kDebugMode`）
- 挂载 `SentryTalkerObserver` 作为 observer

#### 5. `lib/main.dart`

- 新增 `_initSentry()`：从 `EnvReader` 读取 `SENTRY_DSN`，调用 `SentryFlutter.init`
  - DSN 为空时 SDK 处于禁用状态，所有 capture 调用静默丢弃
  - `tracesSampleRate`：release 0.2，debug 1.0
  - `attachStacktrace: true`，`sendDefaultPii: false`
- 用 `runZonedGuarded` 包裹 `runApp`，捕获 Dart 异步未处理异常 → `Sentry.captureException`
- 设置 `FlutterError.onError`：Framework 错误 → `FlutterError.presentError` + `Sentry.captureException`

#### 6. `lib/core/errors/run_guarded.dart`

- catch 块从 `talker.error('$tag: failed: $e')` 改为 `talker.handle(e, st, '$tag: failed')`
- 这样 `SentryTalkerObserver` 能拿到完整的异常对象和堆栈跟踪自动转发 Sentry
- 避免重复上报（不需要显式调 `Sentry.captureException`）

### 架构

```
┌─────────────────────────────────────────────┐
│              AppLogger (Talker)              │
├──────────────────┬──────────────────────────┤
│  Debug 模式       │  Release 模式              │
│  Talker           │  Talker                   │
│  ├─ console       │  ├─ 内存历史               │
│  ├─ 内存历史       │  └─ error → Sentry（通过    │
│  └─ TalkerScreen  │     SentryTalkerObserver） │
│     (可选)        │                           │
│                  │  Sentry                    │
│                  │  ├─ 原生崩溃捕获             │
│                  │  ├─ Dart 未处理异常          │
│                  │  └─ Flutter Framework 错误   │
└──────────────────┴──────────────────────────┘
```

## CI InputDecorator 无界宽度断言修复

### 问题

CI（Linux）运行 `flutter test` 时，`forui` 0.23.0 的 `FTextField` 内部 `InputDecorator` 触发 `constraints.maxWidth < double.infinity` 断言错误。本地 Windows 测试全通过，CI Linux 环境失败。

### 根因

`SoundPreferenceRow`（`lib/features/medicine/presentation/widgets/reminder/reminder_rows.dart`）中 `FSelect<MedicineReminderSoundPreference>` 直接放在 `Row` 内，未使用 `Expanded` 或 `SizedBox` 约束宽度。`FSelect` 内部使用 `FTextField` → `TextField` → `InputDecorator`，后者要求有限宽度约束。`Row` 给非 flex 子组件传递无界宽度，导致断言失败。

本地 Windows 测试通过的原因：`_pumpForm` helper 使用 `tester.pump()` + `tester.takeException()` 抑制了渲染异常，但该机制在 Linux CI 上未能可靠捕获 `performLayout()` 阶段的断言。`SoundPreferenceRow` 的直接单元测试此前已被跳过（注释说明 "FSelect FollowerLayer unbounded width assertion"）。

### 修复

- **`lib/features/medicine/presentation/widgets/reminder/reminder_rows.dart`**：`FSelect` 外层包裹 `SizedBox(width: 140)`，为 `InputDecorator` 提供有限宽度约束。
- **`test/medicine/presentation/widgets/reminder/reminder_rows_test.dart`**：恢复 `SoundPreferenceRow` 测试组（2 个测试：渲染验证 + 选择回调验证），使用 `find.byWidgetPredicate` 查找泛型 `FSelect<T>` 实例。
- **`test/medicine/presentation/widgets/reminder/reminder_form_body_test.dart`**：移除 `_pumpForm` 中的 `tester.takeException()` 异常抑制 hack，改为正常的 `tester.pumpAndSettle()`；保存按钮测试恢复直接调用 `onPress`（按钮在 800×600 测试视口外）。
- **删除 `test/tmp_platform_test.dart`**：调查期间创建的临时平台测试文件。
