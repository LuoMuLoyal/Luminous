## Luminous — 建议性问题审查与修复

- **来源**：用户提供的 5 个建议性问题，经代码核实后修复 2 项、确认已修复 2 项、不修复 1 项。
- **验证方式**：`flutter analyze` 零问题，72 个测试全部通过。

### 问题 1：LegalDocType.fromPathSegment 可优化为 Map（✅ 已修复，无需操作）

- **核实**：`lib/features/legal/domain/entities/doc_type.dart` 已使用 `_byPathSegment` Map 实现 O(1) 查找，`fromPathSegment` 方法直接 `return _byPathSegment[value]`。注释标注 `/// O(1) lookup map`。此建议已落地。

### 问题 2：SuggestionJsonCodec 序列化兼容性（⚠️ 已修复）

- **问题**：`suggestion.dart` 的 `_fetch()` 方法在网络失败时尝试从缓存读取（stale-while-error），但 `bundleFromJson(cached)` 调用无 try-catch。如果缓存格式不兼容（如 app 更新后字段结构变更），反序列化会抛出未处理的 `TypeError`/`CastException`，导致 provider 进入不可恢复的错误状态。
- **修复**：`suggestion.dart` 的缓存反序列化路径包裹 try-catch：反序列化失败时记录 warning 日志（`talkerProvider`），调用 `dao.clear()` 清理过期缓存，然后 rethrow 原始网络错误（保持与"无缓存"场景一致的行为）。
- **测试**：`suggestion_provider_test.dart` 新增 `clears stale cache when deserialization fails and rethrows` 测试，验证网络失败 + 缓存格式不兼容时 `dao.clear()` 被调用。

### 问题 3：DesktopTabShell 构造函数参数多（❌ 不修复）

- **核实**：`DesktopTabShell` 实际有 8 个参数（+ `super.key` = 9），在 Flutter `StatelessWidget` 中完全正常。Builder 模式在 Flutter widget 中反惯用，引入反而增加复杂度。

### 问题 4：isPublicRoute 硬编码只包含 /legal（✅ 已修复）

- **问题**：`router.dart` 的 redirect 守卫中 `isPublicRoute = location.startsWith('/legal')` 硬编码了 `/legal` 前缀。变量名暗示通用性，但未来新增公开路由（如帮助页、关于页）时容易遗漏更新。
- **修复**：提取 `_publicRoutePrefixes` 常量集合（`const <String>['/legal']`），`isPublicRoute` 改为 `_publicRoutePrefixes.any((prefix) => location.startsWith(prefix))`。注释说明添加新公开路由时更新此列表。

### 问题 5：高对比度模式颜色硬编码（✅ 已修复，无需操作）

- **核实**：`bootstrap.dart` 的 `_applyHighContrast` 函数已使用 `HighContrastColors` 常量类（`lib/core/design/high_contrast.dart`），不再有硬编码 `Color(0xFF...)`。`HighContrastColors` 的注释明确说明颜色有意不从主题系列生——高对比度模式是无障碍覆盖，使用跨系列一致的极值。
