## Trace 全链路 — Sentry 分布式追踪（方向 1）

### 接入 sentry_dio + W3C traceparent 传播

- `pubspec.yaml` / `pubspec.lock`：新增直接依赖 `sentry_dio ^9.0.0`。
- `lib/main.dart`
  - `options.propagateTraceparent = true`：Sentry 在出站请求注入 W3C `traceparent`，后端 OTel 承接同一条 trace（Sentry + Jaeger + 帮助页「最近请求 Trace ID」展示同一 traceId）。
  - `tracesSampleRate` 由 `release 0.2 / debug 1.0` 统一为 `1.0`：低于 1.0 时未采样请求会带 `sampled='00'`，Lucent OTel（parent-based sampler）会丢弃其 span。
  - `beforeSend` 不再读全局 `TraceContext.lastTraceId`，改为提升 hint 中 per-error `trace_id` 为 tag，消除「最近一次请求」的误导性关联（请求级错误上下文由 SentryDioInterceptor 自动绑定）。
- `lib/core/network/dio_client.dart`：`_dio` 与 `_refreshDio` 均调用 `addSentry(captureFailedRequests: false)`（HTTP 失败已由 Talker→Sentry observer 与框架错误处理器上报，避免重复事件）。
- `lib/app/router.dart`：接入 `SentryNavigatorObserver`，路由导航开启 Sentry 事务、请求成为其子 span；Sentry 未初始化（测试环境）时为 no-op，不产生事务与计时器。

## Trace 全链路 — 请求级 traceId 绑定（方向 2）

### 每请求 traceId 随异常/日志绑定

- `lib/core/network/interceptors/trace_interceptor.dart`
  - 请求时把该请求的 traceId 写入 `options.extra['traceId']`（已有 `traceparent` 的透传场景取其 traceId）。
  - 响应时用后端确认的 `traceresponse` traceId 回写 `requestOptions.extra['traceId']`。
  - 抽出共享解析函数 `traceIdFromTraceHeader` 供各错误拦截器复用。
- `lib/core/network/api_exception.dart`：`LucentApiException` 新增 `traceId` 字段并纳入 `toString()`，Talker 日志（字符串化异常）自动携带请求级 traceId。
- `lib/core/network/interceptors/error_interceptor.dart` / `lib/core/network/error_mapper.dart`：错误映射时优先取响应头 `traceresponse`，无响应（网络层错误）回退 `requestOptions.extra['traceId']`，绑定进 `LucentApiException.traceId`。
- `lib/core/network/interceptors/envelope_interceptor.dart`：空响应体 / 业务失败两个构造点同样绑定 traceId。
- `lib/core/logger/sentry_talker_observer.dart`：hint 的 `trace_id` 优先取异常内绑定的 `LucentApiException.traceId`，否则回退 `TraceContext.lastTraceId`（配合 main.dart `beforeSend` 提升为 tag）。
- 测试：`trace_interceptor_test.dart` 新增 `extra['traceId']` 注入 / 透传 / 响应回写断言；`error_interceptor_test.dart` 新增 traceId 从 `traceresponse` 绑定、`extra` 兜底、缺省为 null 三个用例。
- 验证：`flutter analyze` 无问题；`flutter test test/core/network test/assistant test/shell`（293 用例）全绿。
