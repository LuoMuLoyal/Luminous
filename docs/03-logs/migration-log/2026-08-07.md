## 🟡 警告修复

### 1. `PushCoordinator` 空 `catchError` 静默吞错

- `lib/core/push/lifecycle.dart`
  - `onAuthChanged` 的 `catchError` 从空实现改为记录 `appTalker.error` 日志，保留链序列化语义的同时不再静默吞掉错误。

### 2. `JpushGateway.init()` 提前置 `_initialized = true`

- `lib/core/push/jpush_gateway.dart`
  - `_initialized = true` 从 `setup()` 调用之前移至之后。若 `setup()` 抛出平台异常，后续 `init()` 调用可正常重试。

### 3. `bootstrap.dart` auth 条件重复检查

- `lib/app/bootstrap.dart`
  - `ref.listen<AuthSessionState>` 回调中，登出条件 `previous?.isAuthenticated == true && !next.isAuthenticated` 从检查两次合并为单一分支。
  - 登出场景现在在一处完成：invalidate health context → sync push alias (null) → return。

### 4. `changeEmail` 重复调用 `_requireBody`

- `lib/features/auth/data/datasources/auth.dart`
  - 提取局部变量 `final body = _requireBody(response.data).data;`，消除同一响应体的二次非空校验。

### 5. `MedicationQuickBatchResult.errors` 字段移除

- `lib/features/record/presentation/quick_entry/medication_flow.dart`
  - 移除 `errors` 字段及其构建逻辑。调用方 (`quick_entry_medication.dart`) 仅消费 `succeeded` / `failed` 列表，`errors` map 从未被 UI 读取。
- `test/record/quick_entry/medication_flow_test.dart`
  - 移除对 `result.errors` 的两处断言。

### 6. ~~`PushMessageHandler` 闭包捕获 router~~（误报，不修改）

- 闭包 `(route) => ref.read(appRouterProvider).go(route)` 在调用时执行 `ref.read`，非构建时捕获。`appRouterProvider` 为 `@Riverpod(keepAlive: true)` 单例，不存在持有旧实例的风险。
