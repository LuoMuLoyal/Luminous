## medicines 搜索 API 响应信封修复（跨项目变更）

### 背景

Lucent 后端 `medicines.controller.ts` 的 `search` 方法返回了非标准信封（`{ code, message, data, meta }`），`meta` 字段放置分页信息。阶段 8 将其统一为标准 `successEnvelope`（`{ code, message, data }`），分页信息移入 `data.pagination`。

### 前端修改

- **重新生成 API 客户端** — `generated/lucent_api` 中 `MedicineSearchResponseDto.data` 类型从 `List<MedicineSearchItemDto>` 变为 `MedicineSearchDataDto`（包含 `items` 和 `pagination`），`meta` 字段移除，新增 `MedicineSearchDataDto` 模型，删除 `MedicineSearchMetaDto`
- **`lib/features/search/data/repositories/lucent.dart`** — `response.data.map(mapper.dtoToResult).toList()` → `response.data.items.map(mapper.dtoToResult).toList()`

### 验证

- `flutter analyze lib/features/search/` — No issues found

## LucentTodayRepository 显式依赖注入重构

### 背景

`LucentTodayRepository` 是项目中唯一持有 `Ref ref` 的 repository——其余所有 repository（`LucentAuthRepository`、`LucentMedicineWorkspaceRepository`、`LucentTodayAiRepository` 等）均已采用构造函数显式注入依赖。此次重构消除该不一致。

### 修改

**`lib/features/today/data/repositories/lucent.dart`** — 移除 `final Ref ref`，替换为 6 个显式依赖：

| 依赖 | 类型 | 说明 |
|------|------|------|
| `fetchHealthContextSnapshot` | `Future<HealthContextSnapshot> Function()` | 回调形式，保留原 `ref.read(provider.future)` 在调用时读取的行为 |
| `dailyRecordRepository` | `DailyRecordRepository` | 直接注入 |
| `cachedDoseLogDataSource` | `CachedDoseLogDataSource` | 直接注入 |
| `userSettingsRepository` | `UserSettingsRepository` | 直接注入 |
| `medicineReminderRemoteDataSource` | `MedicineReminderRemoteDataSource` | 直接注入 |
| `talker` | `Talker` | 直接注入 |

移除了对 `flutter_riverpod`、`logger.dart`、`health_context/data/providers/health_context.dart`、`workspace.dart`、`record_access.dart`、`settings/data/repositories/lucent.dart` 等 provider 文件的 import。repository 现在仅依赖 domain 接口和 data source 类。

**`lib/features/today/data/providers/today_suggestion.dart`** — `todayRepositoryProvider` 改为在 provider 函数中 `ref.watch` 全部依赖并传入构造函数。
