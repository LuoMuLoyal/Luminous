# 2026-07-12 Migration Log

## 审查报告修复（luminous-review-2026-07-12）

基于 `plans/luminous-review-2026-07-12.md` 增量审查报告中的 🟡/🟢 级别问题，进行以下修复：

### 🟡: LegalDetailPage 非法 docType 时增加返回列表操作

- **文件:** `lib/features/legal/presentation/pages/detail_page.dart`
- **问题:** 当用户直接输入非法 URL（如 `/legal/invalid-type`）时，页面显示错误状态但没有提供返回列表页的操作，形成死胡同体验。
- **修复:** 在 `AppStateErrorView` 中增加 `actionLabel`（"返回列表" / "Back to list"）和 `onAction`（`context.go(AppRoutes.legal)`），引导用户返回法律文档列表页。新增 ARB key `legalBackToListAction`。

### 🟡: LucentLegalRepository 异常处理细粒度化

- **文件:** `lib/features/legal/data/repositories/lucent_repository.dart`
- **问题:** `catch (_)` 捕获了所有异常（包括网络超时、HTTP 500、解析错误等），导致 API 服务器故障时用户看到本地占位文档却误以为是最新版本，调试时也难以区分"API 故障"和"文档不存在"。
- **修复:** 将 `catch (_)` 改为 `on DioException catch (e)`，仅当 HTTP 404（文档不存在）时使用 fallback；其他异常（网络错误、500 等）向上抛出，由 UI 显示明确的错误状态和重试按钮。`findAll()` 和 `findOne()` 两个方法均已修复。

### 🟡: Sentry DSN 为空时跳过 init 调用

- **文件:** `lib/main.dart`
- **问题:** DSN 为空时仍然调用 `SentryFlutter.init`，设置 `options.dsn = null`。注释声称 "no-op"，但实际依赖 SDK 内部实现，可能仍有初始化开销。
- **修复:** DSN 为空时直接 `return`，跳过整个 `SentryFlutter.init` 调用。`Sentry.captureException` 在 SDK 未初始化时是安全 no-op。

### 🟡: runZonedGuarded 初始化顺序修正

- **文件:** `lib/main.dart`
- **问题:** `WidgetsFlutterBinding.ensureInitialized()` 在 `runZonedGuarded` 内部调用，可能导致某些 platform channel 异常无法被 zone 捕获。
- **修复:** 将 `WidgetsFlutterBinding.ensureInitialized()` 移到 `runZonedGuarded` 之前调用，确保 binding 在 zone 创建前完成初始化。

### 🟢: LegalDocType.fromPathSegment 用 Map 优化

- **文件:** `lib/features/legal/domain/entities/legal_doc_type.dart`
- **问题:** `fromPathSegment` 使用 O(n) 遍历查找，虽然当前只有 7 个元素影响微乎其微，但可用 Map 优化到 O(1)。
- **修复:** 新增 `static final Map<String, LegalDocType> _byPathSegment` 预计算映射，`fromPathSegment` 改为直接 Map 查找。

### 🟢: SuggestionJsonCodec 向后兼容旧序列化格式

- **文件:** `lib/features/today/domain/entities/suggestion.dart`、`lib/features/today/data/utils/suggestion_json_codec.dart`
- **问题:** `.name` → `.toJson()` 序列化格式变更后，缓存中已有的旧数据（camelCase 如 `confirmedRisk`）在反序列化时无法被 `fromJson`（期望 snake_case `confirmed_risk`）识别，导致类型回退到默认值。
- **修复:** 在 `TodaySuggestionType.fromJson`、`TodaySuggestionEvidenceKind.fromJson` 和 `_feedbackFromString` 三个反序列化方法中同时接受 snake_case 和 camelCase 两种格式，确保旧缓存数据向后兼容。

### Bug 修复：RangePickerDialog 日历日期范围校验

- **文件:** `lib/features/report/presentation/widgets/dialogs/range_picker_dialog.dart`
- **问题:** forui `FCalendar.grid` 的 `FGridCalendarControl(end: now)` 在日历渲染整月时会触发 `debugCheckInclusiveDateRange`，当 `now` 不是月末时，同月后续日期超出 `[start, end]` 导致 assertion 失败。

## Drift 数据库 Web 平台适配

为鸿蒙 Next ArkWeb 壳方案做准备，将 drift 本地数据库从仅支持原生平台（`dart:io` + `NativeDatabase`）扩展为通过条件导入同时支持 Web 平台（`WasmDatabase`）。

### 新增文件

- **`lib/core/database/database_connection.dart`** — 平台无关的 stub，声明 `DatabaseConnection connect()` 函数签名，不引入任何平台特定依赖
- **`lib/core/database/database_connection_io.dart`** — 原生平台实现，使用 `NativeDatabase.createInBackground(File)` + `getApplicationDocumentsDirectory()`，逻辑与原 `app_database.dart` 中的 `_open()` 完全一致
- **`lib/core/database/database_connection_web.dart`** — Web 平台实现，使用 `WasmDatabase.open()` 加载 `sqlite3.wasm` + `drift_worker.js`，数据通过 OPFS / IndexedDB 持久化
- **`web/drift_worker.dart`** — drift Web Worker 入口点源码，编译为 `web/drift_worker.js`
- **`web/sqlite3.wasm`** — SQLite WASM 二进制（从 sqlite3.dart v3.3.4 release 下载）
- **`web/drift_worker.js`** — 编译后的 drift Web Worker（`dart compile js -O4`，~340KB）

### 变更文件

- **`lib/core/database/app_database.dart`**:
  - 移除 `dart:io`、`package:drift/native.dart`、`package:path/path.dart`、`package:path_provider/path_provider.dart` 四个原生平台 import
  - 新增 `package:flutter/foundation.dart`（仅用 `kIsWeb`）
  - 新增条件导入：`import 'database_connection.dart' if (dart.library.io) 'database_connection_io.dart' if (dart.library.js_interop) 'database_connection_web.dart' as conn;`
  - 构造函数从 `super(_open())` 改为 `super(conn.connect())`
  - `beforeOpen` 中的 `PRAGMA journal_mode = WAL` 用 `if (!kIsWeb)` 保护（WASM SQLite 不支持 WAL）
  - 删除文件内 `_open()` 函数（已移至 `database_connection_io.dart`）

### 条件导入解析规则

| 平台 | `dart.library.io` | `dart.library.js_interop` | 使用的实现 |
|---|---|---|---|
| Android / iOS / macOS / Windows / Linux | ✅ | ❌ | `database_connection_io.dart` |
| Web (JS / WASM) | ❌ | ✅ | `database_connection_web.dart` |
| 理论 fallback | ❌ | ❌ | `database_connection.dart`（抛 UnsupportedError） |

### 测试兼容性

测试文件使用 `AppDatabase.forTesting(NativeDatabase.memory())` 直接传入内存数据库，不经过 `connect()` 函数，因此不受条件导入影响。69 个数据库相关单元测试全部通过。

- `flutter analyze`（全项目）— No issues found
- `flutter test test/core/database/` — 69 tests passed
- `flutter build web --release` — 编译成功，产物输出到 `build/web/`
