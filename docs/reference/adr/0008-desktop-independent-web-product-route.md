# ADR-0008: 桌面端采用独立 Web 产品路线

- **Status**: accepted
- **Date**: 2026-08-16
- **Deciders**: LuoMuLoyal

## Context

Luminous 当前以 Flutter 手机客户端作为首发与用户价值验证表面。现有 Flutter Desktop 和桌面浏览器中的 Flutter Web 复用手机端的信息架构与功能，但桌面场景并不天然需要复制手机端的记录、提醒和五个入口；继续追求机械功能对等，会让手机端产品演进持续承担桌面布局、平台兼容和发布维护成本。

桌面端仍可能为个人用户提供手机屏幕不适合承载的阅读、比较和分析空间，因此本提案不永久放弃桌面产品，也不删除已经存在的 Flutter 桌面代码。需要决定的是桌面产品是否继续作为 Flutter 手机客户端的一个平台目标，还是成为具有独立产品边界的 Web 客户端。

## Decision

采用以下产品与架构边界：

1. **桌面端走独立产品路线**：桌面产品拥有独立的信息架构、功能范围和发布节奏，不复制手机端五个入口，也不要求与手机端功能对等。
2. **独立桌面客户端使用 Next.js + Tauri**：工作台界面使用 Next.js，桌面发行包使用 Tauri；两者从工作台 MVP 起同步交付。客户端代码归属 Lucent 仓库，但本 ADR 不规定其仓库内目录结构。
3. **停止扩展现有 Flutter 桌面表面**：Flutter Desktop 和桌面浏览器形态的 Flutter Web 保留现有代码，不再新增桌面专属产品功能，不再以独立桌面产品对外发行；共享代码回归、安全修复和明确批准的维护任务除外。
4. **手机端边界不变**：Android、iOS 以及面向手机浏览器的 Flutter Web 继续由 Luminous Flutter 客户端承担。桌面路线不得阻塞当前手机端发布与用户验证。
5. **共享业务合同，不共享页面结构**：手机端与独立桌面 Web 共享 Lucent 的 API 合同、账号身份、健康数据语义、授权与安全边界；各自维护适合自身任务的界面和交互。
6. **0.1.0 后启动桌面 MVP**：0.1.0 发布后直接启动工作台 MVP；具体 MVP 页面和功能集另行决策，不阻塞移动端发布。
7. **桌面壳已选择 Tauri**：Tauri 与 Next.js 同步交付；PWA 或其他桌面分发方式不在当前路线内。

## Options Considered

| Option | Advantages | Disadvantages |
|---|---|---|
| 继续用 Flutter 维护桌面与手机功能对等 | 最大化复用现有页面和 Dart 代码 | 桌面任务被手机信息架构限制；每次手机功能变化都带来桌面适配和回归成本 |
| 使用 Flutter 构建差异化桌面界面 | 保留单一客户端技术栈；可继续使用现有桌面基础设施 | 同一仓库仍需长期承担两套信息架构、平台条件分支和桌面发布链路 |
| **独立 Next.js Web 客户端 + Tauri 桌面壳，归属 Lucent 仓库（已选）** | 产品边界清晰；可独立设计大屏交互；可同步提供浏览器与桌面发行形态 | 新增第二套客户端技术栈，以及桌面签名、更新和分发成本 |

## Consequences

- 手机端不再因未来桌面产品而承担机械功能对等要求，桌面端也不再受手机五入口结构限制。
- 现有 Flutter 桌面代码继续保留，但其状态是停止产品扩展，不是新桌面路线的实现基础。
- Lucent 将同时承载后端合同、Next.js 桌面客户端与 Tauri 壳代码，需要明确它们的依赖方向，不能让客户端实现反向成为 API 事实源。
- 两个客户端必须共同遵守 OpenAPI 合同、认证与会话规则、隐私授权、健康数据解释和安全边界；合同变更需要可检测的跨客户端兼容检查。
- 独立客户端需要单独解决认证、CORS/CSRF、SSE、缓存、错误恢复、可访问性、部署以及 Tauri 的签名和更新问题。这些属于后续设计与执行计划，不在本 ADR 中预先给出实现答案。
- 屏幕宽度跳转阈值、页面清单、MVP 阶段、发布时间和 Lucent 内目录结构仍需后续决定。
