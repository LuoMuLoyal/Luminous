## Directory Architecture

代码库是 feature-first 的 **DDD-lite + Clean** 结构，分层依赖由
`luminous_lints --clean-layers` 强制（见 [Layering](#layering-enforced)）。

```
lib/
├── main.dart              # App entry point
│
├── app/                   # 组合根（composition root）
│   ├── bootstrap.dart     # LuminousApp bootstrap (providers, theme, locale, log sink)
│   ├── router.dart        # GoRouter configuration (StatefulShellRoute + top-level routes)
│   ├── router_helpers.dart        # 路由辅助（外部链接、action route 映射）
│   ├── auth_session_adapter.dart  # 会话快照 → 具体 AuthUser 的只读接缝
│   ├── push_handlers.dart         # 推送 → 深链/刷新
│   ├── sync_handlers.dart         # SyncWorker 的实体重放 handler 注册
│   ├── settings_adapters.dart     # 设置项与 provider 的接线
│   ├── window_manager_setup.dart  # 桌面窗口初始化
│   └── composition/       # provider 装配、跨 feature 接线、快照 hub 出口（按 domain 分目录）
│
├── core/                  # 横切基础设施（不得 import lib/features/**）
│   ├── accessibility/     # Accessibility settings (font size, reduce animations, high contrast)
│   ├── ai/                # AI runtime config and providers (experiment seam)
│   ├── analytics/         # Usage analytics
│   ├── auth/              # 会话状态与鉴权守卫（feature-free 值模型）
│   ├── config/            # Developer settings, feature flags, env keys, pref keys
│   ├── composition/       # 可组合表面：组件目录/注册表、表面布局、宿主；responsive/ 下是
│   │                      # 三档列数与跨列（手机 1 列 / 平板 2 列 / 桌面 3 列）
│   ├── database/          # Drift schema/DAOs/connection(io+web)/sync worker/cache cleanup
│   ├── design/            # 设计令牌：color/（SemanticColor）、tokens/（Spacing、图标、动效、断点）、layout/
│   ├── errors/            # Shared error types and handling
│   ├── feedback/          # AppToast, page state views
│   ├── forms/             # Shared form primitives
│   ├── i18n/              # Locale enum and controller
│   ├── logger/            # Talker 单例、级别过滤、Sentry observer
│   ├── native/            # 平台通道（OCR、健康数据等原生桥）
│   ├── network/           # Dio client、API session、SSE、错误映射、contract 词汇、app_log
│   ├── notifications/     # Local notification gateway
│   ├── providers/         # 横切 provider：instrumentation/（DataChangeBus 等）、session/、storage/
│   ├── push/              # Push notification integration
│   ├── router/            # Shared route helpers
│   ├── shortcuts/         # Keyboard shortcuts
│   ├── storage/           # 键值偏好（hive_ce 之上的 KvStore）
│   ├── theme/             # Forui theme family catalog + 主题偏好持久化
│   ├── utils/             # Shared utilities
│   └── widgets/           # Shared UI components
│       ├── common/        # State views, dialog shell, date picker, back button, icon action
│       └── layout/        # PageScaffold, ResponsiveContentFrame
│
├── shared/                # 共享内核：纯值类型，无 I/O、无 Flutter
│   ├── domain/            # failure 词汇（failure.dart）、语义枚举（semantic.dart）
│   └── design/            # 跨 feature 共用的视图令牌（medicine workspace / review dashboard）
│
├── features/              # Business feature modules (17)
│   ├── assistant/         # AI health assistant chat
│   ├── auth/              # Login, register, OAuth (WeChat, Apple, QQ, Google)
│   ├── health_context/    # User health profile (onboarding, allergies, conditions)
│   ├── health_data/       # Health platform data import and sync
│   ├── health_event/      # User-confirmed health event lifecycle and daily outcomes
│   ├── legal/             # Legal document list and detail (terms/privacy)
│   ├── medicine/          # Medicine box, dose logs, reminders, medicine detail
│   ├── mine/              # User profile dashboard, health context summary
│   ├── notification/      # In-app notification list
│   ├── record/            # Daily record logging (symptoms, water, sleep, quick entry, NLP intake)
│   ├── review/            # Review tab: event review and suggestion history
│   ├── scan/              # Barcode/QR medicine scanning
│   ├── search/            # Global medicine search
│   ├── settings/          # App settings (preferences, account, help, sleep reminder)
│   ├── shell/             # 主 tab 外壳（底部导航、桌面侧栏），presentation-only
│   ├── support/           # Support resources (data + domain only)
│   └── today/             # Today dashboard + AI analysis
│
├── theme/                 # Forui CLI 生成的样式（hand-edit 禁止）
│
└── l10n/                  # Localization
    ├── src/               # ARB source fragments (hand-edited, single source of truth)
    └── app_localizations*.dart  # Generated by flutter gen-l10n
```

Legacy directories (`lib/pages/`, `lib/stores/`, `lib/viewmodels/`, `lib/components/`) have been
removed. All runtime code lives under `lib/app/`, `lib/core/`, `lib/features/`, `lib/shared/`,
`lib/theme/`, and `lib/l10n/`.

### Feature Module Inner Structure

每个 feature 按依赖方向分四层。**依赖只能向内**：`presentation → application → domain`，
`data → domain`（实现接口）；组合根在 `lib/app/composition/` 把 data 实现注入 domain 接口。

```
lib/features/<feature>/
├── application/            # use case 与 orchestrator（纯 Dart，不出现 Ref/BuildContext）
│   ├── usecases/           # 单操作 use case（函数式）
│   └── orchestrators/      # 多步流程 orchestrator（类式）
│
├── data/                   # 数据访问
│   ├── datasources/        # Remote API、本地源、缓存源（含平台适配器）
│   ├── mappers/            # DTO ↔ domain entity
│   └── repositories/       # Repository 实现 + 同文件的 @riverpod 装配
│                           # （data/providers/ 已废弃，且被门禁禁止）
│
├── domain/                 # 纯 Dart：仅 fpdart / freezed_annotation / meta / clock + lib/shared/domain
│   ├── entities/           # 领域实体（freezed）
│   ├── repositories/       # Repository 接口
│   ├── services/           # 纯规则服务
│   └── constants/          # 领域常量 / 目录
│
└── presentation/           # UI（薄：build + 路由 + 触发 use case）
    ├── pages/              # 整页 widget
    ├── providers/          # 读模型 provider + data_access.dart 接缝
    ├── controllers/        # UI 控制器
    ├── utils/              # 展示层工具
    └── widgets/            # 页面级 widget
        ├── dialogs/        # 弹窗
        ├── forms/          # 表单组件
        ├── sections/       # 页面分区
        ├── shared/         # feature 内共用
        └── views/          # 视图级 widget
```

禁止目录（`forbidden_directory`）：`presentation/services/`、`data/providers/`、
`presentation/flows/`。

**四层齐全**（application + data + domain + presentation）：`record`、`settings`、`today`

**标准**（data + domain + presentation）：`assistant`、`auth`、`health_data`、`health_event`、
`legal`、`medicine`、`mine`、`notification`、`review`、`scan`、`search`

**仅 data + domain**：`health_context`、`support`

**仅 presentation**：`shell`

`application/` 是逐 feature 推广中的层：目前只有 `record`、`settings`、`today` 有 use case，
其余 feature 的编排仍在 `presentation/providers/` 里；推广范围见
`plans/2026-10-21-ddd-refactor-frontend.md`。

### Presentation → Data 的接缝

`presentation/` **不得 import `data/`**。每个 feature 用
`presentation/providers/data_access.dart` 再导出（`export`）自己 data 层的 provider，
作为展示层唯一取数入口。该文件是纯中转、不含逻辑；`export` 不构成 import，因此不违反
`presentation_layer` 规则，但语义上它是「展示层不认识 data 实现」的边界。

### Application Layer

application 层承载原先内联在页面里的业务编排，两种形态：

- **函数式 use case**（`application/usecases/`）：单一操作。**只接收纯参数**
  （实体、值对象、领域类型），不接收 `Ref` / `BuildContext`；副作用通过与编排无关的返回值表达。
- **类式 orchestrator**（`application/orchestrators/`）：多步流程，依赖通过构造注入。

application 层可以 import **别的 feature 的 `domain/`**（接口 + 实体）做跨 feature 编排，
但**永不**触碰对方的 `data/` 或 `presentation/`。

## Layering (enforced)

分层不是约定而是门禁：`tool/luminous_lints` 的 `--clean-layers` 模式跑 R1–R9，违规即 exit 1，
无白名单。命令、允许清单与门禁挂载点（pre-push / `scripts/workflows/daily.dart` / CI）见
`AGENTS.md` §Layering Rules。

- `domain_purity` — `domain/**` 只允许 `dart:*`、纯 Dart 包、同 feature `domain/`、
  `lib/shared/domain/`；框架与插件包另由 CLI 的文本级检查拦截
- `application_layer` — `application/**` 只允许 `domain/`（含别的 feature）+ `lib/shared/domain/`
- `data_layer` — `data/**` 只允许同 feature `domain/`、自身层、`core/network|database|storage`、
  `lib/shared/`
- `presentation_layer` — `presentation/**` 不得 import `data/**`；只允许同 feature
  `application/`+`domain/`、自身层、纯 UI 的 `core/` 子树、`app/router`、`app/composition`、
  `app/auth_session_adapter.dart`、`lib/shared/`
- `core_not_import_features` — `lib/core/**` 不得 import `lib/features/**`
- `cross_feature_import` — 不得 import 别的 feature 的 `data/**` 或 `presentation/**`
- `directory_file_cap` — 单目录直挂源文件 ≤ 8
- `forbidden_directory` — 见上

已知待对齐项：观察模式的 `layered_import` 允许跨 feature 的 `presentation/providers/` 接缝与
`shell` 外壳，而 `cross_feature_import` 目前两项都不允许。收敛计划见
`plans/2026-10-28-composable-tabs.md` A0。

## Design System

The active root theme is now Forui-led. `LuminousApp` applies Forui `FTheme` at the app root and
derives `MaterialApp` light/dark themes from Forui `FThemeData` through
`toApproximateMaterialTheme()`.

- **Root theme** → `lib/core/theme/family.dart` — Owns the app-level Forui theme-family catalog and stock
  light/dark theme mapping
- **Color token** → `lib/core/design/color/semantic_color.dart` — `SemanticColor` enum used by
  data/domain layers; resolved through the current Forui theme in widgets via `.solid(context)` / `.subtle(context)` / `.muted(context)` / `.border(context)`
- **Spacing/icon-size tokens** → `lib/core/design/tokens/spacing.dart`, `tokens/icon_size.dart` —
  Project layout vocabulary (`Spacing`, `IconSizeTokens`) plus Forui-native
  `style.borderRadius` / `typography` scales
- **Theme preference** → `lib/core/theme/preference.dart` — Persists both `ThemeMode`
  and `theme.family`
  (`system / light / dark`)

Shared page chrome is now Forui-based: child pages compose `FScaffold` and `FHeader` directly,
`AppBackButton` is a Forui icon button, `showAppDialog` / `DialogShell` wraps `showFDialog` /
`FDialog`, and shared state surfaces use `FCard`/`FButton`. Legacy bridge files
(`AppThemeSurface`, `AppTypographyTokens`, `AppSectionSurface`, `AppColorTokens`, `AppShadowTokens`,
`AppInkWell`, `AppDialog`) have been removed from runtime `lib/`.

That same direction now also covers shared feedback/control surfaces: global toast presentation
resolves from `FTheme`, and feature-level control panels such as the assistant settings block are
expected to use page-local Forui tiles/switches directly instead of routing new work back through
the old `AppSettings*` wrapper set.

The top-level `SettingsPage` and the main secondary settings sub-pages (`theme`, `language`,
`advanced`, `notification`, `sleep reminder`, `AI`, `help`, `about`, `data export`) render directly
with page-local Forui tile groups/tiles/switches/cards/buttons; the old shared settings wrapper set
under `lib/core/widgets/settings/` has been removed.

### UI Guidelines

- Prefer flat surfaces over nested boxes (aligned with concept images).
- No explanatory/narrative/onboarding copy on normal app pages.
- All page-level error states use `AppStateErrorView`.
- All page-level loading states use shimmer skeleton screens.
- Child pages default to a standard header: left back arrow + centered title.
- Mock repositories live only under `test/helpers/mocks/`; production code always uses the Lucent implementation.
- During the Forui migration, touched pages should move toward Forui primitives directly instead of
  adding new handcrafted wrapper aliases.
- The root shell is already on Forui primitives: `ShellPage` uses `FScaffold`,
  `FBottomNavigationBar`, and `FSidebar` while keeping the existing GoRouter `StatefulShellRoute`
  structure, and its navigation/action iconography now comes from Forui's bundled Lucide set instead
  of Material icons.
- The shared child-page shell is now also on Forui primitives, but the repo is still in an
  intentional compatibility phase where shared scaffolding can host both Forui widgets and
  unmigrated Material descendants in the same page tree.

## Key Conventions

### Freezed Immutable Models

Domain entities use the `freezed` package for immutable data classes with union types, JSON
serialization, and `copyWith`.

### flutter_hooks

Form controllers (`TextEditingController`, `FocusNode`) are managed via `flutter_hooks`
(`useTextEditingController`, `useFocusNode`) instead of `StatefulWidget` lifecycle. This eliminates
`initState`/`dispose` boilerplate and reduces widget rebuild scope.

### Internationalization

User-visible text goes through ARB fragment files + `flutter gen-l10n`. Locale is resolved via
`AcceptLanguageResolver`. See [Localization](localization.md).

### Cross-Feature Import Boundaries

Three rules govern cross-feature imports to prevent coupling. 它们由
`layered_import`（观察模式）与 `--clean-layers` 的 `cross_feature_import`（门禁）共同覆盖，
口径差异见 [Layering](#layering-enforced)。

1. **data → data prohibited**: A feature's `data/` layer must not import another feature's
   `data/` layer. Cross-feature data access goes through **domain interfaces**
   (`domain/repositories/`). Provider assembly injects concrete implementations at the
   provider wiring level.

2. **presentation → presentation prohibited**: A feature's `presentation/` layer must not
   import another feature's `presentation/` providers. Cross-feature reads use **domain
   entities** or the **shared read-only snapshot hub** (`healthContextSnapshotProvider`).
   Cross-feature writes use the **DataChangeBus**.

3. **application → domain allowed**: The `application/` layer may import other features'
   `domain/` layer (interfaces + entities) for cross-feature orchestration. This is the
   application layer's privilege — it coordinates across features but only through domain
   abstractions, never through data or presentation implementations.

### WeChat OAuth

- **Mobile**: Uses `fluwx` SDK to obtain auth code → Lucent mobile callback.
- **Desktop**: Loopback callback listener → system browser → Lucent redirect.
- **Web**: Passes `/login/oauth/wechat` as callback path.
- Manual callback paste is a fallback for all platforms.
