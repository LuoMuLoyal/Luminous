## Luminous - Color migration (decision updated)

- Time: ~09:30 local time.
- Decision updated: do not create a color mapping. Instead, delete the project's existing color system entirely and replace every color reference at its call site with Forui semantic colors.
- Key points agreed:
  - No custom color extension; no custom theme for now; default family remains `neutral`.
  - All project-specific color constants and helper classes (e.g. `AppColors`, theme extensions, color palettes) will be removed.
  - All `Color(0xFF...)` literals in `lib/` will be replaced at the usage site with `context.theme.colors.*` when a `BuildContext` is available.
  - All `Theme.of(context).colorScheme.*` reads will be replaced with `context.theme.colors.*`.
  - Files without `BuildContext` (data/domain/repository layer) will use static `FThemes.neutral.light.touch.colors.*` references, not project constants.
  - `const` contexts that become invalid after switching to non-const Forui colors will be fixed by removing `const` from the relevant widget/literal.
- Action taken: exploratory automated mapping script remains reverted; migration will be performed by directly editing call sites.
- Next step: enumerate all color references in `lib/`, remove color definition files, replace each reference, then verify with `flutter analyze --no-pub` and `flutter test --no-pub`.
