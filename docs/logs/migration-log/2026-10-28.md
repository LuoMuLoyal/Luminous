# 2026-10-28

## 本地存储整改 P0：cache-first 覆盖全部读路径

ADR-0006 §4 的「初期只缓存 5 个核心实体」范围被证明撑不起 cache-first 的承诺。
实测 23 个 repository 中只有 4 个读缓存，页面要等齐所有数据源才渲染，
**本地有无缓存不影响首帧**——UI 层（`PageViewState` 的 `isLoading && hasValue` 短路）
与守卫层（`authGuarded` 冷启动直接 fetch）本身正确，缺的是 repository 层的缓存。

按页面逐个补齐，每个页面一个独立提交：

| 提交 | 范围 | 新增缓存 |
|---|---|---|
| `ae8b38c2b` | record 汇总 | `daily_record_summaries` |
| `c71430c03` | notification 列表 | `notification_pages` |
| `3dd57060a` | mine 仪表盘 | `mine_dashboards` |
| `1bee2734f` | medicine 工作台 | `medicine_workspaces` |
| `97b99d293` | search 结果 | `search_results` |
| `05b89a4e7` | user settings | `user_settings_cache` |

### 统一模式

每个仓储：读缓存 → 命中即返回并触发节流后台刷新（`backgroundRefreshThrottle`）
→ miss 走网络并回写。写路径（含 mutation）后失效对应缓存。
沿用 `cache_constants.dart` 的既有常量，**不引入 per-row TTL**——
`cachedAt` 只供保留期清理使用。

### JSON 序列化交还代码生成

此前缓存层靠手写的 `DailyRecordJsonCodec`（104 行）做序列化。改为在实体上加
`@freezed` + `fromJson`，由 `json_serializable` 生成——手写解析对未知枚举值会
**静默回退**（未知 kind 被当成 `note`），这是隐患；生成代码会直接抛错，
缓存损坏时不会被伪装成别的记录类型。

### 展示层字段移出 domain

`mine` / `medicine` / `search` 的实体里混着 `IconData`、`SemanticColor`——
这些是客户端决定的样式，却让实体无法序列化。逐个拆出：

- `mine` → `presentation/utils/mine_visuals.dart`（按 `kind` / `titleKey` 推导）
- `medicine` → `presentation/utils/medicine_visuals.dart`；
  服务端返回的语义色保留在实体上，并给 `SemanticColor` 加 `@JsonEnum`；
  告警的 `IconData` 改为可序列化的 `MedicineAlertIcon` 标识
- `search` → `presentation/utils/search_visuals.dart`（按 `type` 推导）

### 破坏性口径

数据库按**全新安装**定义：删掉整条 1→5 迁移链，`schemaVersion` 回到 1，
`onUpgrade` 不再保留任何兼容分支。

### 验证

`flutter analyze` 无问题；`flutter test` 全绿（record / notification / mine /
medicine / search / settings 各自单独跑过，最后跑全量）。

## 本地存储整改 P1 / P2

### P1：shared_preferences → Hive

`shared_preferences` 全量替换为 `hive_ce`（原 `hive` 已停止维护）。**破坏性变更**：
不迁移旧偏好，升级后偏好重置为默认值。

- 新增 `lib/core/storage/kv_store.dart`：`KvStore` 接口 + `HiveKvStore`（生产）+
  `MemoryKvStore`（测试）。统一经 `KvStore.instance` 访问；未打开时抛错，而不是
  静默返回空表。
- 移除 `shared_preferences` 依赖；20 个文件的调用点全部迁移。
- 顺带删除误导性遗留：`PrefKeys.accessToken` / `refreshToken` 与
  `SharedPrefsLucentSessionStore` 的整套双键迁移逻辑。这两个 key 早已不承载真实
  token（真实存储在 `flutter_secure_storage`），留着只会让人误判成「token 明文落盘」。
- 测试侧新增 `test/helpers/kv_test_store.dart`，替代
  `SharedPreferences.setMockInitialValues`。

**迁移中修掉的真实退化**：批量替换把若干默认值抹平成了 `false` / `0`：

| 位置 | 原默认 | 被误改为 |
| --- | --- | --- |
| `feature_flags` `onDeviceAiRuntime` | `envConfig.enabled` | `false` |
| `feature_flags` `genUiEnabled` | `envConfig.genUiEnabled` | `false` |
| `feature_flags` `assistantStreamMode` | `true` | `false` |
| `quick_entry` `waterCustomMl` | `250` | `0` |
| `quick_entry` `medicationAutoRecordSingle` | `true` | `false` |
| `quick_entry` `medicationShowAlreadyRecordedHint` | `true` | `false` |

这些不是测试问题而是**功能退化**（例如 AI 运行时会默认关闭），已逐个恢复。

### P2：本地库启用 SQLCipher 加密

**破坏性变更**：不迁移明文库，检测到「无密钥但文件存在」即删除重建。

- 新增 `lib/core/database/key.dart`：密钥为 **32 字节原始随机量**（SQLCipher 的
  256-bit key），由 `Random.secure()` 生成（平台 CSPRNG），base64 存平台安全存储。
- 打开库时以 `PRAGMA key = x'<hex>'` 注入**原始字节**。用 blob 字面量而非引号字符串
  是关键：后者会走 SQLCipher 的 KDF，得到完全不同的密钥材料。
- **密钥取不到时直接失败，绝不降级为明文**——静默明文落盘比打不开更糟。
- 依赖层面 `sqlite3_flutter_libs` → `sqlcipher_flutter_libs`；两者都提供原生
  `sqlite3` 符号，并存会链接冲突。
- **Web 不加密**：`connection_web.dart` 走 `WasmDatabase`，SQLCipher 不适用，
  该平台由浏览器 origin 隔离保护。ADR-0006 §5 已把范围限定在原生平台。
- 新增 `test/core/database/key_test.dart`：锁定 32 字节、同安装内稳定、跨安装互异、
  存储不可用时抛错。

### 验证

`flutter analyze` 无问题；`flutter test` **4014 通过 / 5 跳过**。
