## refactor(architecture): 分层门禁 `--clean-layers` 从 34 条清零

### 范围

只动架构接缝与目录组织，无行为变更；`flutter analyze` 与相关测试全绿。

### 结论

`dart run bin/luminous_lints.dart --clean-layers` 由 **34 条红灯**降到
**0**（`clean-layers gate: clean`）。三类违规逐条消除：

- **cross_feature_import 28 → 0**：跨 feature 的 `presentation`/`data` 直连
  改走门禁承认的两个接缝——`presentation/providers/`（feature 对外发布的读模型与
  入口）与组合根 `lib/app/composition/`。典型收敛：
  - 三件通用展示原语（分组标题 / 选中标记 / 瓦片组样式）下沉
    `core/widgets/common/control/settings/`，`settings` 不再被别的 feature 反向 import；
  - 药品加箱闭环与预检对话框收进 `search/presentation/providers/`，
    药品文案与图标下沉 `medicine/design/`，扫描侧改走该接缝；
  - 扫描方法选择面板（`showMedicineBoxScanSheet`）迁到
    `scan/presentation/providers/`；
  - 组件的**身份常量**下沉共享内核（`shared/domain/composition/ids.dart`、
    `generative/design/ids.dart`），表面目录不再互相 import 别人的组件目录；
  - 槽位编辑面板经组合根注入（`app/composition/generative/slot_editor.dart`），
    编排页不 import `generative` 的 widgets；
  - 搜索页的 `@TypedGoRoute` 声明随页面迁回 `search`，`medicine` 路由表不再
    引用 search 页面；桌面外壳经 `medicine/presentation/providers/detail_view.dart`
    复用详情内容体。
- **presentation_layer 1 → 0**：genui 区块声明改为领域仓储
  `SlotSpecRepository`（读取同步，首帧即正确），presentation 不再 import 自己的
  `data/`。
- **directory_file_cap 5 → 0**：`record/.../dashboard` 按日历/筛选/日期、
  `medicine` 的实体/数据源/读模型按风险/提醒/安全拆子目录。

## feat(shell): 底部 tab chrome 数据化，取消 go_router → auto_route 迁移

### 决策改动

推翻 `plans/2026-11-12-navigable-shell-auto-route.md` 的核心前提。原方案以
「`StatefulShellRoute` 要求 branches 编译期固定」为由主张全仓迁移 `auto_route`。
核对 `go_router 17.3.0` 源码后该前提不成立：`branches` 是普通
`final List<StatefulShellBranch>`（`lib/src/route.dart` 的构造函数只断言
`branches.isNotEmpty`），运行期构造完全可行；真正受限的只是「router 建好后不能改
branches」（`StatefulNavigationShell.currentIndex` 是 `final`，`goBranch` 按 index
寻址）。而 Material 底栏上限 5、本仓恰好占满 5 个，「运行期增删 tab」不通往任何
产品形态。故**留在 `go_router`**，`lib/app/router.dart` 一行未改。

计划文件同时更名为 `plans/2026-11-12-navigable-shell.md`，内容重写为「在 go_router
上做数据驱动」。

### 变更范围

- 新增 `features/shell/domain/`：`TabId` / `TabPlacement` / `NavConfig`（纯值 +
  严格 JSON 编解码，未知 `schemaVersion` 与任何结构问题整体回退默认）、
  `TabDefinition`、`nav_rules.dart`（名称清洗、编辑校验、配置补全、可见过滤）、
  `NavConfigRepository` 接口。
- 新增 `features/shell/data/repositories/cached_nav_config.dart`：KV 持久化
  （`PrefKeys.shellNavConfig`），写默认配置等价于删键；坏数据保留原始值供诊断。
- 新增 `features/shell/presentation/providers/`：`navConfigProvider` /
  `resolvedNavProvider` / `visibleNavProvider`，以及 `data_access.dart` 接缝
  （presentation 不直接 import `data/`）。
- 改写 `presentation/tab.dart`：`ShellTabStyle` 提供默认图标与 ARB 文案，
  `ResolvedTab` 合并配置与注册表，`shellTabKey(TabId)` 供测试按身份查找。
- 改写 `presentation/page.dart` 与 `sidebar/desktop.dart`：底栏与侧栏都遍历
  resolved 列表，切换经 `ResolvedTab.branchIndex` 翻译回 `goBranch`；底栏选中态
  按「可见列表里的位置」算，不再等于 branch 下标。
- 删除 `enum ShellTab`、`enum ShellBranch`、`test/shell/branch_test.dart`。
- `common_{en,zh}.arb` 新增 `shellNav*` 文案（编排页标题、字段标签、校验提示），
  经分片合并 + `flutter gen-l10n` 生成。

### 不变量

- branch 结构是编译期的，用户配置只改变渲染顺序。
- 可见 tab 数 3..5；首页 tab 不可隐藏；重复 / 未知 tabId 拒绝。
- `completeNavConfig` 永远成功：注册表新增的 tab 自动补进来（插在默认位置附近），
  删掉的跳过，`order` 归一——升级加 tab 后老配置照样渲染。
- `ShellTabStyle.review.testKey` 仍为 `shell-tab-report`。

### 验证

- `flutter analyze lib test integration_test` 无问题。
- `luminous_lints --clean-layers` 违规数与改动前一致（无新增）。
- 新增 `nav_config_test`（JSON 与坏数据）、`nav_rules_test`（规则与补全）、
  `cached_nav_config_test`（降级语义）、`nav_render_test`（顺序 / 名称 / 隐藏 /
  坏数据 / 编排往返的端到端行为）。
- `test/shell`、`test/app`、`test/desktop` 全绿。
- 未做：编排页 UI（N2）与 Lucent `/layouts/tab` 同步（N3），
  记在 `plans/2026-11-12-navigable-shell.md` §5。

## feat(shell): 底部导航编排页 N2

### 变更范围

- 新增 `/customize/nav`（`features/shell/presentation/pages/nav_customizer.dart`），
  入口在设置页常规分组的 `settings-row-nav`。每行：图标 + 名称 + 路由路径 +
  换图标 + 上移/下移 + 显隐开关；底部「恢复默认」带二次确认。
- 新增 `navDraftProvider` / `navDraftRowsProvider`：进页面以**补全后**的配置为起点，
  改动只进内存，取消丢弃、完成才写回；非法编辑逐次拒绝并 toast，草稿不变。
- 用上移/下移按钮而非拖拽：5 项、顺序长期生效，按钮可预期可自动化；组件编排页
  用拖拽是因为那边组件多、顺序是探索性的。首项上移与末项下移置灰不隐藏，
  越界移动是无操作而非报错。
- `SemanticIcons` 补 `actionUp` / `actionDown` / `actionBottomNavigation`。
- `Routes.customizeNav`；`shell/presentation/routes.dart` 注册到组合根。
- ARB 补 `shellNav*` 的编排页文案（标题、描述、字段、提示、计数摘要）。
- 留白就地用 `Spacing` 令牌算，不复用 settings 的 `page_padding.dart`
  （`cross_feature_import` 禁止跨 feature import presentation）。

- `luminous_lints --clean-layers` 违规数与改动前一致（无新增；过程里一度引入

## feat(shell): tab 配置接通远端同步 N3

### 变更范围

- 新增 `domain/repositories/nav_config_remote.dart`：`NavConfigRemote` /
  `NavConfigSyncQueue` 两个窄端口。shell 不能 import customizer 的 `data/`
  （`cross_feature_import`），但两者要共用同一个 `/layouts` 端点，所以跨 feature
  的接缝停在 `domain/`。
- 新增 `data/sync/nav_config_sync.dart`：`NavConfigSync` 负责推送、拉取与离线入队。
  载荷编解码各一份——`NavConfig` 不是 `SurfaceLayout`（`ComponentPlacement.id`
  要求 `domain.view` 两段格式，tab id 是 `today` 这样的单段值）。
- 装配在组合根 `lib/app/composition/shell/nav_config_sync.dart`，把 customizer 的
  `LucentLayoutRemote` / `PendingLayoutSyncQueue` 适配成 shell 的端口。
- `LayoutRemote` 增加 `fetch(surface)`（404 → `Right(null)`）；`LayoutSyncQueue`
  增加 `enqueueRaw`，并让 `decodeLayoutPayload` 同时接受对象与已编码字符串两种信封。
- `NavConfigController` 的 `commit()` / `reset()` 各推一次；新增 `adoptRemote`。
  `bootstrap` 在 `restore()` 之后、**仅已登录**时拉一次。
- 本地 KV 仍是权威读源：推送失败入 `ui_layout` 队列由 `SyncWorker` 重放，
  拉取失败静默保持本地，远端文档解不开时不覆盖用户当前能用的配置。

- `flutter analyze lib test integration_test` 无问题。
- `luminous_lints --clean-layers` 违规数与改动前一致（无新增；过程里一度因

- 新增 `test/shell/nav_config_sync_test.dart`（推送、重放入队、拉取采纳、
  远端空/坏数据/失败三条降级、载荷往返共 13 条）。
- `test/shell`、`test/customizer`、`test/core/composition` 与全量 `flutter test` 全绿。
