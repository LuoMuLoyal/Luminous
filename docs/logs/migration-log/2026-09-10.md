# Migration Log — 2026-09-10

## fix(android): x86_64 模拟器 debug 启动崩溃修复

### 问题

`flutter run` 在 Android x86_64 模拟器上启动即崩，日志 `Could not find 'libflutter.so'`（`Luminous/error.md`）。

### 根因

提交 `2a21140d`（2026-08-28 `perf(apk): PaddleOCR 模型按需下载 + release 限 ABI + 代码混淆`）在 `android/app/build.gradle.kts` 中做了两处 ABI 收缩：
1. `defaultConfig.ndk.abiFilters` 从 `["arm64-v8a", "x86_64"]` 缩为仅 `["arm64-v8a"]`。
2. **新增无条件 `packagingOptions`**，在 `resources` 与 `jniLibs` 两处同时排除 `lib/x86_64/**` 和 `lib/armeabi-v7a/**`。

第 2 项是直接原因：`packagingOptions` 无论放在 `buildTypes.release {}` 还是顶层，在 AGP 9 下均**全局生效**——`buildTypes` 块内的 `packagingOptions` 实际作用于项目全局共享实例（AGP 8+ 已弃用的 legacy DSL），debug 变体同样受影响。debug 构建 `-Ptarget-platform=android-x64` 时，Flutter 引擎通过 `CopyFlutterJniLibsTask` 将 `lib/x86_64/libflutter.so`（来自 `io.flutter:x86_64_debug` AAR）复制到 merged_jni_libs，但资源与 jni 打包阶段的全局 excludes 将其剔除，APK 中完全缺失 → 运行时崩溃。

### 修复

`Luminous/android/app/build.gradle.kts`（126 行）：

- **删除** `buildTypes.release { packagingOptions { ... } }` 块（旧 DSL，全局泄漏根因）。
- **新增** `androidComponents { onVariants(selector().withBuildType("release")) { ... } }`（AGP 8+ variant API），在该作用域内设置 `variant.packaging.jniLibs.excludes` 与 `variant.packaging.resources.excludes`，排除 `lib/x86_64/**` 与 `lib/armeabi-v7a/**`，**仅对 release 变体生效**。
- `abiFilters` 恢复为 `["arm64-v8a", "x86_64"]`（注释说明 Flutter 插件会用 PLATFORM_ABI_LIST 覆盖）。

### 验证

| 构建目标 | ABI 覆盖 | libflutter.so | 结果 |
|---|---|---|---|
| `flutter build apk --debug --target-platform android-x64` | arm64-v8a + armeabi-v7a + x86_64（13+12+13 = 38 文件） | `lib/x86_64/libflutter.so` | ✅ 通过 |
| `flutter build apk --release --target-platform android-arm64` | arm64-v8a（15 文件） | `lib/arm64-v8a/libflutter.so` + `libapp.so` | ✅ release 仍为 arm64-only |
| `flutter run -d emulator-5554 --debug` | — | `flutter (null) was loaded normally!` / Impeller OpenGLES 启动 | ✅ 模拟器正常启动，原崩溃消失 |

`health` 插件 `ClassCastException`（`HealthPlugin.onAttachedToActivity` → MainActivity 未实现 `ComponentActivity`）为独立问题，与本次 ABI 修复无关。

## fix(auth): 冷启动 skeleton 屏 → 离线优先即时显示本地缓存

### 问题

冷启动时所有 tab 显示骨架屏长达 8 秒（session restore 超时），即使本地 Drift 缓存中已有上次数据。离线优先架构应当在启动瞬间显示缓存数据，同时后台刷新。

### 根因

`authGuarded()` 在 `session.isRestoring` 期间返回 `pendingAuthSessionResolution<T>()`（永不完成的 Future），所有依赖 `authGuarded` 的 provider（todayDashboard、mineDashboard、medicineWorkspace、recordDashboard、healthContextSnapshot 等）全部卡在 `AsyncLoading` → 骨架屏。同时 `resolvePageViewState()` 在 restore 期间无条件返回 `PageViewStateLoading`，即使 provider 已有数据也强制骨架。

### 修复

**`lib/core/providers/auth_guarded.dart`**:
- 函数签名从同步改为 async（`Future<T>` 包裹，throw 行为不变）。
- `isRestoring` 路径增加 stored-session gate：读取 `lucentSessionStoreProvider.readRefreshToken()`，有 token（返回用户）→ 调用 `fetch()` 走 cache-first 路径，缓存数据即时呈现；无 token（全新安装）→ 保留原 `pendingAuthSessionResolution` 行为（restore 极快 resolve 为 signed-out，无需无谓请求）。
- 新增 `_hasStoredSession()` 辅助函数，store 读取失败时静默返回 `false`（测试环境/平台通道不可用时不崩溃）。
- 文档注释全面更新，记录 offline-first 设计决策和 signed-out gate 理由。

**`lib/core/widgets/common/feedback/page_state.dart`**:
- 移除 `resolvePageViewState()` 中 `Priority 1: session.isRestoring → PageViewStateLoading` 判断。现在直接委托给数据状态（loading/error/ready），当 provider 已有缓存数据时直接展示而非骨架。
- 文档注释和类级 doc 更新，反映新的优先级顺序。

### 测试影响

- `auth_guarded_test.dart`：新增 "stored session → fetch during restore" 和 "no stored session → pending" 两个测试，替代旧的 "restoring → pending" 单测试。`throws` 测试因 async 变更需 `await` 后检查 error。
- `session_gate_test.dart`：restore 测试增加 `MemorySessionStore` override（带 token）；signed-out 测试从同步断言改为 await microtask 后检查 error。
- `risk_check_providers_test.dart` / `risk_check_provider_test.dart`：signed-out 测试同上，需 await 微任务后检查 provider error 状态。
- `recognize_dialog_test.dart`：22 个测试全部通过——stored-session gate 防止了 restore 期间的网络调用链触发平台通道异常。
- 全量 `flutter test`：3702 通过 / 5 skipped / 0 失败。

### 消费者签名变更注意

`authGuarded` 从同步函数变为 async 函数。所有调用者已在 async 上下文中（`FutureProvider` 或 `AsyncNotifier`），无需调用方改动。受影响的测试文件需要在 signed-out 断言前 `await Future.delayed(Duration(milliseconds: 50))` 等待 error settle。
