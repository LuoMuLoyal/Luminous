# Migration Log — 2026-09-10

## fix(android): x86_64 模拟器 debug 启动崩溃修复

### 问题

`flutter run` 在 Android x86_64 模拟器上启动即崩，日志 `Could not find 'libflutter.so'`（`Luminous/error.md`）。

### 根因

提交 `2a21140d`（2026-08-28 `perf(apk): PaddleOCR 模型按需下载 + release 限 ABI + 代码混淆`）在 `android/app/build.gradle.kts` 中做了两处 ABI 收缩：
1. `defaultConfig.ndk.abiFilters` 从 `["arm64-v8a", "x86_64"]` 缩为仅 `["arm64-v8a"]`。
2. **新增无条件 `packagingOptions`**，在 `resources` 与 `jniLibs` 两处同时排除 `lib/x86_64/**` 和 `lib/armeabi-v7a/**`。

第 2 项是直接原因：`packagingOptions` 无论放在 `buildTypes.release {}` 还是顶层，在 AGP 9 下均**全局生效**——`buildTypes` 块内的 `packagingOptions` 实际作用于项目全局共享实例（AGP 8+ 已弃用的 legacy DSL），debug 变体同样受影响。debug 构建 `-Ptarget-platform=android-x64` 时，Flutter 引擎通过 `CopyFlutterJniLibsTask` 将 `lib/x86_64/libflutter.so`（来自 `io.flutter:x86_64_debug` AAR）复制到 merged_jni_libs，但资源与 jni 打包阶段的全局 excludes 将其剔除，APK 中完全缺失 → 运行时崩溃。

### 修复

`Luminous/android/app/build.gradle.kts`（126 行）：

- **删除** `buildTypes.release { packagingOptions { ... } }` 块（旧 DSL，全局泄漏根因）。
- **新增** `androidComponents { onVariants(selector().withBuildType("release")) { ... } }`（AGP 8+ variant API），在该作用域内设置 `variant.packaging.jniLibs.excludes` 与 `variant.packaging.resources.excludes`，排除 `lib/x86_64/**` 与 `lib/armeabi-v7a/**`，**仅对 release 变体生效**。
- `abiFilters` 恢复为 `["arm64-v8a", "x86_64"]`（注释说明 Flutter 插件会用 PLATFORM_ABI_LIST 覆盖）。

### 验证

| 构建目标 | ABI 覆盖 | libflutter.so | 结果 |
|---|---|---|---|
| `flutter build apk --debug --target-platform android-x64` | arm64-v8a + armeabi-v7a + x86_64（13+12+13 = 38 文件） | `lib/x86_64/libflutter.so` | ✅ 通过 |
| `flutter build apk --release --target-platform android-arm64` | arm64-v8a（15 文件） | `lib/arm64-v8a/libflutter.so` + `libapp.so` | ✅ release 仍为 arm64-only |
| `flutter run -d emulator-5554 --debug` | — | `flutter (null) was loaded normally!` / Impeller OpenGLES 启动 | ✅ 模拟器正常启动，原崩溃消失 |

`health` 插件 `ClassCastException`（`HealthPlugin.onAttachedToActivity` → MainActivity 未实现 `ComponentActivity`）为独立问题，与本次 ABI 修复无关。
