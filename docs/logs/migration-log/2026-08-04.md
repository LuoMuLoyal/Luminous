# 2026-08-04 全仓库审查修复

来源：`plans/Luminous-review-2026-08-04.md`（3 🔴 + 7 🟡 + 2 🟢，代码验证全部属实；审查文档随后删除）

## 核心数据层（🔴 3 条）

### 1. 待同步队列 ID 生成与并发安全

- `lib/core/database/daos/pending_sync_dao.dart`
  - `_generateId()` 保持 `Random.secure()` 32 位随机后缀 + 微秒时间戳：热重启/多 isolate 场景下仍不与库内旧 ID 冲突。
  - `markFailed()` 由先读后写改为数据库层原子更新 `retryCount = retryCount + 1`（`PendingSyncItemsCompanion.custom`），消除并发调用时重试计数漏增的竞态条件。

### 2. 后台刷新日志升级

- `lib/features/record/data/repositories/lucent_daily.dart`
  - 内联 `Duration(seconds: 30)` 改为复用 `backgroundRefreshThrottle`（`lib/core/database/cache_constants.dart`）。
  - 新增按日期维度的连续后台刷新失败计数器；连续失败 3 次后将日志级别从 `warning` 提升为 `error`，成功时清空计数器，避免用户长期看到过旧缓存而开发者无感知。

### 3. SSE 重连退避上限

- `lib/core/network/sse.dart`
  - 退避由 `Duration(seconds: 1 << (reconnectAttempts - 1))` 改为 `.clamp(1, 60)`，即使未来调高 `maxReconnects` 也不会产生不可控的等待时间。

## 警告项修复（🟡 7 条）

### 4. `catch (_)` 异常不再只 Toast

- `lib/features/record/application/usecases/quick_entry_medication.dart`（2 处）
- `lib/features/record/application/usecases/quick_entry_sleep.dart`（5 处）
- `lib/features/record/application/usecases/quick_entry_meal.dart`（1 处）
- `lib/features/record/presentation/pages/page.dart`（1 处）

原 `catch (_)` 块仅显示 Toast，线上无法定位根因。全部改为 `catch (e, st)` 并通过 `ref.read(talkerProvider).error(...)` 记录异常与堆栈（release 下经 `SentryTalkerObserver` 上报 Sentry），界面仍保留用户友好提示。

### 6. 硬编码 `maxWidth: 440` 统一为 design token

### 9. 同步失败详情 `_retryAll` 状态重置

- `lib/features/mine/presentation/widgets/sections/sync_failed_details.dart`
  - `_retryAll` 改为 `try/finally` 结构，无论成功 `pop()`、失败还是抛异常，`_isRetrying` 都会在 `finally` 中重置，避免极端情况下按钮永久 loading。
  - 异常路径仍记录 `talker.error(...)` 与显示通用错误文案。
