# 2026-11-08

## refactor(contract): 布尔字段统一 `is` 前缀，与 Lucent 契约同步

### 问题

Lucent 侧对 12 个布尔列做了 `is` / `has` 前缀标准化，其中 7 个已进 OpenAPI 契约
（`isEmailVerified`、`isNotificationEligible`、4 个通知开关、`isStale`）。
本次导出契约后，Luminous 读取这些字段的位置全部编译失败。

### 落地

生成的客户端（`generated/lucent_api/**`）由 `dart run scripts/contract/bootstrap.dart`
重新生成，未手改。

手写代码按「领域模型也统一」处理，不留翻译层：

- `MedicineRiskCheckRecord.stale` → `isStale`；`MedicineRiskCheckRecords` 上原本
  作为语法糖的 `isStale` getter 更名为 `bestRecordIsStale`（否则与字段同名冲突）。
- `NotificationPreferences` 的 4 个开关补 `is` 前缀，repository 里不再需要
  「契约字段 → 本地字段」的手写映射，`data.isHealthAlertsEnabled` 直接对同名属性。
- `TodaySuggestion.isNotificationEligible` 同步改名，`suggestion_json_codec` 读写
  两侧的键名一起改。
- `PrefKeys.settingsNotificationsSleepReminderEnabled` 的**值**也改为
  `settings.notifications.isSleepReminderEnabled`，与领域模型命名一致。代价是升级后
  本地偏好里旧键读不到，睡眠提醒开关回落到默认值——这是有意的取舍，不做键迁移。
