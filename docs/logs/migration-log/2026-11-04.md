# 2026-11-04

## fix(web): Hive 在 web 上不再走 path_provider，修复鸿蒙壳卡在启动页

### 现象

鸿蒙壳（DevEco 打开 `Luminous/ohos` 后 Run）启动停在 HTML splash（叶子 logo），
永远进不了应用。`hdc shell hilog -x` 里 tag `LuminousWeb` 只有一条
`console: Uncaught `（`main.dart.js`，无 message），此后不再有任何应用日志。

### 根因

`HiveKvStore.open()` 在 `runApp` **之前**调用 `getApplicationDocumentsDirectory()`。
`path_provider` 没有 web 实现，该调用抛 `MissingPluginException`，`main()` 在
`WidgetsFlutterBinding` 已初始化、`runApp` 尚未执行的位置终止——第一帧永远不会画，
而 index.html 的 splash 是引擎在首帧之后才移除的，于是永久停留。

这是 2026-10-28 `shared_preferences` → Hive 迁移带来的回归；2026-10-30 的迁移日志
已把它记为「Web 端因 `path_provider` 在 web 上没有实现而停在启动」，但鸿蒙壳在
2026-10-23 跑通后没有复验，所以又以「壳启动卡死」的形态暴露。同一处修复也让
GitHub Pages 的 Web 版恢复启动。

### 落地

- `lib/core/storage/kv_store.dart`：web（含 ArkWeb 壳）分支 `Hive.openBox(boxName)`
  不传 `path`。hive_ce 的 web 后端用 IndexedDB 存 box，`path` 本来就被忽略；
  `_storagePath()` 仍走 `path_provider`，只由原生平台调用。
- `docs/howto/build-release-artifacts.md` 的 HarmonyOS 排查表补一行：停在 splash 时
  用 `hdc shell hilog -x` 查 `LuminousWeb` 的 `console: Uncaught`，先怀疑 `runApp`
  之前的平台插件调用（`path_provider` 这类没有 web 实现的插件）。

### 验证

- `flutter analyze`：无问题。
- `python scripts/ohos/build_hap.py`：Web 产物校验通过，HAP 构建成功。
- 模拟器（API 26，`127.0.0.1:5555`）`python scripts/ohos/install_hap.py --launch`：
  hilog 出现 `console: Got object store box in database preferences.`（Hive 已走
  IndexedDB），不再有 `Uncaught`；截图确认今日页与五个 tab 正常渲染、中文不是方块。
- 模拟器没有 WebGL（`webGLVersion is -1`），CanvasKit 走 CPU 渲染，首屏偏慢属环境限制。
- 按要求未跑全量测试，验证范围限定为 analyze + 设备实测。

## fix(core): 登录提示条固定单行，登录按钮不再掉到第二行

### 现象

未登录预览时页面顶部的 `SignInHintBanner` 在鸿蒙壳（≈480dp）上渲染成两行：文案一行、
「登录查看」按钮单独占第二行右侧。

### 根因

banner 用 `LayoutBuilder` + `TextPainter` 预判「图标 + 文案 + 按钮放不放得下」，但按钮
宽度取的是外层 `ConstrainedBox` 的 `maxWidth`（160）这个**上限**，而 `FButton` 默认
`mainAxisSize: max` 会真的吃满 160：文案只剩约 60dp，于是被判成放不下、走两行兜底。
即使文案本身一行的自然宽度远小于可用空间，480dp 也会落进这个分支。

### 落地

- `lib/core/widgets/common/feedback/page_state.dart`：`SignInHintBanner` 改成硬性单行
  —— 图标 + `Expanded(Text(maxLines: 1, ellipsis))` + 按钮，删掉按宽度猜布局的
  `LayoutBuilder` / `TextPainter`。空间不足时省略文案，不换行、不顶高 banner。
- 同一处的 `FButton` 加 `mainAxisSize: MainAxisSize.min`，按钮只占内容宽度，把宽度
  还给文案；`ConstrainedBox(maxWidth: 160)` 的上限保留，极端窄屏下标签自己省略。
- `test/core/widgets/sign_in_hint_banner_test.dart` 改为断言「单行」不变量：
  393dp/1.15 与 320dp/1.3 下文案与按钮的纵向区域必须重叠，文案 `maxLines: 1` +
  `TextOverflow.ellipsis`；原先「宽屏并排」用例沿用。

### 验证

- `flutter test test/core/widgets/sign_in_hint_banner_test.dart`：4 个用例通过。
- 宽度实测（测试内临时脚本，未入库）：320–480dp × 1.0/1.15/1.3 字号档下均为单行；
  除 320dp + 1.3 这类极端组合外文案完整，不省略。
- 重建 HAP 装模拟器（API 26）实测：提示条单行、文案完整，五个 tab 与中文渲染正常。

## fix(app): 鸿蒙壳不再绘制桌面常驻滚动条（右侧黑色竖条）

### 现象

手机形态的鸿蒙壳右侧有一条常驻的黑色圆角竖条，占可视高度约 2/3，换页/换滚动区域时位置、
长度跟着变。

### 根因

`lib/app/bootstrap.dart` 的 `_DesktopScrollBehavior` 只按 `defaultTargetPlatform` 判断
是不是桌面。Flutter web 的 OS 探测只读 `navigator.platform` / UA
（`ui_web/browser_detection.dart`）：ArkWeb 的 platform 以 `Linux` 开头、UA 里没有
`Android`，于是被判成 `TargetPlatform.linux`——桌面分支被激活，给每个可滚动区域套上
常驻、10dp 厚、圆角、`colorScheme.outlineVariant` 的 `Scrollbar`。
`lib/app/bootstrap.dart` 是仓内唯一消费 `defaultTargetPlatform` 的地方，所以影响面只有滚动条。

排除浏览器文档滚动条：往 `rawfile/index.html` 临时注入
`html, body { overflow: hidden }` + `::-webkit-scrollbar { display: none }` 后黑条仍在
（说明黑条画在 Flutter 画布内）。

### 落地

- `lib/app/bootstrap.dart`：`_DesktopScrollBehavior` 的判定改为「平台是桌面 **且** 窗口短边
  ≥ `Breakpoints.mobile`(600)」。原生桌面最小窗口 960×640（`window_manager_setup.dart`）
  满足；手机竖屏/横屏短边都在 426dp 上下，不满足。桌面 Web（窗口 ≥ 600）行为不变。
- `test/app/widget_test.dart`：新增两个用例，在同一个 `TargetPlatform.linux` 判定下，
  426×944 不出现 `Scrollbar`、1000×700 出现。用例要求 `debugDefaultTargetPlatformOverride`
  在测试体结束前复位——`addTearDown` 太晚，会撞上框架的 foundation 调试变量断言。
  该文件改用 `package:material_ui` 取 `Scrollbar` 类型：`LuminousApp` 用的是独立
  material 包，`flutter/material.dart` 的同名类型不是同一个类。

### 验证

- `flutter test test/app/widget_test.dart`：5 个用例通过（含新增两例）。
- `flutter analyze`：无问题。
- 重建 Web + HAP 装模拟器（API 26）实测：右侧黑条消失，页面、tab 与滚动正常。

## fix(storage): 偏好库与本地库迁到应用私有目录，修 Linux 桌面启动即退

### 现象

Ubuntu 26 桌面（VMware 虚拟机）上跑 Linux release 包，终端里启动后没有窗口，
直接以未捕获异常退出：

```
[ERROR:flutter/runtime/dart_vm_initializer.cc(40)] Unhandled Exception:
  FileSystemException: lock failed, path = '/home/ubuntu/Documents/kv/preferences.lock'
  (OS Error: 资源暂时不可用, errno = 11)
  #3 HiveImpl._openBox  #5 HiveKvStore.open  #6 main
```

`errno 11` 是 `flock(LOCK_EX | LOCK_NB)` 的 `EAGAIN`：同一个 box 已被另一个进程持有。
换成别的机器全新安装也一样能复现「两次启动必有一次失败」。

### 根因

`HiveKvStore.open()` 与 drift 的 `connection_io.dart` 都用
`getApplicationDocumentsDirectory()` 取存储根。`path_provider_linux` / `_windows`
把它解析成 **XDG 用户目录里的 documents**（`$HOME/Documents`），那是按**用户**共享
的文件夹，不是按**应用**隔离的：两份安装（终端一次 + 启动器一次、或两个版本并存）
打开同一把 Hive 锁，后启动的那份在 `runApp` 之前抛出。同一处也让 `luminous.db`
留在用户的文档目录里，与「缓存文件」的定位不相称。

### 落地

- `lib/core/storage/kv_store.dart`：存储根改为 `getApplicationSupportDirectory()`
  （Linux `~/.local/share/luminous`，Windows `%APPDATA%`，macOS
  `~/Library/Application Support`），与 `features/scan/data/datasources/ocr_model_manager.dart`
  已有的用法一致；注释写明为什么不能用 documents 目录，web 分支（不传 path）不变。
- `lib/core/database/connection_io.dart`：drift 库文件同样落在 application support 根，
  与 KV 库共用一个存储根。本地库是可丢弃缓存（schemaVersion 恒为 1、无迁移链），
  旧位置的 `luminous.db` 不迁移，按全新安装处理。
- `lib/main.dart`：`HiveKvStore.open()` 收敛进 `_openPreferenceStore()`，失败时先写
  `appTalker.error` 与 `stderr` 再 rethrow——release 包没有终端输出，原先是「双击没反应」。
  失败仍然致命（`KvStore.instance` 的设计就是宁可抛错也不让偏好静默回落），重试由
  重启完成：锁在持有进程死亡时由内核释放。
- `test/core/storage/kv_store_test.dart`：新增契约测试，用 `PathProviderPlatform` 假实现
  断言 box 只在 application support 下创建、documents 根不被写入。
- `pubspec.yaml`：`path_provider_platform_interface` / `plugin_platform_interface`
  加入 dev_dependencies（测试直接构造平台接口假实现，与其他 `*_platform_interface`
  的既有做法一致）。
- `docs/howto/build-release-artifacts.md`：补「Linux 桌面（各发行版 / 虚拟机）排查」一节
  ——Hive 锁冲突、Impeller + llvmpipe 首帧慢、光标主题警告、缺运行库，并写明数据目录位置。

### 验证

- `flutter test test/core/storage/kv_store_test.dart`：2 个用例通过。
- `flutter test test/app test/core/storage test/core/database`：全部通过。
- `flutter analyze`：无问题。
- 数据库 schema 未变，未跑 build_runner；未在真机 Ubuntu 上复验（产物需重新出包）。

## fix(settings): 开发者端点可在 release 切换，非法地址不再红屏

### 现象

在「设置 → 高级设置 → 开发者选项 → API 端点」选「自定义」后填
`122.9.102.50:3000`（没有 scheme）并确认，页面整块红屏：

```
ProviderException: Tried to use a provider that is in error state.
FormatException: Scheme not starting with alphabetic character (at character 1)
122.9.102.50:3000
  #3 Uri.parse (dart:core/uri.dart)
  #4 OptionsMixin.baseUrl= (package:dio/src/options.dart:102)
  #6 LucentDioClient._createBaseOptions (.../dio_client.dart:156)
  #8 lucentDioClient (.../client_providers.dart:51)
```

同一条路径在 release 包里的表现是「改了没反应」：`lucentBaseUrlProvider` 固定用编译期
`LUCENT_BASE_URL`，开发者分组被 `kDebugMode` 隐藏，端点打错只能重新打包。

### 根因

两处叠加：

- `Dio` 的 `BaseOptions` 用 `Uri.parse(baseUrl)` 解析地址，`host:port` 没有 scheme 时
  直接抛 `FormatException`。异常发生在 `lucentDioClient` provider 的**构建期**，Riverpod
  把 provider 记成 error 态，所有 watch 它的页面一起红屏——不是一次普通的请求失败。
- 端点只能在 debug 改：`client_providers.dart` 里 `if (kReleaseMode) return
  LucentBaseUrl.value;`，`DeveloperSettingsController.build()` 在 release 强制
  production，`advanced.dart` 的两处开发者分组由 `kDebugMode` 隐藏。

### 落地

- `lib/core/network/client/base_url.dart`：新增 `normalize()`——补 `http://`、裁掉包裹引号
  与尾部斜杠、只接受 http(s) 且 host 非空；`configured` / `productionConfigured` 返回归一化
  值；`value` 在缺 define 时回退 `fallback`（原为 release 直接抛 `StateError`），并留一条
  release 日志。
- `lib/core/network/client/dio_client.dart`：`_createBaseOptions` 最后兜底归一化，非法值
  回退 `LucentBaseUrl.fallback` 且只打日志，构造期不再抛异常。
- `lib/core/network/client/client_providers.dart`：`lucentBaseUrlProvider` 去掉 release
  分支，所有构建模式都读开发者设置；解析值归一化后回退，provider 不会进入 error 态。
- `lib/core/config/developer_settings.dart`：去掉 release 强制 production；`resolvedBaseUrl`
  归一化自定义地址、`local` 复用 `LucentBaseUrl.fallback`；新增 `normalizeApiUrl` 供
  presentation 层校验（settings 不直接 import `core/network`）。
- `lib/features/settings/presentation/pages/advanced/advanced.dart`：开发者分组在 release
  也显示（「恢复默认」里的开发者/feature-flag 重置随之无条件执行）；端点 sheet 确认时校验，
  scheme-less 自动补全，非法值在 sheet 内报 `settingsDevApiEndpointInvalid`、不落盘、不登出。
- l10n：`settingsDevApiEndpointInvalid`（zh/en 分片，经 merge + gen-l10n）。
- 文档：`docs/howto/build-release-artifacts.md` 更新 release 端点语义与排查表；
  `lib/core/network/README.md`、`lib/features/settings/README.md` 补约束。

### 验证

- `flutter analyze`：无问题。
- `flutter test test/core/network/base_url_test.dart test/core/config/developer_settings_test.dart
  test/core/network/client_providers_test.dart`：全部通过（含 scheme-less 归一化、非法值回退、
  `lucentBaseUrlProvider` 不再抛错、Dio 收到的 baseUrl 已补 scheme）。
- `flutter test test/settings/more_subpages_test.dart`：全部通过（含「无 scheme 自动补全后落盘」
  与「非法地址内联报错且不落盘」两个新用例）。
- 未重新出包到模拟器实测（HAP 需要重建后复验）。
