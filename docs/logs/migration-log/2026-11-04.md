# 2026-11-04

## fix(web): Hive 在 web 上不再走 path_provider，修复鸿蒙壳卡在启动页

### 现象

鸿蒙壳（DevEco 打开 `Luminous/ohos` 后 Run）启动停在 HTML splash（叶子 logo），
永远进不了应用。`hdc shell hilog -x` 里 tag `LuminousWeb` 只有一条
`console: Uncaught `（`main.dart.js`，无 message），此后不再有任何应用日志。

### 根因

`HiveKvStore.open()` 在 `runApp` **之前**调用 `getApplicationDocumentsDirectory()`。
`path_provider` 没有 web 实现，该调用抛 `MissingPluginException`，`main()` 在
`WidgetsFlutterBinding` 已初始化、`runApp` 尚未执行的位置终止——第一帧永远不会画，
而 index.html 的 splash 是引擎在首帧之后才移除的，于是永久停留。

这是 2026-10-28 `shared_preferences` → Hive 迁移带来的回归；2026-10-30 的迁移日志
已把它记为「Web 端因 `path_provider` 在 web 上没有实现而停在启动」，但鸿蒙壳在
2026-10-23 跑通后没有复验，所以又以「壳启动卡死」的形态暴露。同一处修复也让
GitHub Pages 的 Web 版恢复启动。

### 落地

- `lib/core/storage/kv_store.dart`：web（含 ArkWeb 壳）分支 `Hive.openBox(boxName)`
  不传 `path`。hive_ce 的 web 后端用 IndexedDB 存 box，`path` 本来就被忽略；
  `_storagePath()` 仍走 `path_provider`，只由原生平台调用。
- `docs/howto/build-release-artifacts.md` 的 HarmonyOS 排查表补一行：停在 splash 时
  用 `hdc shell hilog -x` 查 `LuminousWeb` 的 `console: Uncaught`，先怀疑 `runApp`
  之前的平台插件调用（`path_provider` 这类没有 web 实现的插件）。

### 验证

- `flutter analyze`：无问题。
- `python scripts/ohos/build_hap.py`：Web 产物校验通过，HAP 构建成功。
- 模拟器（API 26，`127.0.0.1:5555`）`python scripts/ohos/install_hap.py --launch`：
  hilog 出现 `console: Got object store box in database preferences.`（Hive 已走
  IndexedDB），不再有 `Uncaught`；截图确认今日页与五个 tab 正常渲染、中文不是方块。
- 模拟器没有 WebGL（`webGLVersion is -1`），CanvasKit 走 CPU 渲染，首屏偏慢属环境限制。
- 按要求未跑全量测试，验证范围限定为 analyze + 设备实测。
