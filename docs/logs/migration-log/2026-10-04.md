# 迁移日志 2026-10-04

## fix(ui): 六项界面缺陷——记录 sheet 按钮溢出、用药 0 药仪表盘、助手空态重叠、Forui 化能力面板与下拉刷新、会话区贴顶

### 背景

真机截图反馈六处界面问题，逐一定位后都落在本仓代码（flow_ui / Forui 均为 pub 依赖，不能改包）：

1. 记录页「自然语言录入」sheet 的「解析候选」按钮右侧溢出（英文 `RIGHT OVERFLOWED BY
   11 PIXELS`）。
2. 用药页在没有药品时用整页 `StateMessageView`（"添加第一种药物"）替换掉整个仪表盘。
3. 助手页空态 greeting 与描述文字互相重叠（`BOTTOM OVERFLOWED BY 63 PIXELS`），键盘弹起
   时更严重（`BOTTOM OVERFLOWED BY 224 PIXELS`）。
4. 能力面板背景是 Material surface、拖动条与 Material 一致。
5. 全仓下拉刷新用的是 Material `RefreshIndicator` 的圆形 spinner。
6. 助手会话页顶栏与首条消息之间有一条页面底色的空白带，会话区没有贴到顶栏。

### 变更

- `features/record/presentation/widgets/dialogs/nlp_sheet.dart`：两个按钮的标签改
  `Flexible(child: Text(..., maxLines: 1, overflow: ellipsis))`。Forui 的 `FButton` 内容
  是 `Row`（`button_content.dart`），Row 给非 flex 子节点无界主轴约束，长标签按固有宽度
  排版并溢出按钮；`Flexible` 让标签随可用宽度收敛。
- `features/medicine/presentation/pages/page.dart`：`emptyInsufficientBuilder` 改为渲染
  `MedicineMobileDashboardView(workspace: <已加载空 workspace>)`——药箱 / 今日用药计划 /
  安全引擎 / 快捷操作各自渲染空态，不再用一个提示页替换全部组件；桌面分支与手机分支共用
  同一个 dashboard（`workspaceAsync.requireValue` 在该状态下必非空）。
- `features/assistant/presentation/widgets/views/empty_conversation.dart`（新增）：助手空态
  视图（欢迎区 + 起始提示 + 记忆提示 + 免责声明），`SingleChildScrollView` +
  `ConstrainedBox(minHeight: 视口)`，装得下时垂直居中、装不下时可滚动。
- `features/assistant/presentation/widgets/sections/page_body.dart`：
  - 不再使用 `FlowChatScreen.empty` 分支（它把 greeting 放在 `Expanded(Center(...))`、把
    suggestions 固定在 composer 上方，内容高于视口时外层 Column 溢出且 `Center` 不裁剪，
    greeting 会画到描述上）；改为 `empty: false` + 把 `AssistantEmptyConversation` 放进
    `thread` 槽位（有界高度），composer 仍由包停靠。
  - 顶部预留 `MediaQuery.removePadding(removeTop: true)`：包的 `FlowChatScreen` 自带
    `SafeArea`，而页面主体已在 `FHeader` 之下，重复消费顶部 inset 就是那条空白带的主因。
  - 页面垂直内边距改为只保留底部，并去掉无错误态时那条前置 `SizedBox`。
- `features/assistant/presentation/widgets/dialogs/capabilities_panel.dart`：移动端由
  Material `showModalBottomSheet` 换成 Forui `showFSheet` + `SheetSurface`
  （`mainAxisMaxRatio: 0.85`），与其余 sheet 同一范式；顺带修掉注释里「全部工具(22 项)」
  与注册表不一致的过期数字。
- `features/settings/presentation/pages/about.dart`：「检查更新」进行中的摘要位由 Material
  `CircularProgressIndicator` 换成 `FCircularProgress`（颜色与 20px 尺寸沿用原值），
  与 Forui 化的下拉刷新口径一致。
- `lib/core/widgets/common/feedback/refresh_indicator.dart`（新增）：`ForuiRefreshIndicator`
  用 Material `RefreshIndicator.noSpinner` 只借手势与 armed 判定（该分支只渲染空
  `Container`，不画 spinner），指示器本体换成 Forui 的 `FCircularProgress`（card 底 +
  neutral 描边 + 圆形），由 `RefreshStatus` 驱动淡入/位移。指示器**只在可见时挂载**：
  `FCircularProgress` 是无限动画，常挂会让页面里所有 `pumpAndSettle` 永远等不到静止
  （首次全量跑挂掉 health_event/today 等一批用例，就是这样暴露的）。
- 8 处 Material `RefreshIndicator` 全部替换为 `ForuiRefreshIndicator`：today 的
  mobile/desktop dashboard、record、review、review legacy、mine、notification、shell
  `DesktopTabShell`。

### 遗留（后端只登记台账，本次不改后端代码）

- 后端两处缺口已登记到 `Lucent/docs/TODO.md`（simple_chat 提示词口径、`get_user_settings`
  读规则缺记忆/设置关键词）；客户端面板口径登记到 `Luminous/docs/TODO.md`。

- 助手「没有可用的记录类工具」是 Lucent 侧的**真实缺口**：`GET /assistant/capabilities`
  报全局工具集（24/24），而对话请求只按关键词路由给模型一个子集；"你在吗" 命中

## build(ios): Podfile.lock 入库，并确认 SwiftPM 关闭后 iOS 发布链路跑通

### 背景

`deploy-ios.yml` 首次运行（`e6846a95`）在链接期失败：CocoaPods 与 SwiftPM 同时提供
`libwebp`，460 duplicate symbols；当天已在 `pubspec.yaml` 项目级关闭 SwiftPM（见
2026-10-03 迁移日志）。本次确认修复生效并把解析结果固化：

- `Deploy iOS` 在 `00ee04b0` 与 `74b8978f` 两次 push 上连续成功（12m28s / 10m24s）；
- 成功日志里 `Adding Swift Package Manager integration` 与 `Xcode is fetching Swift
  Package Manager dependencies` 命中 0 次，`pod install` 从失败那次的 23.6s 变成 113.5s，
  说明依赖全部改走 CocoaPods；
- 产物为 `luminous-ios-unsigned-ipa`（约 27MB）、`luminous-ios-symbols`、
  `luminous-ios-podfile-lock`。

`ios/Podfile.lock` 此前一直没入库（开发机是 Windows，跑不了 `pod install`），CI 每次都会
重新解析 onnxruntime-objc / OpenCV / JPush 的版本。

### 变更

- `ios/Podfile.lock`（新增，入库）：取自 `74b8978f` 那次成功构建的产物。先确认它对该提交
  有效：lock 的 `PODFILE CHECKSUM` 与已提交的 `ios/Podfile` blob（LF）SHA1 完全一致
  （`f2b03fc8…`），且 `74b8978f..HEAD` 没有改动 `pubspec.yaml` / `pubspec.lock` / `ios/` /
  `pkgs/`。锁定 `OpenCV (4.3.0)`、`onnxruntime-objc (1.30.0)`、`JPush (6.2.0)`、
  `JCore (5.5.3)`、`libwebp (1.6.0)`（单一提供方）、`COCOAPODS: 1.17.0`。
- `.github/workflows/deploy-ios.yml`：`Upload Podfile.lock` 的注释改成「已入库，产物用于
  对比版本漂移」；`if: always()` 保留。
- `docs/TODO.md`：删除「`ios/Podfile.lock` 未入库」条目；SwiftPM 迁移条目里的依赖树核对
  改指已入库的锁文件。
- `.github/workflows/README.md`：产物表注明 lock 已入库、pod 版本由它固定。

### 验证结论

- `ios/Podfile.lock` 通过 YAML 解析（49 个 `PODS` 条目、35 个 `SPEC CHECKSUMS`）。
- `PODFILE CHECKSUM` 与 `git cat-file blob HEAD:ios/Podfile` 的 SHA1 一致，所以 CI 的
  `pod install` 会沿用锁定版本而不是重新解析。
- `flutter analyze` 全绿（pre-commit 钩子）。
- `dart run scripts/docs/links.dart`、`scripts/docs/verify.dart --verify`、
  `scripts/docs/generate.dart --check` 通过。

### 遗留

- 仍有两个插件不支持 SPM（`flutter_image_compress_common`、`paddle_ocr_native`）：Flutter
  会把这条警告升级为错误，CocoaPods 注册表 2026-12-02 起转只读，迁移方案见 `docs/TODO.md`。
- iOS 产物仍是未签名 IPA；签名分发与 TestFlight 未接入。

## fix(today): 建议动作的未知路由不再落到 Page Not Found

### 背景

真机（vivo X200s，App 语言英文）点 Today 主建议卡的「健康档案信息不完整」主操作后，直接进入
go_router 的 "Page Not Found / GoException: no routes for location: /mine/profile/edit"。
该 location 由服务端下发，客户端路由表里只有 `/profile`；`openRoute` 原样
`context.push(route)`，对不上就渲染错误页。

### 变更

- `features/today/presentation/widgets/shared/view_models.dart`：`openRoute` 先用
  `GoRouter.configuration.findMatch(...).isError` 与客户端路由表对账；对不上时记 error 日志 +
  提示 `todaySuggestionOpenUnavailableToast`，不再导航。合法路由仍走 `context.push`（保留返回栈）。
- l10n 分片 `today_zh.arb` / `today_en.arb` 新增该提示文案（已跑 `arb_tools.dart merge` +
  `flutter gen-l10n`；合并产物与生成代码不入库）。

### 验证结论

- `flutter analyze` 全仓无问题。
- `flutter test test/today` 全绿：既有导航类用例走的是合法路由，行为未变。
- 服务端侧的动作 label / route / 文案语言三个缺口另登记在 `Lucent/docs/TODO.md`。
- 同批真机反馈的布局类溢出（Today 卡标题行、For reference 徽章、未登录提示条、记录页帮助弹窗、
  无药品弹窗、日期选择器头部）与「窄屏 + 大字号 sweep 测试」登记在 `Luminous/docs/TODO.md`。
