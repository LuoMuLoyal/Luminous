# 迁移日志 2026-09-27

## fix(search): 搜索过期响应守卫与键盘提交立即搜

### 背景

实测反馈「输入一个 `a` 就直接搜了,打不完想搜的词」。排查结论分两层:

- 400ms debounce 是既有有意设计(2026-07-19 为消除「每击键即搜」闪烁引入),本身不是缺陷;
  但它只是延迟,挡住的是"还没发出的请求",挡不住"已经飞在路上的请求"。
- 真正的缺陷是 `_doSearch` 缺少请求时序守卫:取消定时器无法召回在途请求,针对废弃前缀
  (如 `a`)的慢响应会在当前查询(如 `aspirin`)的响应之后落地,把 results /
  `selectedResultId` / `detailPreview` 整体覆盖成过期数据;并且废弃前缀会被写进最近搜索。
- 附带一处语义缺失:`onSubmit` 与 `onChange` 共用同一个 `onChanged` 回调,键盘 search 键
  并不产生"立即搜"语义,只是重走一遍同样的 debounce 路径。

### 变更

- `presentation/providers/medicine_search.dart`
  - 新增 `_searchGeneration` 单调计数;`_doSearch` 起始处 `++` 并捕获本轮 generation,
    在**每个 await 之后**(search 响应、detail preview 之后)提交状态前复核 generation,
    不一致则整体丢弃(含失败分支),既不写 state 也不写最近搜索。
  - `updateQuery('')`/空白查询分支递增 generation 并就地复位 `isSearching`:被丢弃的搜索
    会提前 return,不会自己清掉它置起的进行中标志,否则清空输入后进度条会卡住。
  - 新增 `submitQuery()`:先取消挂起的 debounce 再立即 `_doSearch`;空/空白查询直接返回。
  - `switchSource` 同步取消挂起 debounce,避免切源后 debounce 再补发一次。
- `presentation/widgets/sections/input.dart`:新增可选 `onSubmitted`;`onSubmit` 在有
  `onSubmitted` 时走它,否则回退 `onChanged`(保持既有调用方行为)。
- `presentation/widgets/views/content.dart` / `presentation/pages/page.dart`:
  逐层透传 `onQuerySubmitted` → `submitQuery()`(移动端与桌面端两条布局链都接)。

### 验证

- `flutter analyze lib/features/search test/search` 无问题。
- `flutter test test/search` 全绿;新增 8 条:提交立即搜(不等 debounce)、空/空白查询不搜、
  提交取消挂起 debounce 只搜一次、慢的旧响应不得覆盖新结果、旧的失败不得清掉新结果、
  废弃前缀不进最近搜索、清空查询丢弃在途搜索。
- 未改动 debounce 时长与既有 400ms 契约,原有用例全部保持通过。

## fix(medicine): Take/Skip 不再对未设提醒的药品显示

### 背景

实测反馈「药箱里只要有药就显示 Take/Skip,应该是设了提醒才有」。排查确认属实:

- `lucent_workspace.dart` 的 `planItems` 遍历**全部** current 药品生成,不是遍历提醒;
  无提醒药的 `slots` 为空,`fallbackStatus` 为 null(当天无 dose log),
  经 `_medicineStatusFromDoseLog(null)` 落成 `MedicineDoseStatus.pending`。
- 打卡按钮门控当时只有 `canMark = onMarkDose != null && takenRequest != null &&
  skippedRequest != null`,而 `buildMedicineDoseMarkRequest` 对无槽位药只要求
  `item.todayStatus == pending` —— 于是每味未排程的药都渲染出 Take/Skip。
- 根因是把「压根没配提醒」与「配了提醒但今天还没打卡」混成了同一个 pending 状态。
  第 131 行那个 `slots.isEmpty` 回退分支是有意为之(供药箱条展示「未设置时间」),
  因此不能改 `todayStatus` 语义,只能在渲染门控上收口。

### 变更

- `presentation/widgets/sections/mobile_records.dart`:`_TodayPlanRow` 新增
  `hasScheduledSlots = item.slots.isNotEmpty`,按钮渲染条件由 `canMark` 改为
  `showDoseActions = canMark && hasScheduledSlots`,并附注为何不能只靠
  `buildMedicineDoseMarkRequest`。`hasReminder`(长按菜单)与空态逻辑不变。
- 未改 `todayStatus` 派生——`_nextDoseFor` 的「无槽位药显示未设置时间」回退
  (`mobile_shared.dart`)与「无待服用剂次」空态均按原样工作。

### 验证

- `flutter analyze lib/features/medicine test/medicine` 无问题。
- `flutter test test/medicine` 全绿;新增 2 条 widget 断言:无提醒药隐藏
  `medicine-plan-dose-action-{taken,skipped}` 但仍在药箱/今日计划中列出;
  有 pending 槽位(已设提醒)的药两个按钮仍显示。
- 反向验证:临时把门控退回 `canMark` 后「无提醒隐藏」用例如期失败,恢复后通过,
  确认该断言真的能捕获此缺陷。

## chore(lint): no_bang_on_response_data 清零

### 背景

观察期收敛第二项。该规则在 `lib/**/data/**` 内扫描**所有** `!` 后缀表达式
(不只是 `response.data!`),共 38 处。规则意图:data 层是系统边界,坏 payload 必须
降级为 domain failure,不能崩成 `TypeError`。

38 处按形态分四类,逐类按"能否在同一表达式内自证非空"处理,不改变原有语义:

1. **`x == null ? null : f(x!)`**(9 处):把 `x` 绑到局部变量后再判空调用,
   消除 `!`。
2. **`_lastXxx != null && ... _lastXxx!`**(5 处):节流判断,同样绑局部变量。
3. **集合元素守卫 `if (x != null) 'k': x!.f()`**(2 处):绑局部变量后守卫直接读它。
4. **其余散点**(22 处):`where`+`map(...!)`、`response.data!`、聚合器私有字段等,
   分别改为单次遍历收敛、先取局部再判空、局部变量替代字段读取。

### 变更

涉及 21 个文件(health_data / health_context / health_event / review / record /
medicine / today / scan / auth 的 data 层)。代表性改动:

- `health_data/data/mappers/health_record_mapping.dart`(8 处):`fieldsForMetric`
  提取 `startAt`/`endAt` 局部变量;`SleepAggregator.add`/`merge` 用局部变量替代
  `_start!`/`_end!`(`overlaps` 本就是该写法,现在全类一致)。
- `scan/data/repositories/scan.dart`:`response.data!` 改为先取 `final data` 再判空
  ——空响应仍抛原来的 `LucentFailure.network(emptyResponse)`,错误路径不变。
- `record/data/providers/record_access.dart`:重放 handler 里 `entry.entityId!`
  改为入口处统一判空并 `return`;队列条目 entityId 缺失属本地状态损坏,跳过单条
  而不是抛 `TypeError` 中断整批重放。
- `today/data/repositories/lucent.dart`:`where(...).map((r) => r.currentMedicineId!)`
  改为单次 `for` 遍历同时过滤与收敛,避免先筛后断言。
- `review/data/datasources/dashboard_remote.dart`:`query.startDate!` 补上 `!= null`
  判断(原先只判 `isCustom`,自定义区间缺端点时会崩)。

### 验证

- `flutter analyze` 无问题。
- 九个受影响 feature 的测试全绿(health_data / health_context / health_event /
  review / record / today / scan / auth / medicine)。
- `luminous_lints` 复扫:`no_bang_on_response_data` 38 → **0**,总数 249 → 211。
- 其余四条规则计数不变。

## chore(lint): no_raw_datetime_parse 清零并排除生成文件

### 背景

观察期收敛第三项,过程中发现一个规则设计缺陷而非代码缺陷。

`no_raw_datetime_parse` 共 7 处,其中 **6 处在
`lib/features/auth/domain/entities/session.g.dart`** —— 而该文件是
.gitignore(`**/*.g.dart`) 覆盖、由 build_runner 重建的生成产物,git 未跟踪。
这些 `DateTime.parse` 由 json_serializable 从 `session.dart` 的普通 `DateTime`
字段自动发出,既不接受手改(违反"不得手改生成文件"口径、下次构建即丢),也会
随生成器版本漂移。

根因在 CLI 驱动:`bin/luminous_lints.dart` 只按 `analyzedFiles()` 取文件、仅过滤
`.dart` 后缀,**没有任何生成文件排除**,因此把本地构建产物一并纳入了统计。
观察基线里这部分数字本质上不可收敛。

### 变更

- `tool/luminous_lints/bin/luminous_lints.dart`:新增 `_isGeneratedSource()`,
  扫描时跳过 `*.g.dart` / `*.freezed.dart`,并附注原因(生成文件不可手改,报在
  其上无法消除且随生成器漂移)。扫描文件数 823 → 707。
- `today/presentation/widgets/views/health_event_section.dart`:唯一手写处的
  `DateTime.parse(localDateKey(...))` 改为 `parseDateTimeOrNull(...) ?? DateTime.now()`,
  补 `core/utils/date_format.dart` import。
- `AGENTS.md`:七规则清单处补充"扫描范围排除生成文件"的口径说明。

### 验证

- `flutter analyze lib/features/today` 无问题;`flutter test test/today` 全绿。
- `cd tool/luminous_lints && dart test`:36 项全绿(改动了 CLI 驱动)。
- 复扫:`no_raw_datetime_parse` 7 → **0**,总数 211 → 204;生成文件 findings 归零。
- 退出码契约未变:观察模式 exit 0,`--fatal` 有 findings 时 exit 1(均实测)。
