# 迁移日志 2026-09-27

## fix(search): 搜索过期响应守卫与键盘提交立即搜

### 背景

实测反馈「输入一个 `a` 就直接搜了,打不完想搜的词」。排查结论分两层:

- 400ms debounce 是既有有意设计(2026-07-19 为消除「每击键即搜」闪烁引入),本身不是缺陷;
  但它只是延迟,挡住的是"还没发出的请求",挡不住"已经飞在路上的请求"。
- 真正的缺陷是 `_doSearch` 缺少请求时序守卫:取消定时器无法召回在途请求,针对废弃前缀
  (如 `a`)的慢响应会在当前查询(如 `aspirin`)的响应之后落地,把 results /
  `selectedResultId` / `detailPreview` 整体覆盖成过期数据;并且废弃前缀会被写进最近搜索。
- 附带一处语义缺失:`onSubmit` 与 `onChange` 共用同一个 `onChanged` 回调,键盘 search 键
  并不产生"立即搜"语义,只是重走一遍同样的 debounce 路径。

### 变更

- `presentation/providers/medicine_search.dart`
  - 新增 `_searchGeneration` 单调计数;`_doSearch` 起始处 `++` 并捕获本轮 generation,
    在**每个 await 之后**(search 响应、detail preview 之后)提交状态前复核 generation,
    不一致则整体丢弃(含失败分支),既不写 state 也不写最近搜索。
  - `updateQuery('')`/空白查询分支递增 generation 并就地复位 `isSearching`:被丢弃的搜索
    会提前 return,不会自己清掉它置起的进行中标志,否则清空输入后进度条会卡住。
  - 新增 `submitQuery()`:先取消挂起的 debounce 再立即 `_doSearch`;空/空白查询直接返回。
  - `switchSource` 同步取消挂起 debounce,避免切源后 debounce 再补发一次。
- `presentation/widgets/sections/input.dart`:新增可选 `onSubmitted`;`onSubmit` 在有
  `onSubmitted` 时走它,否则回退 `onChanged`(保持既有调用方行为)。
- `presentation/widgets/views/content.dart` / `presentation/pages/page.dart`:
  逐层透传 `onQuerySubmitted` → `submitQuery()`(移动端与桌面端两条布局链都接)。

### 验证

- `flutter analyze lib/features/search test/search` 无问题。
- `flutter test test/search` 全绿;新增 8 条:提交立即搜(不等 debounce)、空/空白查询不搜、
  提交取消挂起 debounce 只搜一次、慢的旧响应不得覆盖新结果、旧的失败不得清掉新结果、
  废弃前缀不进最近搜索、清空查询丢弃在途搜索。
- 未改动 debounce 时长与既有 400ms 契约,原有用例全部保持通过。

## fix(medicine): Take/Skip 不再对未设提醒的药品显示

### 背景

实测反馈「药箱里只要有药就显示 Take/Skip,应该是设了提醒才有」。排查确认属实:

- `lucent_workspace.dart` 的 `planItems` 遍历**全部** current 药品生成,不是遍历提醒;
  无提醒药的 `slots` 为空,`fallbackStatus` 为 null(当天无 dose log),
  经 `_medicineStatusFromDoseLog(null)` 落成 `MedicineDoseStatus.pending`。
- 打卡按钮门控当时只有 `canMark = onMarkDose != null && takenRequest != null &&
  skippedRequest != null`,而 `buildMedicineDoseMarkRequest` 对无槽位药只要求
  `item.todayStatus == pending` —— 于是每味未排程的药都渲染出 Take/Skip。
- 根因是把「压根没配提醒」与「配了提醒但今天还没打卡」混成了同一个 pending 状态。
  第 131 行那个 `slots.isEmpty` 回退分支是有意为之(供药箱条展示「未设置时间」),
  因此不能改 `todayStatus` 语义,只能在渲染门控上收口。

### 变更

- `presentation/widgets/sections/mobile_records.dart`:`_TodayPlanRow` 新增
  `hasScheduledSlots = item.slots.isNotEmpty`,按钮渲染条件由 `canMark` 改为
  `showDoseActions = canMark && hasScheduledSlots`,并附注为何不能只靠
  `buildMedicineDoseMarkRequest`。`hasReminder`(长按菜单)与空态逻辑不变。
- 未改 `todayStatus` 派生——`_nextDoseFor` 的「无槽位药显示未设置时间」回退
  (`mobile_shared.dart`)与「无待服用剂次」空态均按原样工作。

### 验证

- `flutter analyze lib/features/medicine test/medicine` 无问题。
- `flutter test test/medicine` 全绿;新增 2 条 widget 断言:无提醒药隐藏
  `medicine-plan-dose-action-{taken,skipped}` 但仍在药箱/今日计划中列出;
  有 pending 槽位(已设提醒)的药两个按钮仍显示。
- 反向验证:临时把门控退回 `canMark` 后「无提醒隐藏」用例如期失败,恢复后通过,
  确认该断言真的能捕获此缺陷。
