## fix(assistant): 首次无会话时误报加载失败——`/latest` 的 `null` 载荷被当成空响应

现象：账号还没有任何会话时首次进入 AI 对话，页面顶部出现
「AI 对话暂时没有加载出来」告警卡，描述为 `Empty response body (getLatestConversation)`。

链路：`GET /api/v1/user/assistant/latest` 在无会话时按契约返回 **200 + `null`**
（本地探针确认：`content-type: application/json`、`content-length: 4`、body `"null"`）；
`AssistantRemoteDataSource.getLatestConversation()` 用 `_requireData()` 包住 `response.data`，
而 `_requireData()` 的语义是「成功响应体缺失 → network/emptyResponse」，于是合法的
「暂无会话」状态必然被判成失败。仓储层本来就写了 `if (dto == null) return null;`
（`AssistantConversation?` 契约），只是数据源没让 `null` 通过。

修复：`getLatestConversation()` 直接返回 `response.data`，`null` 原样上抛；其余仍要求
非空载荷的端点保持 `_requireData()` 不变。

测试：`test/assistant/remote_data_source_test.dart` 新增
「getLatestConversation returns null when no conversation exists」（200 + `null` 载荷 → `null`，
而非 failure），与既有的 `getCapabilities` 空响应用例并存。

## fix(network): SSE 请求被 Web XHR 的 10s 总超时掐断

现象：Web 端助手回答耗时较长时以「这次回复没有完成 / 连接中断了」结束。

原因：dio 的 Web 适配器只有一个超时旋钮——`xhr.timeout = connectTimeout + receiveTimeout`
（`dio_web_adapter` `adapter_impl.dart`）。`LucentSseClient._postAndDecode` 只把
`receiveTimeout` 置 0（意图「不限超时」），`connectTimeout` 仍继承 `BaseOptions` 的 10s，
在 Web 上退化为「整条流 10s 总期限」：超过 10s 的回答被 `xhr.abort()` →
`receiveTimeout`/`connectionError`，`classifySendError` 判为 `streamInterrupted`。

修复：SSE 请求同时把 `connectTimeout` 置 `Duration.zero`（dio 中 0 即不设超时；IO 适配器
`> Duration.zero` 才生效，故原生端一并取消 SSE 的连接超时），并在注释里记录 Web 适配器
会把两个超时相加这一约束。

测试：`test/core/network/sse_test.dart` 新增
「leaves the SSE request without a connection or receive deadline」——断言请求实际下发时
connect/receive 均为 0（修复前前者继承 10s，用例失败）。

验证：`flutter analyze` 零 issue；`flutter test test/assistant test/core/network` 全绿。

遗留：Web 端 `ResponseType.stream` 目前不真正流式（dio Web 适配器用 XHR + arraybuffer，
整流 body 到齐才交给解析器），回答在 Web 上是「一次性出现」；恢复 Web 逐字流式需要
fetch + ReadableStream 适配器或 EventSource 方案，已登记 `docs/TODO.md`。

## style(settings): 帮助与反馈 FAQ 对齐 Forui 官方 accordion 样式

### 问题

`/settings/help` 的「常见问题」列表与官方 Accordion 示例（forui.dev `FAccordion` 默认外观）不一致：
问题标题被提升为 `body.md`（touch 下 18px）+ w600，字号与字重都高于官方默认的
`display.sm`（16px）+ w500，整段列表因此比页面标题、也比同页下方 `FTileGroup` 的条目标题
（`body.sm`、常规字重）更重，页面内层级互相打架。

### 修改

`lib/features/settings/presentation/pages/help.dart`：

- `_FaqAccordion` 移除 `FAccordionStyleDelta.delta(titleTextStyle: ...)` 覆盖，直接使用主题默认

  标题因此回到 `display.sm` / w500 / foreground（touch 16px），并恢复官方默认的 hover 下划线变体。
- 展开内容去掉额外叠加的 `Padding(bottom: Spacing.level3)`：答案与分隔线的间距交回 accordion 自身的
  `childPadding`（官方节奏：标题上下 16、答案距分隔线 16），消除上紧下松的不对称。
- 答案仍走 `MarkdownBody` + `MarkdownStyle.legal`（FAQ 是 Markdown 资产；`p` 为 `body.sm`、行高 1.7，
  字号与颜色与官方 `childTextStyle` 相同，只把行距按中文长段落放宽）。
- 更新类文档注释，记录「使用官方默认样式」这一决策与理由。

### 验证

- `test/settings/help_settings_page_test.dart` 在原「renders FAQ items」用例内追加断言：`FAccordion.style`
  等于 `FAccordionStyleDelta.context()`（无覆盖），问题标题解析后的字号等于 `theme.typography.display.sm.fontSize`、
  字重 w500。按旧实现该断言必然失败（18px / w600）。
- `flutter analyze` 零 issue；`flutter test test/settings` 通过。
- 说明：该测试文件有已知的 fake-async 时序限制（FAQ 资产 + shimmer 骨架屏，顺序运行时 `pumpAndSettle`
  会挂起），故新断言合并进已能稳定 settle 的首个用例，而非新增独立用例。

## fix(today): 区块间距对齐其他页面 + 空区块槽位不再留下幽灵间距

### 问题

今日页移动端「优先处理」卡片下方与「今日摘要」标题之间的空隙明显大于其他区块之间：
截图取像素带实测该处为 40 逻辑像素，而「今日摘要」卡片→「健康观察」、
健康观察卡片→「留意事项」两处都是 20。

### 原因

`MobileTodayDashboard` 给每个槽位无条件套 `Padding(bottom: Spacing.level5 = 20)`，
而「稍后处理」区块在 bundle 没有 secondary 卡片时渲染 `SizedBox.shrink()` —— 空区块
自身高度为 0，外层的间距却照旧占位，于是相邻两区块之间变成 2×区块间距。
预览态（未登录）下 `HealthEventSection` 同样返回 `SizedBox.shrink()`，留下同类幽灵间距。

用一次性 widget 探针量取几何确认：修复前后「今日摘要」标题 top 由 366 → 346，
「优先处理」卡片底边始终是 326，即该处间距 40 → 20；其余三处间距不变。

### 修改

- `mobile_dashboard.dart`：由 `StatelessWidget` 改为 `ConsumerWidget`，「稍后处理」槽位
  按 `TodaySecondarySuggestionsSection.hasCards` 判定是否纳入——不纳入时是
  `SizedBox.shrink()`，与既有的 banner 槽位「隐藏分支不占位」写法一致；
  「健康观察」槽位在 `isPreview` 时同样不纳入。
- `suggestion.dart`：抽出 `hasCards(bundle)` 静态判定，布局与区块共用同一条件，
  避免两处条件漂移。
- 区块间距由 `Spacing.level5`（20）改为 `Spacing.level4`（14），与同为 tab 级内容流的
  记录页（`dashboard_view.dart` 全部 `SizedBox(height: Spacing.level4)`）和回顾页
  （`review_view.dart` 区块统一 `Padding(bottom: Spacing.level4)`）一致；
  设置页 `label + card` 区块用的 level5 保留在设置页自身，不在本次范围。
- 桌面布局有意不改：`DesktopTodayDashboard` 用显式 `SizedBox(level6)` 分隔区块，
  区块自身不带下间距，因此不受本次改动影响。

### 验证

- `test/today/page_test.dart` 追加两条几何断言：空「稍后处理」槽位时「优先处理」卡片底
  到「今日摘要」标题的距离 == `Spacing.level4`；预览态下「今日摘要」卡片底到
  「留意事项」标题的距离 == `Spacing.level4`。
- 负向对照：把槽位改回无条件 `Padding` 后第一条断言失败（间距翻倍），确认用例守得住此回归。
- `flutter analyze` 零 issue；`flutter test test/today` 通过。

## refactor(design): 标题与内容的间距统一走 Forui 原语 `context.titleContentGap`

### 变更

- 新增 `TitleContentGapTokens`（`lib/core/design/tokens/spacing.dart`）：
  `context.titleContentGap` = `context.theme.style.borderRadius.lg.topLeft.x`（Forui 圆角 token = 14，
  与本层 `Spacing.lg` / `level4` 同值）。取法与圆角、字体一致——值从 Forui 主题经 context 取，
  不在 widget 内联 `Spacing.level*` 常量或裸数值。
- 全应用「区块标题/分组标签 → 其直接统领的内容」的间距统一到该值，覆盖 24 个文件 43 处：
  - 共享骨架：`TodaySection`（今日页所有区块）、`ReviewSectionCard`（回顾四段）、
    药盒提醒表单 `_SectionTitle` 的底部间距。

    notification / page / theme / about_section / general_section / privacy_section /
