## feat(architecture): 严格 Clean 分层门禁上线（C0）

- 新增 `tool/luminous_lints/lib/src/clean_layers.dart`：把原 `layered_import`
  的三条子规则（带 presentation providers / shell / core-auth / core-push 四处豁免）
  替换为六条独立规则，**无白名单**：
  `domain_purity`（R1/R2）、`application_layer`（R3）、`data_layer`（R4）、
  `presentation_layer`（R5）、`cross_feature_import`（R6）、
  `core_not_import_features`（R7）。六条规则共用同一个纯谓词 `checkImportPath`，
  CLI 驱动与单测因此跑的是同一条实现。
- 新增 `directory_shape.dart` + `directory_scan.dart`：`directory_file_cap`（R8，
  目录直接源文件 ≤ 8，排除 `*.g.dart` / `*.freezed.dart`）与 `forbidden_directory`
  （R9，`presentation/services/`、`data/providers/`、`presentation/flows/`）。
- CLI 增加 `--clean-layers` 门禁模式：只跑 R1–R9，任一违规 exit 1。
  `--fatal` 让全量规则阻断；默认仍是观察模式。
- 接入 `.githooks` pre-push（经 `scripts/hooks/git.dart`）与
  `scripts/workflows/daily.dart`，两处均不带 `continue-on-error`，是真门禁；
  `.github/workflows/ci.yml` 新增同名步骤但 `continue-on-error: true`，
  架构清理期间只暴露违规数、不阻断 PR 合并。
- 旧 `layered_import` 规则保留在规则包中（其单测仍跑），但从 CLI 驱动摘除：
  它承载的豁免与「无白名单」口径冲突。
- 规划：`plans/2026-10-21-ddd-refactor-frontend.md` 重写为严格 Clean + DDD-lite；
  `plans/2026-10-28-composable-tabs.md` 补充「原生组件化」立场（§0.5）。

### 解耦手法（本批通用）

1. **仓储 → 端口接口**：use case 只声明自己需要的动词（`DailyRecordWriter`、
   `SleepQuickEntryRepository`、`DoseLogMarkWriter`），`TaskEither` 在 provider 适配器
   处折成异常，use case 不依赖 `core/errors`。
2. **UI 副作用回迁**：Auth 弹窗、sheet、Toast、路由、撤销 toast 全部留在 presentation；
   use case 只返回 `sealed` 结果（`ChangeRecordDateOutcome`、`DeleteRecordOutcome`、
   `SleepQuickEntryOutcome`、`QuickEntryUndoHint`）。
3. **撤销命令随结果返回**：原先 use case 往调用方的可变变量里塞 `QuickEntryUndoAction`，
   现在放进结果对象（`QuickEntryUndoOffer`），流自身无 UI 状态。
4. **跨 feature**：record 的 domain 服务被 today 消费；today 的 skip_dose 用本地
   `DoseLogMarkWriter` 接口而不是 import medicine 的仓储接口（application 只允许看同
   feature 的 `domain/`）。
5. **纯格式化下沉**：`formatRecordDate` / `formatHourMinute` 等无业务规则的函数复制到
   `domain/services/hour_minute.dart`，presentation 仍走原 `date_time_formatters`。
