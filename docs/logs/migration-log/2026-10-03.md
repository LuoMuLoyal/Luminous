# 迁移日志 2026-10-03

## fix(today): 主建议卡头部与次级操作区排版修正

### 背景

今日页主建议卡（`suggestion_primary_card.dart`）在三处排版上偏离设计意图：

1. 头部左上角有多余的 glyph 图标块（`TodayGlyphTile`），挤占标题横向空间；
2. 标题位于图标块下方，被视作独立一行，导致标题与右侧主操作按钮不在同一行；
3. 「次级操作」（`secondaryActions`）与「查看依据」（`EvidenceToggleButton`）分属两个
   独立区块，各占一行，垂直空间被浪费。

此外 e2e 截图 fixture 与后端契约不符，放大了上述问题：`cardTone` 用了 `warning`
（后端 `COMPLIANCE` 为 `urgent`），`feedbackOptions` 缺 `suppress`，且次级操作标签
误用 `稍后提醒`（`actionId: 'later'`）——与反馈行中同样本地化为「稍后提醒」的
`later` 反馈重复，页面因此出现两处「稍后提醒」。

### 变更

- `presentation/widgets/sections/suggestion_primary_card.dart`
  - 删除头部 `TodayGlyphTile` 图标块及其下 `SizedBox`；标题改用 `Expanded` 与主操作
    按钮合并进同一 `Row`（`crossAxisAlignment: center`），标题独占弹性空间、按钮
    `mainAxisSize.min` 靠右。
  - 次级操作与「查看依据」合并为**单个左对齐 `Wrap`**（`spacing`/`runSpacing` 用
    `Spacing.sm`，`WrapCrossAlignment.center`）。选择 `Wrap` 而非左右两端对齐，是为了
    在无次级操作时自然退化为仅「查看依据」，窄屏时靠 `runSpacing` 换行而不溢出。
  - 移除随之变为孤儿的 `shared/components.dart`、`shared/suggestion_icon_mapping.dart`
    导入（`TodayGlyphTile` 仍由次级建议卡 `suggestion.dart` 使用）。
- `presentation/widgets/sections/suggestion_state_views.dart`
  - `SuggestionSkeleton` 头部镜像新卡结构：标题条 + 右侧胶囊按钮占位同处一行，其后
    两行原因占位，再是次级操作胶囊与「查看依据」长条占位（去掉原图标方块）。
- `integration_test/support/screenshot_fixtures.dart`
  - `cardTone` 改为 `urgent`；`primaryAction` 明确为 `go_confirm`（去确认）；
    `secondaryActions` 改为后端真实产出的 `skip_dose`（跳过此次）并带上跳转 query；
    `feedbackOptions` 补 `suppress`。

  glyph 图标、次级操作与「查看依据」同行且左→右排列、无次级操作时「查看依据」仍在）。

## ci(ios): 补齐 iOS 工程能力缺口，并把门禁与发布拆成独立 workflow

### 背景

iOS 端自 6 月接入微信 SDK、7 月换 PaddleOCR、8 月接 JPush 之后未再系统核对，而开发机是
Windows，本地无法编译 iOS，也一直没有 CI 覆盖面。静态核对发现四类问题：

1. 部署目标不一致：`ios/Podfile` 与 `paddle_ocr_native.podspec` 都要求 iOS 16.0，而
   `project.pbxproj` 的主 target 仍是 15.0；
2. `health` 插件读 HealthKit、`sign_in_with_apple` 做 Apple 登录，但
   `Runner.entitlements` 只有 `aps-environment`，这两个能力都缺 entitlement；
3. JPush 的远程通知缺 `UIBackgroundModes`；
4. `ci.yml` 的 `build-apk` 缺 `Build generated API client` 步骤：`generated/lucent_api`
   是独立 package，根 `build_runner` 不替它生成被 gitignore 的 `*.g.dart` model part
   文件，因此 main 上这个 job 一直失败（2026-10-02 的运行记录里 Flutter CI 绿、
   Build APK (release) 红）。

此外 `ci.yml` 既跑门禁又出产物：产物失败会把 PR 门禁一起染红，触发条件也只能取并集。

### 变更

iOS 工程：

- `ios/Runner.xcodeproj/project.pbxproj`：`IPHONEOS_DEPLOYMENT_TARGET` 15.0 → 16.0
  （Profile/Debug/Release 三处），与 Podfile 及 `paddle_ocr_native` 的 16.0 对齐；
  Runner 的 `TargetAttributes` 补 `SystemCapabilities`（HealthKit / Push /
  SignInWithApple），与 entitlements 保持一致。
- `ios/Runner/Runner.entitlements`：补 `com.apple.developer.healthkit` 与
  `com.apple.developer.applesignin`（`Default`）。这两项缺失时真机上的授权请求会失败；
  `aps-environment` 继续由 `$(APS_ENVIRONMENT)` 按 Debug/Profile=development、
  Release=production 注入。
- `ios/Runner/Info.plist`：补 `UIBackgroundModes: [remote-notification]`（JPush 后台
  推送），补 `ITSAppUsesNonExemptEncryption=false`（HTTPS-only，免去每次上架回答出口
  合规问题）。

workflow 按门禁 / 发布拆分，发布按平台各占一个文件：

- `ci.yml` 收敛为纯门禁：ARB 合并、生成物准备、生成客户端、生成文档一致性、analyze、
  全量单测；移除 `build-apk` 与 `build-ios`，触发保持 push / PR / 手动。
- `deploy-android.yml`（新，`Deploy Android`，`push main` 或手动触发）：release APK 构建；

## fix(ios): 关闭 SwiftPM 集成，修复首次 iOS 构建的 libwebp 重复符号

### 背景

`deploy-ios.yml` 的首次运行（push main）走到了链接阶段才失败：

- Flutter 3.47 默认启用 Swift Package Manager，日志出现
  `Adding Swift Package Manager integration...`，拉 SPM 依赖用了 62.8s；
- 其中两个插件不支持 SPM（`flutter_image_compress_common`、`paddle_ocr_native`），
  它们的依赖仍留在 CocoaPods；
- 结果 Xcode 链接期报 `460 duplicate symbols` 与 `Linker command failed with exit code 1`，
  Flutter 的提示指向 CocoaPods 与 SwiftPM 同时提供了 `libwebp`。

前一批提交只覆盖静态配置核对与工作流拆分，iOS 能否编译尚未被真实执行过；这次运行是第一
次实机构建，暴露的是依赖管理方式混用。

### 变更

- `pubspec.yaml`：在 `flutter` 段增加

  ```yaml
  config:
    enable-swift-package-manager: false
  ```

  这是 Flutter 官方的**项目级**关闭方式（`docs.flutter.dev` → Swift Package Manager for
  app developers → How to turn off Swift Package Manager → Turn off SwiftPM for a single
  project），对仓库所有贡献者生效，比只在 CI 里跑 `flutter config` 可靠。关闭后 iOS 依赖
  统一走 CocoaPods，与既有的 `ios/Podfile`（`use_frameworks! :linkage => :static`、
  `flutter_install_all_ios_pods`）一致。
- `docs/TODO.md`：登记 SwiftPM 迁移遗留——两个插件缺 `Package.swift`、CocoaPods 注册表
  2026-12-02 起转只读、`paddle_ocr_native` 是本仓 vendored fork 可自主补 `Package.swift`。

没有改 `deploy-ios.yml`：项目级开关已经覆盖 CI，不需要在 workflow 里再关一次。

## fix(network): 真机调试不再用开发者端点覆盖编译期 LUCENT_BASE_URL

### 背景

真机（Android，debug 包 `com.dev.luminous`）注册页点「发送验证码」稳定失败，
Talker 记录 `RegisterFormNotifier.sendCode: failed: ... networkErrorCode:
NetworkErrorCode.connectionTimeout`，间隔十余秒可重复复现。`.env` 里的
`LUCENT_BASE_URL` 已改成线上地址，现象不变。

排查结论是 debug 构建的 base URL 解析顺序问题，与网络环境无关：

- `lucentBaseUrlProvider` 在非 release 下**优先**取开发者设置
  （`DeveloperSettingsState.resolvedBaseUrl`），只有拿不到该状态时才回退到
  `LucentBaseUrl.value`（编译期 define）；
- 开发者设置的默认值是 `ApiEndpoint.local`，而该 preset 在 Android 上硬编码
  `http://10.0.2.2:3000`——那是**模拟器**访问宿主 loopback 的专用别名；
- 真机既没有 `10.0.2.2` 的路由，也不会收到任何 RST，于是表现为 TCP 连接超时
  （`connectionTimeout`）而不是 `connection refused`，与日志一致。

用临时探针在 `TargetPlatform.android` + define `http://122.9.146.162:3000` 下复现：
`devSettings.apiEndpoint=local`、`resolvedBaseUrl=http://10.0.2.2:3000`、
`lucentDioClient.dio.options.baseUrl=http://10.0.2.2:3000`——即 `.env` 被完全忽略。

### 变更

- `lib/core/network/client/base_url.dart`：新增 `LucentBaseUrl.configured`，
  返回显式配置的 URL 或 `null`。`value` 在 debug 下永远返回非空回退值，无法区分
  「构建期钉了地址」与「没人配置」，开发者设置的默认值判断需要这个区分。
- `lib/core/config/developer_settings.dart`：`build()` 在**没有任何已存偏好**时，
  若 `LucentBaseUrl.configured` 非空则默认落到 `ApiEndpoint.custom` + 该 URL；
  否则维持 `ApiEndpoint.local`。已存偏好仍然优先，`reset()` 恢复同一默认。
  这样钉了 define 的真机构建直接可用，模拟器不传 define 时行为不变，
  运行期切换端点的能力也保留。

### 验证结论

- 探针复验（Android + define）：`apiEndpoint=custom`、
  `resolvedBaseUrl` 与 `dio.options.baseUrl` 均为 define 的地址；
  不传 define 时仍是 `http://10.0.2.2:3000`（模拟器回退未受影响）。
- `test/core/config/developer_settings_test.dart` 增补「无偏好时采用 define」
  与「已存偏好覆盖 define」两条；`reset` 用例同步覆盖新默认。
  `test/core/network/base_url_test.dart` 覆盖 `configured` 的空值/空白/取值。
- `flutter analyze` 全绿；`test/core` 全量通过。
- 探针文件为临时验证用，已删除，未进入变更集。

### 遗留

- 华为云 `122.9.146.162` 的 `3000` 端口按安全组 `/32` 放行（仅监控与运维 IP），
  `80`/`443` 不监听：真机若不在放行网段（例如走蜂窝数据、换 Wi-Fi），
  即使 base URL 正确也仍会连接超时，需要补安全组规则或改用 443 上的域名。
- `ApiEndpoint.staging` / `production` 两个 preset 的 `defaultUrl` 仍是
  `http://127.0.0.1:3000` 占位值，debug 包选「生产」等于指向手机自身；
  需要真实域名后另行接线，未在本次改动内虚构地址。
- `LUCENT_BASE_URL` 之类的 `--dart-define-from-file=.env` 是**编译期**输入，
  改完后必须重新 `flutter run`（hot restart 不会重读 define）。
