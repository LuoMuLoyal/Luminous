## fix(health_data): Web 端 Platform 桩抛错导致设置页 Provider 崩溃

设置页（隐私区「健康数据自动同步」tile）在 Flutter Web 上构建时
`healthAutoSyncAvailabilityProvider` 抛
`Unsupported operation: Platform._operatingSystem`（Riverpod error state，
表现为设置页该区域 ProviderException）。根因：
`HealthPlatformDataSource.isPlatformAvailable` 与
`HealthSyncRepositoryImpl._sourceTag` 直接访问 `dart:io` `Platform.isIOS`，
而 Web 上 `Platform` 是桩实现，任何属性访问即抛。与其他调用点（
`account_security.dart`、`lucent_workspace.dart` 等）一致，改为
`!kIsWeb &&` 前置守卫：Web 下 `isPlatformAvailable` 返回 `false`（
auto-sync 显示 unsupported），`_sourceTag` 回退 `health_connect`；
iOS/Android 行为不变。

验证：`flutter analyze`（两文件）零问题；`test/health_data/health_sync_repository_test.dart`
与 `test/health_data/health_sync_providers_test.dart` 全部通过。

## fix(auth): SSE 流式请求 401 时 access token 自动刷新失效

SSE（`ResponseType.stream`）请求在 access token 过期时收到 401 响应，Dio 的
`response.data` 是 `ResponseBody`（流对象）而非 Map，导致
`AuthInterceptor._shouldRefresh` 内 `LucentErrorMapper.fromObject` 抛
`FormatException`→ `failure = null`→判定「不可刷新」→跳过 refresh → 直接清
session → 用户看到「登录会话已过期」，即使 refresh token 仍然有效。

本机 `.env.development` 配置 `JWT_ACCESS_TTL=15m`，access token 仅 15 分钟有效，
assistant SSE 请求在 token 过期后必然触发此路径。

修复：`_shouldRefresh` 捕获 `FormatException` 后，若响应 status 为 401 且
content-type 为 `application/problem+json`（Lucent 标准 Problem Details 格式），
尝试 refresh——refresh 对无效 token 是幂等的（后端 `claimSessionForRefresh` 原子
认领），失败时按原路径清 session，行为与修复前一致；成功时 refresh + 重试恢复
请求。

测试：`test/core/network/interceptors/auth_interceptor_test.dart` 新增两个用例：
- streamed 401 + problem+json content-type → refresh 成功 → 重试成功
- streamed 401 + 非 problem+json content-type → 不 refresh → 清 session

验证：network + assistant 全部 372 例通过。
