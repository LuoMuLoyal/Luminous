# Migration Log — 2026-09-06

## fix(health_data): Web 端 Platform 桩抛错导致设置页 Provider 崩溃

设置页（隐私区「健康数据自动同步」tile）在 Flutter Web 上构建时
`healthAutoSyncAvailabilityProvider` 抛
`Unsupported operation: Platform._operatingSystem`（Riverpod error state，
表现为设置页该区域 ProviderException）。根因：
`HealthPlatformDataSource.isPlatformAvailable` 与
`HealthSyncRepositoryImpl._sourceTag` 直接访问 `dart:io` `Platform.isIOS`，
而 Web 上 `Platform` 是桩实现，任何属性访问即抛。与其他调用点（
`account_security.dart`、`lucent_workspace.dart` 等）一致，改为
`!kIsWeb &&` 前置守卫：Web 下 `isPlatformAvailable` 返回 `false`（
auto-sync 显示 unsupported），`_sourceTag` 回退 `health_connect`；
iOS/Android 行为不变。

验证：`flutter analyze`（两文件）零问题；`test/health_data/health_sync_repository_test.dart`
与 `test/health_data/health_sync_providers_test.dart` 全部通过。

## fix(mine): 「我的」页健康同步入口在 Web 端抛出 Unsupported operation

「我的」页 `account_security.dart` 的 `if (Platform.isIOS || Platform.isAndroid)` 缺少
`kIsWeb` 守卫:dart:io `Platform` 在 Flutter Web 上是桩实现,访问即抛
`Unsupported operation: Platform._operatingSystem`,导致该 tile 子树构建失败,在
「通知与提醒」模块下方整块渲染为红色报错。其余 Platform 调用点(`bootstrap.dart`、
`lucent_workspace.dart`、`shell/page.dart`、`search/content.dart` 等)均已有
`!kIsWeb &&` 前置守卫,仅此一处遗漏。改为与其他调用点一致的前置守卫后,Web 端该
入口隐藏、移动端行为不变(测试运行于 VM,`Platform.isIOS` 返回 false 不抛,故此前
单测未暴露)。

验证:`flutter analyze` 无新增告警;`test/mine/page_test.dart` 通过。
