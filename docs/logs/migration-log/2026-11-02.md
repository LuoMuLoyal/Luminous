# 2026-11-02

## feat(tooling): 截图产出新增组件裁切工具（区块级）

### 为什么

`outputs/screenshots/` 里是整页截图，但组件库/文档需要的不是逐像素碎片，而是
**有意义的区块**：一个章节标题加它下面那组内容（如「健康档案」+ 五行卡片），而不是
每行一张图、每张卡片一张图。手工裁切既慢又容易漏，而且同一组件在 `*_scrolled`、
不同页面之间大量重复。

### 落地

- 新增 `tool/screenshots/crop_components.py`：只用 numpy + Pillow——
  取边框主色当页面底色，前景掩码做按行游程 + 并查集的连通域，得到独立色块；
  再按「填充率高（排除文字行与虚化残影）/ 尺寸下限 / 不贴画布边缘（排除被视口截断）」筛选。
- 区块合并：OCR 行里页面背景上的短标题（如「健康档案」「工具」）作为章节头，
  它与后续间距很小的卡片/行合并成一个区块；相邻的 chip/tab/分段控件横向合并成一行；
  无标题的连续同形列表行合并为一个列表块；整块被视口截断时回退为其中完整可见的行。
- 整屏大白板（聊天气泡、弹窗面板）会吞掉内部元素：检测到覆盖大部分画面的色块时，
  以该色块自身填充色为底色再分割一层，气泡/卡片因此可被切出。
- 弹窗截图（背景压暗）只保留明亮面板；无 OCR 文字且无彩色强调的骨架屏占位条丢弃。
- OCR（`rapidocr-onnxruntime`，`--ocr-libs` 指向 `pip --target` 目录）对整页识别一次，
  用于章节标题识别、区块命名、占位条过滤；结果按页面内容哈希缓存在 `outputs/.ocr-cache`。
- 组件按内容哈希去重；`desktop/` 与横屏截图属于另一视口档、`long/` 是整页重复，默认跳过。
- `tool/screenshots/README.md` 增补「Component crops」一节（安装、运行、判定规则）。
- 产出目录 `outputs/components/<group>/` + `MANIFEST.md`（crop → 源图 → 像素框 → 标签），
  `outputs/` 本身在 gitignore 内，不随提交。

### 验证

- 对当前截图集运行：79 张唯一手机档截图产出 200+ 个区块（数量随截图集变化）；
  抽查 `mine` / `today` / `settings` / `medicine` / `assistant` / `auth` / `record`：
  章节块（标题+整卡）、表单字段（标签+输入）、chip 行、聊天气泡、弹窗面板均按预期成块；
  被视口截断的区块不出现，纯文字页只切出其中成块的元素。
- 输出中无内容完全相同的文件、无近空白块；第二次运行命中 OCR 缓存，全量重跑十几秒
  （首次含 OCR 约数分钟）。
