# 2026-11-02

## feat(tooling): 截图产出新增组件裁切工具（区块级）

### 为什么

`outputs/screenshots/` 里是整页截图，但组件库/文档需要的不是逐像素碎片，而是
**有意义的区块**：一个章节标题加它下面那组内容（如「健康档案」+ 五行卡片），而不是
每行一张图、每张卡片一张图。手工裁切既慢又容易漏，而且同一组件在 `*_scrolled`、
不同页面之间大量重复。

### 落地

- 新增 `tool/screenshots/crop_components.py`：只用 numpy + Pillow——
  取边框主色当页面底色，前景掩码做按行游程 + 并查集的连通域，得到独立色块；
  再按「填充率高（排除文字行与虚化残影）/ 尺寸下限 / 不贴画布边缘（排除被视口截断）」筛选。
- 区块合并：OCR 行里页面背景上的短标题（如「健康档案」「工具」）作为章节头，
  它与后续间距很小的卡片/行合并成一个区块；相邻的 chip/tab/分段控件横向合并成一行；
  无标题的连续同形列表行合并为一个列表块；整块被视口截断时回退为其中完整可见的行。
- 整屏大白板（聊天气泡、弹窗面板）会吞掉内部元素：检测到覆盖大部分画面的色块时，
  以该色块自身填充色为底色再分割一层，气泡/卡片因此可被切出。
- 弹窗截图（背景压暗）只保留明亮面板；无 OCR 文字且无彩色强调的骨架屏占位条丢弃。
- OCR（`rapidocr-onnxruntime`，`--ocr-libs` 指向 `pip --target` 目录）对整页识别一次，
  用于章节标题识别、区块命名、占位条过滤；结果按页面内容哈希缓存在 `outputs/.ocr-cache`。
- 组件按内容哈希去重；`desktop/` 与横屏截图属于另一视口档、`long/` 是整页重复，默认跳过。
- `tool/screenshots/README.md` 增补「Component crops」一节（安装、运行、判定规则）。
- 产出目录 `outputs/components/<group>/` + `MANIFEST.md`（crop → 源图 → 像素框 → 标签），
  `outputs/` 本身在 gitignore 内，不随提交。

### 验证

- 对当前截图集运行：79 张唯一手机档截图产出 200+ 个区块（数量随截图集变化）；
  抽查 `mine` / `today` / `settings` / `medicine` / `assistant` / `auth` / `record`：
  章节块（标题+整卡）、表单字段（标签+输入）、chip 行、聊天气泡、弹窗面板均按预期成块；
  被视口截断的区块不出现，纯文字页只切出其中成块的元素。
- 输出中无内容完全相同的文件、无近空白块；第二次运行命中 OCR 缓存，全量重跑十几秒
  （首次含 OCR 约数分钟）。

## fix(tooling): 截图重复与缺内容——按视口翻页、搜索页补提交、长截图不再裁尾

### 为什么

`outputs/screenshots/` 的产物被判定不合格，三类具体缺陷都能定位到生成器：

- **翻页距离太短**：原来滚到 `maxScrollExtent × 0.55` 再截一张。只溢出十几像素的
  页面（提醒详情/提醒编辑）第二帧与首屏几乎逐像素相同；多屏页面（用药 3 屏、
  回顾 2.7 屏）只到中段，页面尾部没有任何帧；对话页进页面已贴底，再拖不动，
  「滚动后」= 首屏原样。
- **extras 产出纯重复帧**：同一路由的弹层/抽屉/候选面板本身不占整页，翻页帧就是
  首屏复制——`assistant/48、49、50、root` 与首屏逐字节相同。
- **回顾趋势三维度完全相同**：`find.text('饮水').last` 命中的是多维度趋势图的
  **图例**而不是趋势卡的 tab，点了没有任何状态变化，三张图逐字节相同。
- **搜索页没有结果**：搜索已改为提交驱动（结果面板由 `hasSubmittedResults` 门控），
  生成器只调 `updateQuery` 不发请求，截到「输入框有字、下面一片空白」。
- **长截图裁掉页尾**：帧高只取内容总高，滚动视口随帧高缩小同样多，最后一屏被底部
  tab bar 吃掉一截。

### 落地

- `_pageTurnPlan`：把首屏以下内容**按视口切片**——偏移取 `v, 2v, 3v…`，末帧只画
  「上一帧之后剩下的那段内容」，帧高可小于一屏；剩余不足 0.2 屏不产帧。两帧之间
  不重叠、整页每段各有一张图。
- `_scrollPageTo`：按需分段拖动（一次拖动位移受视口边缘限制），起手点几何取自
  `ScrollableState` 自身的 `RenderBox`——改帧高后 Scrollable element 会重建，
  靠 element 同一性定位会落空。
- extras 关闭 `scrolledCapture`；趋势三维度改走 `reviewTrendDimensionProvider`
  选中维度（与用户点 tab 同一条状态通路），并把趋势卡 `ensureVisible` 进视口。
- `_primeRoute` 对 `/medicine/search` 补 `submitQuery()`（不 await：`_doSearch`
  末尾的 KV 写入在假时钟下推不动，结果 state 在此之前已提交）。
- 长截图帧高改为「内容总高 + chrome」（`帧高 - viewportDimension`），尾部完整。
- `tool/screenshots/README.md` 同步新的产物模型（翻页帧、尾帧高度、extras 规则、
  搜索提交驱动、趋势维度选择方式）。

### 验证

- 全量重生成：119 个用例通过，140 张 PNG；精确重复 0 组；MANIFEST 与磁盘一一对应
  （140↔140）。
- 抽查：`medicine/1_medicine` 三帧按视口递进、末帧为页尾；`settings/root_scrolled`
  只含页面尾部；`medicine/2_search` 显示「共找到 5 条结果」与完整药品卡；
  `review/58、59、60` 三张分别对应用药完成率/饮水/睡眠；长截图尾部不再被裁。

## feat(search): 桌面端搜索改为主从布局，右侧复用 shell 详情面板渲染药品详情

### 为什么

桌面端搜索右栏原本是一张「选中项预览」卡。F-11 去掉了把后端 subtitle 拆成
「临床提示」的假映射之后，这张卡只剩一个药名——桌面端搜到药品后右边几乎是空白，
而手机端一直能打开完整的药品详情页。桌面有横向空间，同一份详情应当**并排展开**，
而不是另造一份精简预览。

### 落地

- 删除 `search/presentation/widgets/shared/results.dart` 的 `PreviewPanel`
  （及其「选中项预览」卡），右栏改由 `_DesktopSearchLayout` 承载
  `DesktopDetailPane`。
- `_DesktopSearchLayout` 改为 `ConsumerStatefulWidget`：`ref.listen` 搜索结果变化，
  post-frame 把当前 `selectedResultId` 同步到 `detailPaneProvider`
  （`MedicineDetailTarget(source, id)`）；无选中则关闭面板。`initState` 也补一次同步，
  覆盖「进入页面时结果已存在」的恢复路径。
- 面板渲染的是**药品详情页本身**（shell `_MedicineDetail` → `MedicineDetailContent`，
  同一个 `medicineDetailProvider` family），与用药页药盒的桌面主从形态一致；因此不必
  为搜索页复制详情组件。跨 feature 只引用 `features/shell/presentation/`
  （`cross_feature_import` 对 shell 基础设施例外）。
- 新增 `test/search/presentation/desktop_master_detail_test.dart`：桌面宽度下选中结果
  → 面板打开为对应 `MedicineDetailTarget` 且渲染药名/适应症；无选中 → 面板关闭。
  删除 `test/search/presentation/preview_panel_test.dart`。
- `lib/features/search/README.md` 更新职责、不变量（桌面右栏 = shell 详情面板，
  不再造预览卡）与跨 feature 依赖清单。

### 验证

- `flutter analyze` 全仓通过；`test/search` 107 用例通过（含新增主从用例）。
- 重生成 `desktop/medicine-search.png`：左侧结果列表，右侧「详情」面板显示
  批准文号/生产企业/规格/商品名与适应症、成分等详情分区。

### 更正（同日）：滚动帧改为直接滚到底，保持设备比例

上面的「按视口切片 + 末帧只画剩余内容」被我撤回：尾帧高度小于一屏，产出图的
比例不再是设备比例（1344×2992），截图集评审时会直接判为「比例变了」。

最终做法是**滚到 `maxScrollExtent`（页面底部）截一张完整视口**，并删除多帧序列：

- 所有非长截图帧统一为设备视口：手机档 1344×2992、桌面档 2560×1600；
- 溢出不足半屏的页面不产滚动帧（位移太小，截出来就是首屏复制，尾部由长截图覆盖）；
- 因此滚动帧数量回落（本页集 6 张），产物总数 134，MANIFEST 与磁盘一一对应；
- 重跑前必须清空 `outputs/screenshots`：生成器不清理过期产物，旧的 `_scrolled2/3`
  残留会混进产物集，表现为尺寸不一致的图。

## ci(release): 新增 Linux 桌面发布 workflow

### 为什么

目标平台里有 Linux，但此前没有对应的产物构建面：Windows 开发机本地编译不了
Linux 桌面产物（需要 Linux 版 Flutter SDK、clang/cmake/ninja、GTK3 开发头文件）。
按 `.github/workflows/README.md` 的约定「新增发布面就新建 `deploy-*.yml`，
不要把产物塞回 `ci.yml`」，新增一个独立的 Linux 发布 workflow。

### 落地

- 新增 `.github/workflows/deploy-linux.yml`（`name: Deploy Linux`）：
  - 触发：`push main` / 手动 `workflow_dispatch`；独立 concurrency group；
    `contents: read`；
  - 依赖：`clang cmake ninja-build pkg-config libgtk-3-dev liblzma-dev g++`
    + 插件系统库 `libsecret-1-dev libjsoncpp-dev`
    （`flutter_secure_storage_linux`）、`libgstreamer1.0-dev`
    `libgstreamer-plugins-base1.0-dev`（`audioplayers_linux`）、
    `libsqlite3-dev libssl-dev`（drift / OpenSSL）。用 `g++` 而非版本化的
    `libstdc++-NN-dev`：runner 的 Ubuntu 版本会滚动，写死版本号会随镜像升级失效；
  - 生成物前置步骤与其它发布面一致：`Bootstrap generated sources --skip-client`
    → `generated/lucent_api` 的 `build_runner`（缺后者编译期直接失败）；
  - `flutter build linux --release` 注入 `LUCENT_BASE_URL`（必填，缺失直接失败）、
    `SENTRY_DSN`、`SUPPORT_EMAIL`，与 Android / iOS / Web 同口径；
  - 产物自证：`bundle/luminous` 可执行、`lib/libapp.so`、`flutter_assets` 清单
    三项缺一即失败；
  - 打包 `build/luminous-linux-x64.tar.gz` 并上传 artifact `luminous-linux-x64`。
- `.github/workflows/README.md`：workflow 索引表、产物表、环境变量、生成物前置
  步骤四处同步新增 Linux 一行。

### 验证

- YAML 结构检查通过（11 个 step：checkout → 密钥校验 → Flutter 3.47.7 →
  pub 缓存 → apt 依赖 → bootstrap → 生成客户端 → build → 产物校验 → 打包 → 上传）。
- 构建面本身需要 GitHub runner 才能跑：Windows 本机无 Linux 工具链，本地验证
  以 `workflow_dispatch` 手动触发为准。

### 调整：Web 自动发布、Linux 改为手动、新增 Windows 发布

按发布面的最终形态调整刚加的 Linux workflow，并补上 Windows：

- **Web**：`deploy-web.yml` 的自动触发分支从 `refactor` 改为 `main`——Pages 跟随
  默认分支发布。`.github/workflows/README.md` 里「只在 refactor 上触发、不要改成
  main」的旧约定同步删除。
- **Linux**：`deploy-linux.yml` 去掉 `push` 触发，**只保留 `workflow_dispatch`**。
  Linux 桌面产物是「需要时要一个」的交付形态，不进 main 的自动发布链路。
- **Windows（新增）**：`deploy-windows.yml` 在 `windows-latest` 上构建
  `flutter build windows --release` 并上传 `luminous-windows-x64.zip`。
  - 生成物前置步骤（bootstrap + generated/lucent_api 的 build_runner）与其它发布面一致；
  - 产物目录不写死：Flutter 的 Windows 输出目录在小版本间移动过，改为按
    `luminous.exe` 反查，再校验 `flutter_windows.dll` 与 `data/flutter_assets`；
  - 触发与 Android / iOS 对齐：`push main` + 手动。
- `.github/workflows/README.md` 同步：workflow 索引表（新增 Windows 行、Linux 改
  「仅手动」、Web 改 `main`）、触发说明、产物表、环境变量、生成物前置步骤五处。

### 验证

- 三个 workflow 的结构自检通过：Linux 11 步（仅手动，ubuntu-latest）、
  Windows 10 步（windows-latest，zip 产物）、Web 12 步（main 自动触发，Pages 发布）。
- Windows / Linux 产物只能在对应 runner 上真实编译，本地（Windows 无 GTK 工具链、
  无 GitHub Actions runner）以 `workflow_dispatch` 手动触发为准。

### 调整：Windows 也改手动，并统一升级 workflow 的 action 版本

- **Windows**：`deploy-windows.yml` 去掉 `push` 触发，与 Linux 一致**只保留
  `workflow_dispatch`**。桌面产物（Windows / Linux）都按需出包，`main` 的自动发布
  链路只保留移动端与 Web。
- **action 版本**：仓库里 deploy-* 一面此前停在 `checkout@v4` / `cache@v4` /
  `upload-artifact@v4`，而 `codeql.yml` / `scorecard.yml` 已经是 `checkout@v7`，
  版本面彼此不一致。统一升到当前最新 major：
  - `actions/checkout` v4 → **v7**
  - `actions/cache` v4 → **v6**
  - `actions/upload-artifact` v4 → **v7**
  - `actions/setup-java` v4 → **v6**
  - `actions/upload-pages-artifact` v3 → **v5**、`actions/deploy-pages` v4 → **v5**
  - `subosito/flutter-action` `@v2` → **`@v2.23.0`**（major 仍是最新的 v2，pin 到
    patch 版本，SDK 来源不被上游 tag 移动影响）
  - `github/codeql-action/*` 已是 **v4**，`ossf/scorecard-action@v2.5.0`、
    `google/osv-scanner-action@v2.7.0` 已是当前版本，未动。
- `.github/workflows/README.md`：Windows 行改「仅手动」，触发说明改为
  「Android / iOS / Web = main；Windows / Linux / HarmonyOS 按需出包」。

### 验证

- 全仓 workflow 已无 `checkout@v4`/`cache@v4`/`upload-artifact@v4`/
  `setup-java@v4`/`pages-artifact@v3`/`deploy-pages@v4`/`flutter-action@v2` 残留。
- Linux / Windows 两个桌面发布面都只有 `workflow_dispatch`；Web 仍是 `main` 自动
  发布 Pages。
