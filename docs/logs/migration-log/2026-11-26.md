## feat(medicine): 接回 `safety.tip_card`，安全提示链路不再是死代码

### 变更范围

`GET /api/v1/medicines/safety-tips` 的客户端链路（实体 / 远端数据源 / notifier /
样式映射）自接口落地起一直没有消费方，四处文件各自挂着 `TODO(archive)`。这轮的
做法不是删掉它们，而是把这条链路接进组件系统，让它成为一个可编排组件：

- 新增 `presentation/components/catalog.dart` 中的 `medicineSafetyTipId`
  （`safety.tip_card`）与 `_SafetyTipComponent`。它注册进 `owned`，**不进
  `defaultLayout`**：一条可选提示不该占据页面主干，用户在编排页自行挂载，可挂到
  任意 surface（组件系统的跨表面复用，`SurfaceCatalog.mountableOn`）。
- 新增 `presentation/widgets/sections/safety_tip.dart` 的 `SafetyTipCard`：HIG
  inset grouped card，单一正文块，17pt body / 行高 1.29 / 内边距 16pt，**无图标、
  无次级灰字、无标题行、无换一条按钮**。类别与来源不上屏；文本由服务端按语言
  下发，客户端不留文案（l10n 无需新增 key）。
- `build` 在「加载中 / 失败 / 后端无更多提示」三态都返回 `null`，宿主连间距一起
  移除。这与关系图组件「失败必须显式否定」相反：那组失败要防止被读成「没有相互
  作用」，这条提示消失不会被读成任何安全结论，空壳卡片反而更糟。
- 删除 `presentation/utils/safety_tip_style.dart` 与
  `test/medicine/safety_tip_style_test.dart`：icon/color 按 category 的映射随
  「卡片不设图标、不按类别上色」一起失去存在理由，留着只会诱人接回装饰性图标。
- 四个文件的 `TODO(archive)` 注释删掉，改成说明实际消费方。

### 验证

- `flutter analyze` 全仓无 issue。
- `test/medicine/safety_tip_component_test.dart`：正文渲染且类别不上屏、无提示时
  整块跳过（`build` 返回 `null`）。
- `test/medicine/graph_components_test.dart` 与 `page_test.dart` 全通过——
  `medicineSurfaceDefinition.owned` 增加一个 id 不影响「已注册但不在默认布局」
  的既有断言。

### 已知未闭环

无。本轮改动自身零违规。

## refactor(auth): 会话读接缝收口，`--clean-layers` 存量违规清零

### 变更范围

`tool/luminous_lints --clean-layers` 原有 16 条阻断违规（`presentation_layer` 15 条 +
`core_not_import_features` 1 条），全部出自同一条链：

- **读接缝没有暴露调用方要的符号**。`core/providers/session/session_snapshot.dart`
  早已是 presentation 读会话的合规入口（`core/auth/` 不授权给 R5），但它只导出
  `authSessionProvider` 与 `AuthSessionState`，**没有 `AuthSessionStateIdentity`**
  ——于是读 `session.userId` 的 12 个文件全都绕回 `core/auth/session_provider.dart`。
  修法是把身份扩展补进接缝，而不是改规则。
- **快照映射住在 core，却认识 feature 实体**。`core/auth/session_mapping.dart` 把
  `AuthUser` / `AuthSession` 投影成 `Session*Snapshot`，`core_not_import_features`
  正是拦这条反向依赖。映射是「跨层接线」而非 core 能力，`git mv` 到
  `app/composition/auth/session_mapping.dart`；core 侧只保留 feature-free 的
  `session_snapshot.dart`。
- **三处页面把 `session.user` 就地 `as AuthUser?` 强转**。改用 feature 侧已有的
  barrel `features/auth/presentation/providers/session_state.dart`
  （`AuthSessionAccountView.user`），强转收进 barrel 一处。

改动明细：接缝导出补 `AuthSessionStateIdentity`；`session_mapping.dart` 迁入组合根并
改写头注释（原注释声称「留在 core 是为了避开主依赖环」，与 R7 冲突，已按实际约束
重写）；12 个 presentation 文件与 `app/auth_session_adapter.dart` 的 import 改指向；
`lib/core/auth/README.md` 与 `lib/features/auth/README.md` 的「被依赖 / 不变量」两节
跟着改口径——展示层不直连 `core/auth/`。

  性对齐排序）。
- `flutter test` 全量通过。
