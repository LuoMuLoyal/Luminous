## feat(medicine): 接回 `safety.tip_card`，安全提示链路不再是死代码

### 变更范围

`GET /api/v1/medicines/safety-tips` 的客户端链路（实体 / 远端数据源 / notifier /
样式映射）自接口落地起一直没有消费方，四处文件各自挂着 `TODO(archive)`。这轮的
做法不是删掉它们，而是把这条链路接进组件系统，让它成为一个可编排组件：

- 新增 `presentation/components/catalog.dart` 中的 `medicineSafetyTipId`
  （`safety.tip_card`）与 `_SafetyTipComponent`。它注册进 `owned`，**不进
  `defaultLayout`**：一条可选提示不该占据页面主干，用户在编排页自行挂载，可挂到
  任意 surface（组件系统的跨表面复用，`SurfaceCatalog.mountableOn`）。
- 新增 `presentation/widgets/sections/safety_tip.dart` 的 `SafetyTipCard`：HIG
  inset grouped card，单一正文块，17pt body / 行高 1.29 / 内边距 16pt，**无图标、
  无次级灰字、无标题行、无换一条按钮**。类别与来源不上屏；文本由服务端按语言
  下发，客户端不留文案（l10n 无需新增 key）。
- `build` 在「加载中 / 失败 / 后端无更多提示」三态都返回 `null`，宿主连间距一起
  移除。这与关系图组件「失败必须显式否定」相反：那组失败要防止被读成「没有相互
  作用」，这条提示消失不会被读成任何安全结论，空壳卡片反而更糟。
- 删除 `presentation/utils/safety_tip_style.dart` 与
  `test/medicine/safety_tip_style_test.dart`：icon/color 按 category 的映射随
  「卡片不设图标、不按类别上色」一起失去存在理由，留着只会诱人接回装饰性图标。
- 四个文件的 `TODO(archive)` 注释删掉，改成说明实际消费方。

- `test/medicine/safety_tip_component_test.dart`：正文渲染且类别不上屏、无提示时

## feat(generative): A2UI catalog id 改由 `--dart-define` 提供

`GenerativeCatalog.luminousCatalogId` 原本是写死的 `https://luminous.app/a2ui/catalog/v1.json`
——那个域名是迁移时凭空写的，没有人确认过归属。catalog id 是**对外发布的标识符**
（出现在模型产出的每一条 `createSurface` 里），选它属于部署决定，不该由代码替部署方
声称一个域名。

### 变更范围

- `EnvKey.a2uiCatalogId`（`A2UI_CATALOG_ID`）+ `EnvReader` 分支；与 Lucent 的服务端
  变量**同名**，因为两边必须同值：服务端据此告诉模型写什么，渲染端按它找已注册的
  catalog，不一致时整批组件被按「不属于本 catalog」拒绝。
- `GenerativeCatalog.catalogId` 由 `static const` 改为读 env 的 getter；未配置时用
  `defaultCatalogId = urn:a2ui:catalog:luminous:v1`。选 URN 而不是 URL 是刻意的：
  A2UI 只要求它是字符串标识（约定写成 URI 以免撞名），URN 不声称任何域名所有权。
- 空值兜底放在**使用点**而不是 `EnvReader.string(fallback:)`：后者只在
  `String.fromEnvironment` 分支套兜底，`setTestValue` 分支原样返回空串。这一条是
  `catalog_id_test.dart` 抓出来的——catalog id 变成空串会让 surface 建不出来。
- `.env.example` / `.env.e2e.example` 补 `A2UI_CATALOG_ID`（留空即默认 URN），并写明
  必须与 Lucent 同值。
- 三个既有生成式测试里写死的 catalog id 改为引用
  `GenerativeCatalog.defaultCatalogId`，否则它们渲染的 surface 与本 build 注册的 catalog
  对不上。

### 顺带修掉的既有缺陷

`.env.example` 里 `LUMINOUS_EXPERIMENTAL_AI_RUNTIME` / `LUMINOUS_AI_RUNTIME_PROVIDER`
两条**代码从来没读过**（只在旧归档里出现）；代码读的是
`LUMINOUS_EXPERIMENTAL_RUNTIME_ENABLED` / `LUMINOUS_RUNTIME_PROVIDER`，CI 文档表也是后一组。
照抄 example 等于没设。已把 example 对齐到代码实际读取的名字。

### 验证

- `flutter analyze`：No issues found。
- `test/generative`：35 个用例通过；新增 `catalog_id_test.dart` 4 例（默认是 URN、
  读 `A2UI_CATALOG_ID`、build 出来的 catalog 与文档都带该 id、空白值回落默认）。
- 未跑全量 `flutter test`。

## feat(llama_native): 端侧 LLM 推理包，Dart 侧分层落地

新增 `pkgs/llama_native`：基于 llama.cpp 的端侧推理包。**本轮只做 Dart 侧，原生库尚未
构建**，因此包还不能真正推理——剩下的工作记在 `docs/TODO.md` 的对应小节。

### 分层（Clean，`app → domain/ports ← data`）

| 层 | 内容 |
| --- | --- |
| `domain/` | 纯 Dart：`GenerationOptions` / `EngineOptions` / `ModelInfo` / `ChatMessage` / `GenerationResult`、`LlamaFailure`（稳定 kind）、`LlamaEngine` 端口、`CollectGeneration` 与 `fallbackChatPrompt` |
| `data/ffi/` | `llama_shim.h` 的机械映射，零逻辑 |
| `data/isolate/` | 跨 isolate 词汇（`worker_protocol`）+ worker（唯一持有原生句柄） |
| `data/worker/` | 主 isolate 侧会话（`WorkerConnection`） |
| `data/repositories/` | `LlamaCppEngine`：domain ⇄ worker 翻译 |

`domain/` 不含 FFI、isolate 或 I/O，所以 `test/domain_test.dart` 的 12 个用例**不需要
原生库或模型文件**。这也是分层的主要收益：取消语义、缺模板的回退、参数校验这些规则
都是毫秒级可测的。

### 三个决策及理由

1. **C shim 而非直接绑 `llama.h`**：llama.cpp 的 C API 在版本间改名、改结构体
   （`llama_load_model_from_file` → `llama_model_load_from_file`，sampler 链整体替换）。
   直接绑定会让升级表现为段错误而非编译错误。`src-native/llama_shim.h` 是约 10 个
   **我们控制的**函数。
2. **推理必须在 worker isolate**：`llama_decode` 每 token 阻塞数百毫秒，在主 isolate 上
   整个生成过程 UI 冻住。
3. **原生句柄只在 worker**：`Pointer` 不能跨 isolate 传递，共享句柄是未定义行为。

### 编写中撞到并修掉的问题

- `NativeCallable<T>` 的类型名写错（`NativeTokenCallback` → `TokenCallbackNative`）。
- `StreamController.addError()` 返回 `void`、`close()` 返回 `Future`：前者不能包
  `unawaited`（会报 `use_of_void_result`），后者必须包（否则 `discarded_futures`）。
- `WorkerConnection.close()` 原本先置 `_closed = true` 再发 dispose，导致 `_send` 直接
  拒绝、dispose 永远发不出去；改为先等 ack 再置位。
- 模块级 token sink 会在 `generate` 结束后残留，下一次生成继承一个已无人监听的端口；
  改为在 `finally` 里清空。
- `pubspec.yaml` 的分层写作 `domain/errors` 与实际 `domain/failures` 不一致。
- `.gitignore` 的 `/build/` 只锚定根目录，子包测试产生的 `pkgs/*/build/` 会漏进提交；
  改为 `**/build/`。
