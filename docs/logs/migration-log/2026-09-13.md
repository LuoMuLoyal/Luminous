# 2026-09-13

## fix(core,auth,settings): 账号资料列表改用 Forui tile,删除自绘行并修正箭头未贴右

### 背景

账号管理页此前用自绘行 `AppValueRow`（标签 `Expanded` + 值列 `Flexible` + 手绘箭头）和自绘白卡片
（`_AccountValueCard` / `_ValueCard`）+ `AppDivider` 拼分组。实测该行的箭头**没有贴右**：值列用松约束
`Flexible`，只占内容自身宽度，未用完的 flex 份额变成尾部空白留在行尾 —— 300px 宽的行里箭头右边缘距行
右边缘 107.75px，且每行因值长度不同而偏移量不同。上一版 `LayoutBuilder` + `IntrinsicWidth` 方案在
`61e8300d` 被换成 flex 比例方案，当时新增的测试只断言「行横跨卡片内宽」，没有量箭头位置，回归未被拦住。

分组卡片与行本来就有 Forui 现成实现：`FTileGroup`（分组 surface + 组内分隔线 + 按压/焦点反馈）与
`FTile`（`title` 左标签 / `details` 右当前值 / `suffix` 尾部箭头，布局由 Forui 负责、箭头按构造落在行尾）。
设置页与 `SettingsNavigationTile` 一直是这么用的，本次把账号/资料面收口到同一实现，顺带删掉
`AppValueRow` 这个已经退化成薄封装的中间层。

### 变更

- 行：`account_manage_sections.dart` / `security_center.dart` / `profile.dart` 共 22 行改为直接写
  `FTile`（`title` / `details` / `suffix` / `prefix` / `onPress`，注销行 `variant: FItemVariant.destructive`）；
  邮箱已验证图标改由调用点自己组 `Row(mainAxisSize: min)`（图标 + 间距 + 箭头）。
- 值列：新增 `lib/core/widgets/common/control/tile_value.dart`（`AppTileValue`，即 `FTile.details` 的值列）。
  它把文本包成非 `Text` 的受限宽度组件（`LayoutBuilder` + `ConstrainedBox`，上限内容宽 55%），因为
  Forui 的 tile 内容布局在 `details` 是 `RenderParagraph` 时把剩余宽度**优先给 `title`**，长标签（实测
  「出生日期(YYYY-MM-DD)」）会把值列压到 0 宽；换成非文本包装后值列先测量、标签退让并 ellipsize，
  55% 上限保证两列都在。
- 分组：三个页面改为 `FTileGroup`（`physics: NeverScrollableScrollPhysics()` +
  `divider: FItemDivider.full`），删除 `_AccountValueCard` / `_ValueCard` 与全部 `AppDivider`；观感随之
  统一到主题 `tileGroupStyle`（白底 + 1px subtle 描边 + 组内分隔线），不再是自绘的无边框白卡片。
- 删除 `lib/core/widgets/common/control/value_row.dart`（`AppValueRow`）：Forui 化之后它只剩 `Text`
  语法糖，`valueColor` 在 `lib/` 下 0 处调用，`isPlaceholder` 是空操作（`SemanticColor.neutral.solid`
  就是 `fColors.mutedForeground`，与 `FTile` 的 `detailsTextStyle` 默认色同色），两个死参数一并删掉；
  纯跳转行不再需要 `value: ''`，不传 `details` 即可。
- 测试：`test/settings/profile_avatar_test.dart` 的贴边用例改为「每行填满所属 `FTileGroup`，箭头落在
  该组尾内边」；新增 `test/core/widgets/tile_value_test.dart`，直接用 `FTile` 组行验证（箭头贴分组尾内边、
  值与箭头相邻、无值行不影响箭头位置、长标题 + 长值两列都可见且值列 ≤55%）。
- 文档：`docs/reference/design-system.md`（列表行与分组约定）、`lib/features/auth/README.md`（账号页约定）。

### 验证

- `flutter analyze` 0 issue；`tile_value_test`、`profile_avatar_test`、`account_settings_page_test`、
  `security_center_page_test`、`flow_test` 窄跑通过；**未跑全量**（按会话要求只跑窄命令）。

## fix(settings,scan,review): 单行卡片由 FCard+FTile 双层改为单子项 FTileGroup

排查「是不是该用 FTileGroup 而不是 FTile」时确认的漏网处：**四处**把 `FTile` 直接塞进 `FCard`，而
Forui 的 tile 在没有 `FTileGroup` 祖先时取主题 `tileStyles`（`tile.dart:301`），其默认
`contentDecoration` 已经是「白底 + 1px 描边 + r10」的卡片——外面再套 `FCard`（同色描边 + r14）
就是双层卡片（实测打印两者 decoration 一致，仅圆角不同）。仓库既有正确写法见 `sign_out_tile.dart`
与账号安全中心的「登录记录 / 账号保护」：单行卡片用单子项 `FTileGroup`。

### 变更

- `lib/features/settings/presentation/widgets/account_header.dart`：`FCard(child: FTile(...))`
  → 单子项 `FTileGroup`。
- `lib/features/scan/presentation/widgets/box_scan_preview.dart`（`MethodTile`）：同上；顺手去掉只为
  `FCard` 定制的那段 `style` delta（自定 `colors.background` 底 + `lg` 圆角），回到主题
  `tileGroupStyle`（白底 + subtle 描边 + `md` 圆角）；tile 内的图标尺寸/副标题样式保持原样。
- `lib/features/review/presentation/widgets/views/legacy/dashboard_view.dart`
  （`_ReportLockedFeaturesHint`）：同上。该文件是 LEGACY 兼容页，本次只改这处 surface，不动其余装配。
- `lib/features/settings/presentation/pages/notification.dart`（`_PermissionCard`）：同上；`key` 仍挂在
  内层 `FTile` 上（调用方与测试按该 key 取卡片）。这一处在首轮按「同文件有 `FTileGroup` 即视为正常」的
  粗筛中漏掉，末轮改用整库正则（`FCard(` 后紧跟 `child: FTile(`）复扫才捞出来。
- 文档：`docs/reference/design-system.md` 的 `FTileGroup` 条目补一句「单行卡片也用 `FTileGroup`，
  别写 `FCard(child: FTile(...))`」并说明原因。

### 验证

  `test/settings/notification_preferences_sync_test.dart`、`test/settings/notification_settings_controller_test.dart`、

  `test/core/widgets/tile_value_test.dart`、`test/review/widgets/more_actions_test.dart`
