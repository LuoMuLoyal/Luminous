## feat(native): 实现 KMP 步数读取

- 共享层:新增 `Capability` / `Failure` / `NativeResult` 与 `StepRequest` /
  `StepSample` / `StepSource`;`normalization.kt` 负责请求区间裁剪、按本地日切分、
  同日同来源合并,以及累计值基线差值与重启回退。
- Android:新增 `AndroidStepSource`,通过 `TYPE_STEP_COUNTER` 读取累计值,
  `SharedPreferences` 持久化基线;无传感器或未授予 `ACTIVITY_RECOGNITION` 时返回
  对应 `Capability`。插件 manifest 声明 `ACTIVITY_RECOGNITION`。
- iOS:新增 `LuminousStepSource`,通过 HealthKit `HKStatisticsCollectionQuery` 按日
  读取步数,并提供 `requestAuthorization()`;结果同样经过 common 归一化。
- 测试:新增 `NormalizationTest`,覆盖日切分、同日合并、边界裁剪、负值/越界样本、
  25 小时日边界与基线重启。
- 验证:`testAndroidHostTest`、`compileKotlinIosArm64`、
  `compileKotlinIosSimulatorArm64` 通过;iOS 链接与真机 HealthKit 仍需 macOS。

## feat(native): 接通 Pigeon 步数桥接

- `pigeon/steps.dart` 定义 `StepHostApi` 的 `capability` / `read`,DTO 固定
  `count`、`startMs`、`endMs`、`source`;生成 Dart、Kotlin、Swift 代码。
- Android `StepHandler` 调用 `AndroidStepSource`,在 `mapping.kt` 完成 DTO 与

  现有 `health` 插件流程。
- Dart `StepBridge` 暴露插件自有 `StepCapability` / `NativeStepSample`,不把 Pigeon
  类型泄漏到应用层;新增 fake API 单测。
- 验证:`flutter analyze`(根/插件)、插件 `flutter test`(3 个测试)、
  `flutter build apk --debug`、KMP 两个 iOS target 编译通过。iOS Swift 接线需在 macOS
  首次编译确认。
