# Migration Log — 2026-09-03

## contract bootstrap 流水线修复(Lucent zod 迁移合同端到端再生成)

背景:2026-09-03 Lucent 侧请求校验全面迁移 zod(050d7851),合同 schema 面大幅变化
(请求体由扁平的 `*_dto` 改为内联 `*_request` 命名)。`dart run scripts/contract/bootstrap.dart`
对当前合同端到端跑不通,根因分三层,处置如下:

### 根因与处置

- **生成残留(合并拷贝不清除旧文件)**:`_buildClient` 只把 openapi 再生成产物合并拷贝进
  `generated/lucent_api`,合同侧删除/重命名 schema 后旧 model/api 文件残留,畸形残留文件
  会让客户端 `build_runner` 在解析阶段失败。处置:生成阶段前整树删除
  `generated/lucent_api/lib`(该目录全部为生成物,含 build_runner 落盘的 `*.g.dart`),
  由拷贝步骤重建精确镜像;本轮合同差异即体现为删除一批旧 `*_dto` model 并新增内联
  `*_request` model。
- **根包 build_runner 确定性失败**:根 `dart run build_runner build` 退出 1。原因是
  `tool/luminous_lints`(独立 analyzer 插件包,自带 pubspec,不在根包 package_config)
  的 `test/` 文件被根包源码集收录,`json_serializable`/`go_router_builder`/`drift_dev`
  等 builder 无法解析其 `package:test` 注解,逐个报 E 错误并致构建失败。处置:`build.yaml`
  的 `sources.exclude` 追加 `tool/luminous_lints/**`,与 `analysis_options.yaml` 既有
  排除口径一致(该包由其自身 `dart test` 独立校验,不削弱必要校验)。此前的
  "Running build hooks... Command failed with exit code 1" 尾段即该失败的呈现;
  修复后该行仅为成功路径噪音。
- **Windows 偶发文件锁**:`support.dart` 的 `runLoggedCommand` 增加可选 `maxRetries`,
  `bootstrap.dart` 对两处 build_runner 调用各配 1 次重试,失败后提示并间隔 3 秒重跑,
  覆盖 Windows 锁类偶发(error 1224 类),确定性失败仍会在重试后如实上抛。

### 验证

- `dart run scripts/contract/bootstrap.dart` 端到端连续两次 exit 0(客户端 build_runner、
  dart format 与根 build_runner 均通过)。
- `cd generated/lucent_api && dart analyze lib` 无 error;仅剩 `unused_import` warning,
  为 dart-dio 生成器既有风格问题(HEAD 已提交客户端同样存在),非本轮引入。
- 根 `flutter analyze` 无问题(generated 目录在根分析中排除)。

### 处置

- 改动仅限脚本/工具链(`scripts/contract/bootstrap.dart`、`scripts/support.dart`、
  `build.yaml`)与 `generated/lucent_api` 再生成产物;未提交,由维护者集成。
- 残留风险:`generated/lucent_api/test/` 下受版本控制的旧测试由早期 generation 产出,
  现 generation 已关闭 tests;该目录被自身 `analysis_options.yaml` 排除,不影响 analyze,
  但内容与当前模型面不同步,后续如需在 generated 包内跑测试应先清理或禁用。
