# 2026-11-03

## fix(ci): Linux 发布构建补 libcurl/zlib 开发包

### 现象

`Deploy Linux`（run `41624513242`，`main`）在 `Build Linux (release)` 步骤失败：

```
CMake Error at /usr/local/share/cmake-4.4/Modules/FindPackageHandleStandardArgs.cmake:290 (message):
  Could NOT find CURL (missing: CURL_LIBRARY CURL_INCLUDE_DIR)
Call Stack (most recent call first):
  /usr/local/share/cmake-4.4/Modules/FindCURL.cmake:291 (find_package_handle_standard_args)
  .../build/linux/x64/release/_deps/sentry-native-src/CMakeLists.txt:493 (find_package)
Unable to generate build files
```

### 为什么

- `sentry_flutter` 的 Linux 插件在 CMake configure 阶段用 `FetchContent` 拉取
  `sentry-native`（9.24.0 锁 0.15.2）并**在本机编译**。这层原生 SDK 不由 Flutter
  工具链提供，它的系统依赖必须由 workflow 自己装。
- sentry-native 在 Linux 上默认 `SENTRY_TRANSPORT=curl`，走
  `find_package(CURL REQUIRED)`；插件又把 `SENTRY_BACKEND` 固定成 crashpad，
  而 crashpad 在 Linux/macOS 上要求系统 zlib（`find_package(ZLIB REQUIRED)`）。
- 原 apt 列表覆盖了 GTK / secret / gstreamer / sqlite / OpenSSL，唯独没有 curl
  开发包。runner 镜像（`ubuntu-26.04`）只带 curl 运行时，不带 `curl/curl.h` 与
  `libcurl.so` 链接名，于是 configure 阶段直接失败。

### 落地

- `.github/workflows/deploy-linux.yml` 的 `Install Linux desktop dependencies`
  增加 `libcurl4-openssl-dev zlib1g-dev`。
- 在 step 注释里写明两者是 sentry-native（curl transport + crashpad backend）的
  构建期硬依赖，避免以后按「看起来和 Flutter 无关」再被删掉。
- 不动 `runs-on`、Flutter 版本、生成物前置步骤与产物校验：问题只在系统依赖面。

### 验证

- workflow YAML 解析通过，`build-linux` 仍是 11 个 step。
- 包名对照 Ubuntu 26.04（resolute）包索引确认存在：`libcurl4-openssl-dev` 提供
  `/usr/include/curl` 与 `libcurl.so`（`FindCURL` 的两个 required var），
  `zlib1g-dev` 提供 `zlib.h` / `libz.so`。
- 依据 sentry-native 0.15.2 README「crashpad backend 需要 zlib；Linux / macOS
  需要 libcurl」与插件 `sentry-native/sentry-native.cmake` 的 `find_package` 路径确认。
- 真实构建仍需在 runner 上手动触发 `workflow_dispatch` 复验：本地是 Windows，
  没有 Linux 桌面工具链，configure 失败只在 Linux 上复现。
