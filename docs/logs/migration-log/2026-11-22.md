## feat(settings): AI 助手引擎选择与 assistantAgentMode 契约接入

### 变更范围

- 契约：Lucent 侧 `pnpm export:openapi` 导出 `assistantAgentMode`（`UserSettingsResponse` /
  `UpdateSettingsRequest` 各一处 enum）；Luminous 侧 `dart run scripts/contract/bootstrap.dart`
  重生成，产出 `UserSettingsResponseAssistantAgentModeEnum`（`default` / `graph` / `deepagents`
  / `unknownDefaultOpenApi`）。
- `domain/entities/user_settings.dart`：新增 `AssistantAgentMode` 枚举（`followOperator` /
  `graph` / `deepAgents`，携带 `wireValue`）与 `UserSettings.assistantAgentMode` 字段，
  默认 `followOperator` —— 旧缓存 payload 缺该键时仍能解码。
- `domain/repositories/user_settings.dart` + `data/repositories/lucent.dart`：`updateSettings`
  增必填参数，写路径用显式 `switch` 翻译成生成枚举，读路径经 `fromWireValue` 归一。
- `presentation/providers/user_settings.dart`：`setAssistantAgentMode`，`_patch` /
  `applySettingsPatch` 透传。
- `presentation/pages/advanced/ai.dart`：新增「助手引擎」区块，三个 `FRadio`（服务端默认 /
  标准 / 增强），选中项直接反映服务端存储值。
- ARB：`settings_{en,zh}.arb` 增 8 个键（区块标题、三个选项的标题与副标题、生效提示）。

### 说明

**为什么 domain 用本地枚举而不是生成的 enum。** `domain_purity` 禁止 `domain/**` 依赖
`lucent_api`，所以实体只能持有一个本地值类型；生成枚举的翻译放在 data 层的 mapper。
`fromWireValue` 对未知值回落 `followOperator`，而不是抛错或保留原字符串 —— 服务端将来新增
模式时，老客户端应表现为「跟随服务端默认」，而不是显示一个没有选中项的控件。

**写路径用显式 `switch` 而非 `byName` 查找。** `byName` 在新增 domain 值时抛运行时异常，
而 `switch` 表达式漏分支是编译错误。这里要的是后者。

**引擎选择不随 `assistantEnabled` 降级。** 内存/上下文开关是数据权限，assistant 关闭时
一并失效；引擎选择是「下次使用助手时用哪个后端」，与是否立刻可用无关，因此只受
`_isPatching` / 加载态约束。

**点击已选中项直接返回，不发 PATCH。** 后端把同值 PATCH 也当作一次写入（会更新
`updatedAt` 并发设置变更事件），对一次「什么都没改」的点击发请求是噪音。

**切换后提示「从下一条消息开始生效」。** 运行时按轮选择，切换不会追溯改变已完成的回答；
这句话只在成功后出现，失败由 `_guardedApply` 出错误提示。

## feat(assistant): 对话框上方的引擎胶囊，点开就地展开选项

### 变更范围

- 新增 `presentation/widgets/shared/engine_pill.dart`：`AssistantEnginePill`（胶囊）+
  `AssistantEngineOptions`（展开的选项行）。
- 新增 `presentation/widgets/shared/engine_option.dart`：`AssistantEngineOption`
  与 `assistantEngineLabel()`（胶囊与选项共用的命名映射）。
- `presentation/widgets/chat_surface.dart`：`InputOptions` 接两个槽位 ——
  `attachmentPreviewBuilder`（输入框**上方**，放展开的选项）与
  `inputToolbarBuilder`（输入框**下方**那一行，放胶囊）；`_engineExpanded` 状态由
  surface 持有。
- ARB：`assistant_{en,zh}.arb` 增 `assistantEnginePillSemantics`（带占位符）。

### 说明

**为什么不用弹窗。** 选择引擎是「边写问题边决定」的动作。弹层会盖住正在输入的文字，
并为一次点击增加一次关闭步骤。选项直接展开在输入框上方、胶囊留在下方那行，与豆包 /
DeepSeek 的形态一致。

**为什么胶囊和选项拆成两个 widget。** 它们落在 gen_ai 包内**不同**的插槽
（`attachmentPreviewBuilder` 在字段之上、`inputToolbarBuilder` 在字段之下的工具行），
没有一个插槽能同时容纳二者。展开状态因此提升到 `chat_surface`，两边读同一个 flag。

**图标不用 chevron。** 免责声明条已经用 `actionExpand` 表达自己的展开语义；同屏两个
相同 chevron 会被读成同一个控件。胶囊用 `aiEntry`（sparkles），选中态用主色而非图标
变化来表达。

**`followOperator` 显示「服务端默认」，不猜具体引擎。** 客户端不知道运维配了哪个；
猜测会在运维改默认值的那一刻让设置看起来被改过。

**发送消息时自动收起。** 一次发送即这次 composer 交互的终点；继续展开会让下一条回复
被挤出屏幕。

**失败不收起。** 写失败只弹 toast，胶囊保持上一个选中值 —— 那才是真实状态。
