## Luminous — Native Assets 构建问题排查

- **目标**：排查集成测试无法在本地 Android 模拟器上运行的 native assets 构建失败问题。
- **排查结果**：
  - **根因**：`sqlite3` 包 v3.3.4 在 `enable-native-assets` 特性标志启用时，通过 native assets hook 从 GitHub 下载预编译的 `libsqlite3.*.android.so` 文件。下载因 `HandshakeException: Connection terminated during handshake` 失败——这是 Dart 在 Windows 上的已知 TLS 证书问题（dartbug.com/52266），Dart 的 `HttpClient` 无法正确使用 Windows 证书存储。
  - **影响范围**：所有集成测试均无法在本地 Android 模拟器上构建执行（包括现有的 `app_smoke_test.dart`），因为 Gradle 构建在 `dart_build` 阶段失败。
  - **已验证的缓解方案**：用 PowerShell 的 `Invoke-WebRequest`（使用 Windows 证书存储）预下载 4 个 Android SQLite 库（x64/arm/arm64/ia32）到 `.dart_tool/hooks_runner/shared/sqlite3/build/download-<hash>/libsqlite3.so` 缓存目录后，`flutter build apk --debug` 成功。但 `flutter clean` 会清除缓存，需要重新预下载。
  - **patrol_cli Windows 路径问题**：`patrol_cli` 4.4.0 在 Windows 上生成 `test_bundle.dart` 时，将绝对文件路径（含盘符 `D:`）转换为 Dart 标识符，但 `:` 不是有效的 Dart 标识符字符，导致编译失败。已在本地副本中修复 `_normalizeTestPath` 方法的路径分隔符不匹配问题，但修复后的快照未生效（原因待查）。
- **未解决**：
  - native assets 预缓存在 `flutter clean` 后需要重新执行，非持久化方案。
  - `patrol_cli` 的 Windows 路径修复未生效（可能需要向上游提交 PR）。
  - 集成测试目前仅通过 `flutter analyze` 静态验证，无法在本地运行时验证。
- **后续行动**：
  - 在 CI 环境（Linux）中运行集成测试，不受 Windows TLS 和路径问题影响。
  - 或等待 `sqlite3` 包修复 native assets hook 的下载逻辑（支持本地缓存或编译）。
  - 或向 `patrol_cli` 提交 Windows 路径修复 PR。
