# 2026-10-26

## ci(web): 流水线现场获取 `sqlite3.wasm`，修复 HarmonyOS 构建的产物断言

- **失败形态**：`deploy-harmonyos.yml` 的 `Assert drift worker and sqlite wasm present`
  报 `build/web/sqlite3.wasm 缺失`。`drift_worker.js` 正常（`dart compile js` 生在
  `web/` 再被 `flutter build web` 拷进 `build/web`），缺的只有 wasm。
- **根因是产物来源缺失，不是步骤坏了**：`web/sqlite3.wasm` 被 `.gitignore` 排除，
  而它**不由任何构建步骤产生**——它是 `simolus3/sqlite3.dart` 的 release 资产，
  按 `sqlite3` 包版本发布。以前靠开发者手工下载放进工作区，CI 的全新 checkout
  从来就没有这个文件，于是只有那条断言会红。
- **顺带发现本地产物已经过期**：工作区里那份 wasm 的 sha256 与 **3.3.4** 逐字节吻合，
  而 `pubspec.yaml` 已钉 `sqlite3: 3.7.0`（3.7.0 的发布资产是 750007 字节，
  本地那份是 747018）。说明手工下载这条路必然漂移。
- **改法**：新增 `scripts/web/fetch_sqlite3_wasm.py`，从 `pubspec.yaml` 读**精确版本钉**
  （非精确钉直接报错，避免 CI 下到与解析结果不符的二进制），到该版本的 release 里
  取 `sqlite3.wasm`，并校验 release 公布的 sha256。`GITHUB_TOKEN` 存在时用它，
  规避匿名调用 GitHub API 的按 IP 限流。
- `deploy-harmonyos.yml` 与 `deploy-web.yml` 都在 `Compile drift web worker` 之后加
  `Fetch sqlite3 web assembly`。**Pages 那份同样需要**：它此前一直在缺 wasm 的情况下发布，
  drift worker 起不来，只是没有断言去发现。
- 验证：脚本对 3.7.0 取到 750007 字节、sha256 与 release 一致；
  `web/sqlite3.wasm` 已按新来源重新生成；三个 workflow 的 YAML 均可解析。
