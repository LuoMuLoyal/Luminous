## refactor(record,health_data): 睡眠时段计算抽为领域服务,payload 键位统一为 startedAt/endedAt

### 背景

睡眠 payload 的时间键位在双仓长期不一致：Lucent 的 DTO 文档把 `startedAt` / `endedAt` 定义为正式键、
把 `startAt` / `endAt` 标为 legacy，但 Luminous 的创建页、编辑页、详情页、NLP 候选编辑器反而一直在
写读 legacy 键；服务端校验器则是两者都读（`startedAt ?? startAt`）。同时「就寝 + 起床 → 跨天时段」
这段时钟算术在创建页与编辑页各写了一份。

NLP 候选编辑器另有隐藏缺陷：用户改动时刻后它把值写成 `{hour, minute}` map，而服务端校验要求时间键
是 ISO 字符串，因此该路径保存必然校验失败。

### 变更

- 新增 `lib/features/record/domain/services/sleep_entry.dart`：`SleepEntryKind`（nightSleep / nap 及线上
  取值与解析）、`computeSleepDurationMinutes`、`resolveSleepWindow`（以**起床日**为归属日解析跨天时段，
  夜间睡眠最多跨一个午夜、小睡禁止跨天）、`validateSleepEntry`（缺时刻 / 起床不晚于就寝 / 小睡跨天 /
  小睡 > 3h / 夜间 > 16h）、`buildSleepPayload`（固定键位 `startedAt` / `endedAt` / `durationMinutes` /
  `sleepType`，加可选 `quality` 与设备侧分期）。
- 新增 `lib/features/record/presentation/utils/sleep_formatters.dart`：`sleepQualityOptions`、
  `formatSleepDurationLabel`、`formatSleepTimeRange`，取代原先散在 `sleep_structured_fields.dart` 与两处
  私有 `_formatDuration` 的重复实现。
- 创建页、编辑页改由领域服务构建 payload；详情页、编辑页、NLP 候选编辑器改读 `startedAt` / `endedAt`；
  NLP 候选编辑器改写时输出规范 ISO 时刻，map 形态的表示整体删除。
- 编辑页保留载入记录的 `sleepType`，避免编辑一条小睡时被改回夜间睡眠；只有时长、没有时刻的设备导入
  记录继续走「仅 durationMinutes」的兜底分支。
- `health_sync` 指纹计算去掉 `?? startAt` / `?? endAt` 回退。

### 验证

- `flutter analyze` 无问题。
- `flutter test test/record test/health_data` 全部通过。新增
  `test/record/domain/services/sleep_entry_test.dart`（跨天解析、小睡同日约束、两类时长上限、payload 键位与
  UTC 时刻往返）；原 `test/record/sleep_duration_test.dart` 由该测试取代删除；编辑页保留 duration-only
  payload 的断言更新为同时写入 `sleepType`。

## feat(record): 睡眠快速录入改为一次性录入

### 背景

睡眠快捷入口此前是两阶段状态机：第一次单击落一条 `sleepEvent: 'start'` 临时事实，第二次单击落
`sleepEvent: 'wake'`，再弹「合并」弹窗把两条合成一条完整睡眠；存在多个进行中的 start 时还要先弹「选择要
结束的睡眠」。目标是一次性录入：表单式收集完整信息，落**一条**记录。

调研（Apple Health / Samsung Health / 华为运动健康的手动录入、Sleep as Android 的 `(+) Add sleep`、
Fitbit / Garmin / vivo 的归属日约定）结论：手动录入主流只收「入睡 + 起床」两个时刻、时长算出来；归属日以
**起床日**最常见（Fitbit `dateOfSleep` 取结束日、Garmin 睡眠记起床日、vivo 官方明文）；但没有任何一家在
录入界面写出这条记录到哪天。因此显式写出归属日是本方案的差异化点。

### 变更

- 新增 `presentation/widgets/dialogs/sleep_quick_entry_sheet.dart`：底部 sheet 收集类型（夜间睡眠 / 午睡，
  `FTabs`）、就寝与起床（`FTimeField.picker`）、实时时长、**「记为 X月X日 睡眠」**、睡眠质量、备注；
  校验失败时错误文案贴在时间下方并禁用保存；关闭 sheet 不产生任何记录。
- `application/usecases/quick_entry_sleep.dart` 重写为一次性流程：预填（沿用所选日期或其前一天最近一条睡眠
  记录的类型与时刻，无历史回落到 23:00–07:00；读取失败只记日志、不阻断录入）→ 打开 sheet → 用领域服务
  构建 payload → 落一条记录（`occurredAt` 为归属日、`occurredTime` 为起床时刻）→ 可撤销 toast。
- 删除状态机实现：`presentation/quick_entry/sleep_flow.dart`、`presentation/widgets/dialogs/sleep_merge.dart`，
  以及仅被它们使用的 11 个 l10n key（两片 ARB 同步）。
- 切到「午睡」时若当前时段不合法（跨午夜或超过 3 小时）自动回落到 13:00–13:30。

### 验证

- `flutter analyze` 无问题。
- `flutter test test/record test/settings test/today` 通过。新增
  `test/record/sleep_quick_entry_sheet_test.dart`（归属日文案与时长、午睡时段回落、跨午夜与小睡超时禁用保存、
  备注裁剪）；`test/record/page_test.dart` 的两条睡眠用例改写为一次性录入（落一条完整记录、预填沿用上一条），
  原 `test/record/quick_entry/sleep_flow_test.dart` 删除。

## chore(record): 移除睡眠进行中标记与默认时长偏好

### 背景

一次性录入落地后，两个睡眠专属偏好失去意义：`sleepInProgressBadgeEnabled` 驱动的是「进行中」瓦片徽标，
它依赖「存在一条没有时长的 start 事实」这个已被删除的状态机概念；`sleepDefaultDurationMinutes` 只在
`RecordFastEntryDialog` 的睡眠分支被读取，而睡眠单击早已在 `handleQuickAction` 被拦截走独立流程，该分支
不可达（连同 `kSleepDurationOptions` 与 `recordFastEntryChoicesFor(sleep)` 一起是死代码）。

### 变更

- `QuickEntryPreferences` 删除 `sleepInProgressBadgeEnabled` 与 `sleepDefaultDurationMinutes`（含
  `PrefKeys` 两项、两个 setter、`copyWith` 参数与 `reset()` 清理项）。
- `RecordQuickEntryPanel` 删除 `_sleepBadge`；`QuickEntryTypeSettingsDialog` 删除 `_SleepSettings`，睡眠长按
  回落为规则文案；快速记录设置页删除「默认睡眠时长」选择与「睡眠进行中标记」开关。
- `fast_entry_choices.dart` 删除睡眠分支与 `kSleepDurationOptions`；`RecordFastEntryDialog` 删除
  `_reorderSleepChoices`。
- l10n 删除 5 个死 key（`recordQuickSleepInProgressBadge`、`recordQuickSettingsSleepBadge` /
  `SleepBadgeHint` / `SleepDefaultDuration` / `SleepDurationHours`），并把 `recordQuickSettingsSleepRule`
  文案改为一次性录入的说法。

### 验证

- `flutter analyze` 无问题。
- `flutter test test/record test/settings test/today test/mine` 通过；删除睡眠快捷选项的三条用例与设置页的
  睡眠徽标断言，瓦片徽标用例改为断言「只剩饮水徽标」。
