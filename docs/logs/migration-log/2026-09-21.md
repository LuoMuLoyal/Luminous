# 迁移日志 2026-09-21

## fix(medicine): 药品详情页永久加载态（OpenAPI oneOf 联合被生成客户端吞并）

### 背景

药品详情页（F-14）持续停留在骨架屏，后端日志显示 `GET /api/v1/medicines/:id` 全部
`statusCode=200`、耗时 6–12ms，无任何 5xx 或 4xx。问题不在网络层，也不在后端。

根因在**生成客户端的联合类型处理**：

- 后端 `medicineDetailDataSchema` 把 `detail` 建模为 `z.discriminatedUnion('kind', [...])`，
  导出的 `openapi.json` 是**正确**的 `oneOf`，两个分支各自只要求自己那一族字段
  （`drugbank` 26 个 / `cnProduct` 21 个）。
- `openapi_retrofit_generator` 也**正确**生成了两个变体类
  （`MedicineDetailResponseDetailOneOf` / `...OneOf1`）。
- 但它同时生成了一个联合包装类 `MedicineDetailResponseDetail`，而
  `MedicineDetailResponse.detail` 声明的类型正是这个包装类；该包装类带
  `checked: true`，并把**两个变体共 47 个字段全部标为 required**。
- 真实响应永远只带其中一族，于是包装类的 `fromJson` 对**每一种药品**都抛
  `CheckedFromJsonException`（`drugbank` 缺 21 个 CN 键，`cnProduct` 缺 26 个 DrugBank 键）。
- 该异常在生成方法的 `try/catch` 里被包成 `DioExceptionType.unknown`，经
  `ErrorInterceptor` 映射为 `LucentFailure.unknown`。

已用真实 payload 复现并确认：`DB00945`（drugbank）与 CN 真实 id 均抛
`Required keys are missing: approvalNumber, ... imageUrl`。

### 变更

- `lib/features/medicine/data/datasources/medicine_detail_remote.dart`
  - `fetchDetail` 不再走 `MedicinesApi.getDetail` 的生成解码：改为经注入的 `Dio`
    直接请求（`dio.request`），拿到已解码 JSON 后按 `kind` 判别式分派到对应变体类
    （`cnProduct` → `...OneOf1`，`drugbank` → `...OneOf`），再在内存中组装包装类，
    使 `MedicineDetailMapper` 的既有签名与扁平取值保持不变。
  - 未参与的那一族字段显式填 `null`；`kind` 不在两个已知值时抛 `LucentFailure.unknown`
    而非静默猜测。
  - 构造函数新增 `required Dio dio`。
- `lib/features/medicine/presentation/providers/medicine_detail.dart`
  - 两个 provider 改为注入 `lucentDioClientProvider` 的 `client` 与 `dio`。
- `test/medicine/medicine_detail_remote_test.dart`
  - 重写为透过被 mock 的 `Dio` 回放**真实响应 JSON**（只带单族字段的 `drugbank` 与
    `cnProduct` 载荷），覆盖此前的构造 DTO 式测试盲区——旧测试直接手搓包装类并填满
    47 个字段，因此永远绿。
  - 新增根因断言：`MedicineDetailResponse.fromJson` 对单族载荷必抛
    `CheckedFromJsonException`，防止后续把数据源"简化"回 `api.getDetail`。

### 验证

- 真机端到端（后端运行中）：`DB00945` 解出 `Acetylsalicylic acid` + 30 个 targets；
  CN 搜索取真实 id 解出 `复方忍冬藤阿司匹林片` + 批准文号，两者此前均抛异常。
- `/medicines/:id/sequences` 复核**未受影响**（该响应无联合），无需改动。
- `flutter analyze` 全仓 0 issue；`flutter test test/medicine/` 全绿；
  `tool/luminous_lints` 对改动文件 0 告警。

### 后续

生成器层面的联合分派缺陷（包装类吞并 `oneOf`）仍是上游问题：本修复在数据源显式绕开，
未改生成物。若后续引入其他 `oneOf` 响应端点，需按同样方式评估。
