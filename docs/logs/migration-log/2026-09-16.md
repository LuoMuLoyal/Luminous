## fix(network): 对象存储直传失败按存储侧语义分类

（修复计划 `plans/2026-09-15-review-remediation-plan.md` §3-1。）

### 变更

`putPresignedObject` 此前只把 `DioException` 原样抛出，交给集中错误 mapper 归类。但对象存储回的是
自家 XML/HTML 错误体，不是 RFC 9457 `application/problem+json`——mapper 的 `_fromProblemResponse`
会直接抛 `FormatException`，结果是**每一个**存储侧失败都被降级成 `unknown`，既看不出是链接过期还是
网络断了，也无法据此提示用户重试。

- `core/network/client/object_upload.dart`：PUT 包 try/catch，失败时薄分类——
  403 → business（签名 URL 过期/签名不匹配，这是链接的正常终点，标 `retryable: true` 并带上状态码，
  可提示「链接已过期请重试」）；其它有响应 → server；无响应 → network。traceId 一路带出，
  与 Lucent 请求的排障口径一致。
- `core/network/contract/error_mapper.dart`：`_errorCodeFromDioType` 提升为公开的
  `errorCodeFromDioType`，让存储侧分类复用同一套连通性错误码词汇，而不是另造一份。
- `core/network/README.md`：补陷阱说明——存储侧错误不经集中 mapper，PUT 自带分类。
- `test/core/network/object_upload_test.dart`：补四条用例——403 为可重试的 business 类并带状态码、
  其它 HTTP 错误为 server 类、无响应的传输错误为 network 类且错误码正确、traceId 透传。

### 验证

- `flutter analyze` 无问题；`flutter test test/core/network test/record test/scan` 全绿
  （另两条直传链路：头像与记录图片上传共用本函数，一并覆盖）。

## fix(health_context): 快照缓存反序列化容忍错类型字段

（修复计划 `plans/2026-09-15-review-remediation-plan.md` §3-2。）

### 变更

快照缓存的反序列化对多个字段用硬 cast（`as String?`、`as double?`、`List.cast<String>()`）。
缓存行由旧版本写入、或只是单纯损坏时，只要有一个字段类型对不上，整份快照就抛
`TypeError`——而它只是缓存，网络上的正确数据就在旁边，却会连带整个 `fetchHealthContext`
失败。`List.cast<String>()` 还更隐蔽：它是惰性转换，异常抛在元素首次访问处，离越界的那条
数据很远。

- `data/utils/health_context_snapshot_codec.dart`：标量读取改走 `_asString` / `_asInt` /
  `_asDouble`，类型不符即丢该字段（`_asDouble` 接受 `num`，因为 JSON 不区分 `170` 与
  `170.0`）；列表读取改走 `_asStringList`，逐元素判定、非字符串丢弃、非字符串但可
  字符串化的保留。文档注释写明这是有意的降级：丢字段后调用方会重新拉取并回写缓存行。
- 集合元素的 `as Map<String, dynamic>` 保持不变——那是快照自身结构，不是缓存陈旧问题。

### 验证

- 新增 `test/health_context/health_context_snapshot_codec_test.dart`：整份快照 round-trip
  保真，加上错类型字符串丢弃、整数接受为 double、错类型数值丢弃、列表元素混合类型、
  字段缺失、summary 字段错类型共六条容错用例。
- 反向验证：临时把 `activityLevel` / `heightCm` 还原成硬 cast，新用例如期以
  `type 'int' is not a subtype of type 'String?'` 等失败；恢复后全绿。
- `flutter analyze` 无问题；`flutter test test/health_context test/core/database test/mine`
  全绿。

## fix(settings): 身高体重滚轮的越界取值回写边界值

（修复计划 `plans/2026-09-15-review-remediation-plan.md` §3-1。）

### 变更

身高/体重 sheet 的滚轮把初始值 clamp 进边界,但只改了**显示的滚轮索引**,没有改那个承载提交值
的对象。于是旧数据越界时(如身高 260cm 超过滚轮 250 上限),用户不动滚轮直接点确认,越界值会被
原样回写——clamp 成了纯显示层的假象。

- `presentation/widgets/shared/quantity_sheet.dart`:两处 `_initialIndexes` 在 clamp 命中时把
  边界值同步写回承载提交值的对象(身高写回 cm,体重写回 kg)。
- 回写条件刻意收紧为「真的越界」而非「与取值不一致」:滚轮按整数取值,若无条件回写,光是打开
  sheet 就会静默改写用户当前值——体重 60kg 会变成 132lb 折回的 59.87kg,比原来的 bug 更隐蔽。
- 给两个 late final 索引字段补注释:`imperial` 在 sheet 打开后视为不可变,要支持中途切换需走
  `didUpdateWidget` 重建,而不是就地改 late final。
- `lib/features/settings/README.md`:把这条双向约束(clamp 命中要回写、非越界不得回写)写进
  陷阱与决策。

### 验证

- 新增 `test/settings/quantity_sheet_test.dart`:公制/英制各覆盖「范围内不被改写」与
  「越界被收敛到边界」,另含英制范围内体重不被改写这条防回归用例。
- 反向验证:临时去掉回写,新用例如期以 `Expected: <250> Actual: <260.0>` 与
  `Expected: <50> Actual: <10.0>` 失败;恢复后全绿。
- `flutter analyze` 无问题；`flutter test test/settings test/health_context` 全绿。

## fix(record): 症状「其它」离开输入态时清空已输入的草稿

（来源：`plans/Luminous-review-09-15.md` 问题 4。）

### 变更

症状快录 sheet 的「其它」是就地展开输入框：点「其它」展开、填名称、保存。但按 Back 回到
症状列表时只把输入态标志置回 false，`_otherController` 里的文字原样留着——再次点开「其它」，
上一次的草稿还在，用户要先手动删干净才能填这次想填的名称（且此时「保存」是可点的，容易
误存上一次的内容）。

- `presentation/widgets/dialogs/symptom_quick_entry_sheet.dart`：「其它」的 Back 与退出多选
  (`_exitMultiSelect`) 两处离开输入态时一并 `_otherController.clear()`。两处都清而不是只清
  Back：多选退回单选同样会离开输入态，只修一处会留下同一个坑的另一半。

### 验证

- `test/record/symptom_quick_entry_sheet_test.dart` 补两条用例：Back 后重开草稿为空且保存置灰；
  进出多选后重开草稿为空。
- 反向验证：临时删掉 Back 分支的 clear，新用例如期失败；恢复后全绿。

## perf(record): 餐食确认对话框只在按钮可点状态翻转时重建

（来源：`plans/Luminous-review-09-15.md` 问题 5。）

### 变更

餐食确认对话框的三个输入框都注册了同一个监听，任何一次文本变化都 `setState(() {})`
重建整棵对话框（含图片、按钮、底部栏）。中文输入法选词期间每个字符都会通知一次，
而这条路径又是每个快录餐食的必经之路。

- `presentation/widgets/dialogs/meal_confirmation.dart`：监听里先比较确认按钮的可点状态，
  只在翻转（空↔非空、或保存中↔可用）时重建。可点状态由输入内容与 `_saving` 共同决定，
  因此 `_saving` 的三处写入统一走 `_setSaving`，让重建缓存始终与实际状态一致。

### 验证

- `test/record/presentation/widgets/dialogs/meal_confirmation_test.dart` 补一条持续输入
  （可点状态不变）后提交仍取到最新文本的用例；既有的「清空预填字段后置灰」「失败保留弹窗」
  等用例覆盖了每次翻转。
- 说明：我另外写了一条「保存失败后清空字段」的用例想锁 `_saving` 与缓存的交互，但实测
  在移除缓存同步后它**仍然通过**——说明该脱节路径在当前实现下不可达（`setState` 本身
  已重建该帧）。这条无法证伪的用例已删除，不保留虚假覆盖。
- `flutter analyze` 无问题；`flutter test test/record` 全绿。
