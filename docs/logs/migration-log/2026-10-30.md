# 2026-10-30

## feat(customizer): 布局本地持久化生效，编排页接入并改为点标题进入

### 布局真的生效了

- 新增 `lib/features/customizer/application/layout_store.dart`：
  - `layoutRepositoryProvider`（`CachedLayoutRepository` 装配点，放在 application 层，
    让 presentation 不必 import `data/`）；
  - `surfaceLayoutsProvider`（`AsyncNotifier`，非 autoDispose）：cache-first 读，读到什么
    就用什么；读取失败回退「没有任何自定义」而不是让整页报错；
  - `commit(draft)`：先更新状态（页面立刻重排），再逐 surface 落盘，失败不回滚；
  - `storedSurfaceLayoutProvider`：用户布局优先，缺省才是 `defaultLayout`。
- 组合根（`lib/app/composition/components/registry.dart`）用它覆盖
  `core/composition/surface.dart` 的 `surfaceLayoutProvider`，`ComponentHost`
  不改一行即按用户布局渲染。此前该 provider 永远返回默认布局，编排结果不会改变页面。
- `commitDraft` 有了真实调用点：编排页「完成」写入后返回。

### 编排页接入

- 新增路由 `/customize/:surface`（`@TypedGoRoute`，`features/customizer/presentation/routes.dart`），
  一个路由服务五个 surface；桌面走侧面板，窄屏走滑入页。
- 入口在 tab 页**标题本身**：新增 `core/widgets/common/control/surface_title_button.dart`
  （`SurfaceTitleButton` + `SurfaceTitleEntry`），标题变成带编辑图标的 `FButton`，
  点一下进入「这一页」的编排页。五个 tab 的移动端顶栏与桌面 `DesktopTabShell`
  （新增 `titleSurface` 参数）全部换用。
- 路由能力经 `core/composition` 新增的 `surfaceCustomizerOpenerProvider` 注入
  （typedef `SurfaceCustomizerOpener`），由组合根安装
  `features/customizer/presentation/widgets/title/entry.dart` 的 `openSurfaceCustomizer`：
  五个 tab 与 `core/` 都不 import customizer，避免新增跨 feature 依赖；
  未注入时标题退化为纯文本，不假装可点。
- 编排页改写：surface 由路由传入（不再由调用方塞 `catalog`/`onDone`）；
  「恢复默认 / 完成」改为图标按钮 + tooltip；「移除」改为图标按钮；
  最后一项不可移除（编辑器不提供全空状态）。
- 跨 tab 面板改为列出**当前 surface 可挂但未挂**的组件（即该表的未挂载池），
  点一下或拖入即加回——此前列出的是所有 surface 的组件，加入会被
  `SurfaceAction.add` 静默拒绝，表现为「点了没反应」。
