### 修掉的 API 偏差

按文档写的调用与 `llama-cpp-2` 0.1.161 的真实 API 有系统性差异，24 个编译错误：

| 文档/我以为的 | 实际的 |
| --- | --- |
| `AddBos` 枚举 | 不存在，`tokenize(bytes, add_special, parse_special)` |
| `model.str_to_token()` | `model.vocab().tokenize()` |
| `model.is_eog_token()` | `vocab.is_eog()` |
| `token_to_piece(t, cb)` → `&str` | `token_to_piece(t, special, lstrip)` → `Vec<u8>` |
| `chain.with_sampler(s)` 链式 | 先把 sampler 收进 `Vec`，再 `chain_simple(vec)` |
| `penalties(last_n, repeat, f, p)` | 5 参，第一个是 `n_vocab` |
| `n_embd()` → `u32` | 返回 `c_int` |

`token_to_piece` 返回 `Vec<u8>` 这条尤其要紧：一个 token 可能是半个 UTF-8 字符，
按 `&str` 处理会在中文或 emoji 上切出乱码。

### codegen 的三个坑

- **看不透类型别名**：`type LlamaResult<T> = Result<T, LlamaError>` 被当成不透明句柄，
  生成的 Dart 完全无法读取值或错误。签名要写全 `Result<T, LlamaError>`。
- **`StreamSink` 在生成之前不存在**：所以先把 `generate` 写成纯 Rust 回调，让 crate
  能独立编译、单独验证 llama.cpp 集成，再换成 `StreamSink`。这个顺序让「集成是否可用」
  和「桥接是否正确」两个问题不会同时爆炸。
- **`mod frb_generated;` 被注入到文件顶端**，即 `//!` 文档注释之前，触发 `E0753`。
  每次都覆盖，所以每次生成后都要手动把它移到模块组里。已写进包 README。

### 测试抓到的真 bug

`LlamaError::kind()` 返回 `backendUnavailable`，而 `Display` 写的是
`BackendUnavailable`。bridge 没有类型化错误通道，Dart 靠把文本转小写后匹配恢复 kind，
两个名字必须严格一致。已把 `Display` 改成复用 `kind()`，两处拼写不会再分叉。

## feat(ai): 模型清单改由 GitHub Release 提供，cargokit 打包原生库，接线完成

上一轮遗留的三件事本轮做完：模型来源、原生库打包、app 接线。

### 模型清单从 release 读，不再由代码写死

原来的做法是在代码里维护 `availableLocalModels` 常量，需要手工填 SHA-256。**那个哈希不可能由
写代码的人算出来**——它必须匹配 host 上将要被分发的那份字节，抄错一个字符就是「每次下载都
校验失败」，而放宽校验等于取消校验。

改成：release 里发布一份 `manifest.json`，同时携带 `downloadUrl` 与 `sha256`。App 读
manifest、按它下载、用它自带的摘要校验。**URL 与哈希同源**，不会出现两者不一致。

配套的三个约束：

- **tag 固定为 `v1`**，不浮动。浮动 tag 会让未来一次上传在没有任何客户端改动的情况下
  改变 app 实际运行的权重——那正是摘要校验存在的目的。
- **摘要格式在解析期就校验**（64 位十六进制）。截断的哈希会与所有文件不等，最后报成
  「完整性失败」，把用户引去怀疑网络而不是 manifest。
- **manifest 解析失败时回落而不是崩**，但 `LocalModel.fromJson` 本身对缺字段抛
  `FormatException`：一个字段缺失的条目会在下载阶段失败，那时错误信息远不如解析期有用。

### 原生库打包用 cargokit

`flutter_rust_bridge_codegen integrate` 生成了五端原生工程与 `cargokit/`，构建期按目标平台
跑 `cargo build` 并把产物拷进 bundle。**不提交二进制**：本仓能提交的只有 Windows DLL，
而 app 还要 Android / iOS / macOS / Linux，每个都要自己的 ABI——一端提交二进制、其余从源码
构建会让每个开发者的集成状态各不相同。

`integrate` 有两处副作用需要留意，都已处理：

- 它把 `lib/llama_native.dart` 的 barrel 整个注释掉换成模板 demo，已恢复。
- 它额外生成了 `rust/src/api/`（模板 demo 的 `simple.rs`）与 `lib/src/rust/`，与我们真实
  的 `rust/src/api.rs`、`lib/src/data/ffi/` 重名并存，已删除。
- 它顺带改写了 `pkgs/paddle_ocr_native-0.1.1/pubspec.lock`（`clock` / `listen` 版本漂移），
  与本次改动无关，已回滚。

### 接线

`lib/core/ai/local_assistant.dart` 是门面：manifest 说有哪些模型、store 持有校验过的字节、
engine 要一个路径。三者各自可测，但单独都没用，这层把它们接起来，让 UI 面对的是「加载助手」
而不是三个协作者。

`LocalAssistant.load` **显式**：模型是几 GB 常驻内存，不该因为打开了设置页就加载。

`modelStore` / `modelManifestSource` / `localAssistant` 三个 provider，后者 `keepAlive`
——引擎持有数 GB 内存，随依赖重建会反复重载模型。
