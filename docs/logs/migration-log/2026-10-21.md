## refactor(sync): flush 返回同步结果摘要

- `SyncWorker.flush()` 从 `Future<void>` 改为 `Future<SyncFlushResult>`,汇总本次
  成功、可重试失败、永久失败与仍待处理数量;队列读取失败时通过 `error` 报告并
  视为可重试。
- 单条重放改为返回内部结果枚举,永久失败分支不再依赖日志推断;并发 flush 返回空
  摘要。
- 更新同步失败页/横幅的 mock,并补充摘要与中断场景测试。
- 验证:`flutter test test/core/database/sync/worker_test.dart` 与相关页面测试通过。

## feat(sync): 接入后台同步

- 引入 `workmanager ^0.10.10`;`main()` 在移动端初始化 callback dispatcher。
- `background_entry.dart` 提供 `@pragma('vm:entry-point')` 入口:构建最小
  `ProviderContainer`,无持久会话时直接成功退出;有会话时用覆盖后的
  `syncWorkerProvider`(不启动 connectivity 监听)执行一次 `flush()`,按
  `SyncFlushResult.shouldRetry` 返回成功/重试。
- `handlers.dart` 抽出前后台共用的 handler 注册;后台容器通过 override 把
  handler 注册到专用 worker。
- `background.dart` 提供 `BackgroundSyncScheduler`:Android 使用
  `registerPeriodicTask`(15 分钟、网络约束、`update` 策略);iOS 使用
  `registerProcessingTask`,每次执行后在入口重新排下一次。
- 登录/恢复会话后调度,登出取消;iOS 增加 `UIBackgroundModes: processing`、
  `BGTaskSchedulerPermittedIdentifiers`,AppDelegate 注册 launch handlers 与
  plugin registrant。
- 验证:`flutter analyze`、后台入口/worker 单测、`flutter build apk --debug`
  通过;模拟器中一次性任务进入 `BackgroundWorker` 并返回 `SUCCESS`,`jobscheduler`
  记录任务启动与 `jobFinished`。未登录场景按设计直接退出,真实 flush 与杀进程后
  的 headless 调度仍需真机/后端验证;iOS 后台任务需 macOS/真机触发验证。
