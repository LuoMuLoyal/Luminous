# 2026-10-23

## docs(plans): 放弃 Flutter 鸿蒙适配，转向 ArkTS + ArkWeb 壳方案

- **放弃的是「用鸿蒙 Flutter SDK 直接适配 Luminous」这条路线**，不是放弃鸿蒙平台。
  原计划 `plans/2026-10-22-harmonyos-ohos-adaptation-plan.md` 已删除，索引同步移除。
- 放弃原因是**上游包不兼容，不是本项目代码问题**。鸿蒙 Flutter SDK
  （`3.47.7-ohos-1.0.1`）的 `TargetPlatform` 枚举新增了 `ohos` 值，使所有未覆盖该值的
  `switch` 穷尽性检查失败。实测 `flutter assemble` 阶段报错 **35 处，分布在 6 个包**：
  - `cupertino_ui`（16 处）、`material_ui`（11 处）—— **Flutter 官方把 material/cupertino
    拆出的包，官方版不支持 `ohos`**，这是最致命的一条，无法靠项目侧打补丁绕过；
  - `flutter_math_fork`（4 处）、`forui`（2 处，本项目全部 UI 的设计系统）、
    `gpt_markdown`（1 处）、`flutter_gen_ai_chat_ui`（间接）。
- 另有 `Abi.ohosArm` 在 Dart SDK 的 `dart:ffi` 中缺失（`code_assets` /
  `native_toolchain_c` 需要定制 Dart SDK 才能编译），属同类问题的另一面。
- 工具链本身是通的，本次已逐个解决并验证：鸿蒙 SDK 产物下载（gitcode CDN 不可达，
  改走华为云 OBS）、DevEco Studio 26.0.0（API 26）识别、`[√] HarmonyOS toolchain`、
  Windows 跨盘符导致 hvigor 拒绝绝对 `srcPath`（pub cache 与 FVM cache 均迁到 D 盘）、
  FVM junction 使 hvigor 解析不到 `integration_test/ohos`（改为真实目录拷贝）、
  脚手架模板 `targetSdkVersion: "1"` 不合法（改 `26.0.0`）。**卡点最终收敛在上游包，
  与工具链配置无关**。
- 结论：该路线要成立，需等 `material_ui` / `cupertino_ui` / `forui` 等上游包适配
  `TargetPlatform.ohos`，短期不可控。
- **新方向**：ArkTS 壳 + ArkWeb（`Web` 组件）渲染 Luminous Web 构建产物，绕开
  `TargetPlatform` 问题。仓库此前已为此铺路（见下），不是从零开始。
- **两条约束后来被推翻**（评审时确认，原计划写得过紧）：
  1. **「Dart 代码零改动」取消**。改为「允许改 Dart 补接缝」，判断标准是「改了是否让
     Web 版也一起受益」——若是（如把 `Uri.base` 换成可注入的 origin）就改；只为鸿蒙开
     特例分支则优先降级。理由：零改动会把 §5.3 的 OAuth 回调、B-6 的安全存储桥等
     真实需求堵死，而这些需求本可以顺带改善 Web 版。
  2. **「独立仓库」取消，改为同仓 `Luminous/ohos/`**。决定性依据是仓内已有同类先例：
     `native/` 就是异构工具链（Gradle/Kotlin）的子工程，自带 `.gitignore`、有自己的
     README、CI 已覆盖（`.github/workflows/ci.yml:47-54` 的 Gradle 缓存与 `:99-102`
     的 host 测试）。同仓省掉整条跨仓制品通道（Web 产物直接从 `build/web` 拷进
     `ohos/entry/src/main/resources/rawfile/web/`），且构建参数不会漂移。
     代价是必须盯住「Web 产物（数十 MB）不进 git」，用 `ohos/.gitignore` + CI 的
     `git check-ignore` 断言处理。
- 清理范围：
  - `Luminous-ohos` worktree 与 `ohos` 分支（分支内容为脚手架与 FVM 配置，无独有代码）；
  - `plans/2026-10-22-harmonyos-ohos-adaptation-plan.md` 与索引行；
  - 临时调研产物 `outputs/ohos-survey/`；
  - **FVM 整体回退**（`git revert bfcac85c`）：删 `.fvmrc`、`.gitignore` 的 `.fvm/` 条目、
    `.vscode/settings.json` 的 `dart.flutterSdkPath`。FVM 是为鸿蒙双 SDK 共存而引入的，
    鸿蒙路线放弃后不再需要，避免给 `flutter` 命令加一层间接。
  - 本机环境：删 `D:\flutter-ohos`、`D:\fvm-cache`、`D:\pub-cache`（合计约 3.4 GB）、
    FVM 可执行与全局设置、用户 PATH 中的 FVM 条目；`~/.flutter_settings` 移除
    `ohos-sdk` / `enable-ohos` 两项。**主 SDK `D:\flutter` 未受影响**。
- 保留：`pubspec.lock` 中的 `flutter_image_compress_ohos`（自 2026-07-13 `feat(image)` 起的
  既有传递依赖，与本次适配无关，不要误删）。
- 注意：删除 `D:\fvm-cache` 前必须先 `rmdir` 掉其中指向 `D:\flutter` 的 junction
  `versions\3.47.7`——否则递归删除会连带删掉主 Flutter SDK。
