## docs(plans): 放弃 Flutter 鸿蒙适配，转向 ArkTS + ArkWeb 壳方案

- **放弃的是「用鸿蒙 Flutter SDK 直接适配 Luminous」这条路线**，不是放弃鸿蒙平台。
  原计划 `plans/2026-10-22-harmonyos-ohos-adaptation-plan.md` 已删除，索引同步移除。
- 放弃原因是**上游包不兼容，不是本项目代码问题**。鸿蒙 Flutter SDK
  （`3.47.7-ohos-1.0.1`）的 `TargetPlatform` 枚举新增了 `ohos` 值，使所有未覆盖该值的
  `switch` 穷尽性检查失败。实测 `flutter assemble` 阶段报错 **35 处，分布在 6 个包**：
  - `cupertino_ui`（16 处）、`material_ui`（11 处）—— **Flutter 官方把 material/cupertino
    拆出的包，官方版不支持 `ohos`**，这是最致命的一条，无法靠项目侧打补丁绕过；
  - `flutter_math_fork`（4 处）、`forui`（2 处，本项目全部 UI 的设计系统）、
    `gpt_markdown`（1 处）、`flutter_gen_ai_chat_ui`（间接）。
- 另有 `Abi.ohosArm` 在 Dart SDK 的 `dart:ffi` 中缺失（`code_assets` /
  `native_toolchain_c` 需要定制 Dart SDK 才能编译），属同类问题的另一面。
- 工具链本身是通的，本次已逐个解决并验证：鸿蒙 SDK 产物下载（gitcode CDN 不可达，
  改走华为云 OBS）、DevEco Studio 26.0.0（API 26）识别、`[√] HarmonyOS toolchain`、
  Windows 跨盘符导致 hvigor 拒绝绝对 `srcPath`（pub cache 与 FVM cache 均迁到 D 盘）、
  FVM junction 使 hvigor 解析不到 `integration_test/ohos`（改为真实目录拷贝）、
  脚手架模板 `targetSdkVersion: "1"` 不合法（改 `26.0.0`）。**卡点最终收敛在上游包，
  与工具链配置无关**。
- 结论：该路线要成立，需等 `material_ui` / `cupertino_ui` / `forui` 等上游包适配
  `TargetPlatform.ohos`，短期不可控。

  `TargetPlatform` 问题。仓库此前已为此铺路（见下），不是从零开始。

## feat(ohos): ArkWeb 容器跑通 Luminous Web，补构建与字体脚本

- 新增 `ohos/entry/src/main/ets/pages/Index.ets`（ArkTS 侧 Web 容器）与
  `scripts/ohos/` 下三个 Python 脚本（`build_hap` / `install_hap` /
  `fetch_fallback_fonts`）。**没有改 `lib/` 任何 Dart 代码**——能力差异全走已有的
  Web 分支。
- **首次在鸿蒙模拟器（API 26）上跑通完整 UI**：五 tab 壳、首页卡片、中文文案、
  图标全部正常渲染。
- 过程中确认了五条硬事实（都写进了代码注释，避免后人重踩）：

  1. **`resource://` 协议不支持 `fetch()` / 动态 `import()`**，只支持
     `<script src>` 这类简单加载。因此 `$rawfile('index.html')` 能打开页面，但
     `flutter_bootstrap.js`、`canvaskit.wasm`、`main.dart.js` 全部
     `ERR_FILE_NOT_FOUND` 或被 CORS 拦。**解法**：自建一个自定义域名
     （`https://luminous.local`）+ `onInterceptRequest` 把请求换成 rawfile 内容
     （官方 `web-cross-origin.md` 给出的做法）。
  2. **Web 产物必须平铺到 rawfile 根，不能放 `rawfile/web/` 子目录**：
     `resource://` 不认 `<base href>`，一律以 rawfile 根为基准解析相对路径。
     放子目录时 `index.html` 能加载而同目录的其它资源 404。
  3. **不能对二进制资源调 `setResponseEncoding('utf-8')`**：会给 `.wasm` 套上文本
     编码，报 `WebAssembly: Incorrect response MIME type. Expected
     'application/wasm'`。现在只对 `text/*`、`application/json`、`image/svg+xml`
     设编码。
  4. **`LUCENT_BASE_URL` 在 release 构建里是必填的**：
     `lib/core/network/client/base_url.dart` 的 `configured` getter 在
     `kReleaseMode` 且未配置时抛 `StateError`，表现为应用卡在启动页、console 里
     只有一句 `ProviderException: Tried to use a provider that is in error state.`
     `build_hap.py` 现在缺省回落到 `http://10.0.2.2:3000`（模拟器访问宿主机）并打印
     提醒，出正式包必须显式传 `LUCENT_BASE_URL`。
  5. **CJK 字体必须同源**：Flutter Web 的中文字形不在构建产物里，引擎运行时按需从
     `https://fonts.gstatic.com/s/` 拉 woff2 切片；国内网络/无网都拉不到，表现是
     文字全变方块（口口口）。解法是把 `fontFallbackBaseUrl` 设成
     **壳自身的 origin**（`https://luminous.local/fonts/`）——不能用相对路径
     （引擎会拼出无效 URL），也不能留 gstatic（跨域 fetch 被 CORS 拦）。切片由
     `fetch_fallback_fonts.py` 下载进 rawfile，再由同一个 `onInterceptRequest` 提供。

- **模拟器实测请求的是 `notosanstc`（繁体）而不是 `notosanssc`**（系统语言决定），
  所以四个 CJK 家族（`notosanssc` / `notosanstc` / `notosanshk` / `notosansjp` /
  `notosanskr` / `notosans`）都下载，共 564 个 woff2 / 12 MB。
- 改 `web/flutter_bootstrap.js`：给 `initializeEngine` 加 `fontFallbackBaseUrl`
  指向 `https://luminous.local/fonts/`。该文件是壳与 Web 版共用的，浏览器下这个
  路径不存在、字体回退失败，**与引入该配置前的行为一致**，不影响 GitHub Pages。
- `.gitignore`（`ohos/.gitignore`）忽略 `**/resources/rawfile/`：Web 产物（54 MB）
  与字体切片（12 MB）都由脚本按需生成，不入库。
- 验证：`python scripts/ohos/build_hap.py` 出包 66.4 MB；`install_hap.py` 装进
  模拟器并拉起；截图确认 UI 与中文正常。`git status` 干净，
  `rawfile/` 下 749 个生成文件均被忽略。
