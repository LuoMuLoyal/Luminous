# 迁移日志 2026-09-30

## fix(contract): bootstrap 在全新 clone 上可用 + 消除平台注册文件的行尾抖动

### 背景

两处长期存在、但都被当作「本机环境问题」忽略的摩擦，实测后确认都是仓库自身的缺陷。

### 一、`bootstrap.dart` 在全新 clone 上必然失败

`AGENTS.md` 明确写着 `dart run scripts/contract/bootstrap.dart` 适用于「全新 clone/ARB/契约
变更后」且「includes the merge + gen-l10n + build_runner」，但它**并不包含 merge**——
`lib/l10n/app_{zh,en}.arb` 是合并产物且被 gitignore，全新 clone 只有 `lib/l10n/src/`，
于是：

```
Generating synthetic localizations package failed with 1 error:
Error: The 'template-arb-file', LocalFile: '...\lib\l10n\app_zh.arb', does not exist.
```

**失败点不在 `gen-l10n`，而在更早的 `flutter pub get`**——该命令会跑 Flutter 的
synthetic localizations 步骤，同样需要合并后的 ARB。所以修复位置是
`bootstrapGeneratedSources` 开头、`flutter pub get` **之前**加上合并步骤，而不是
放进 `_buildAppCodegen`（我先后者试过，症状不变，因为失败时间点更早）。

`arb_tools.dart merge` 实测幂等（重复执行产物哈希不变），故无条件执行是安全的。

### 二、五个平台注册文件在每次 `flutter pub get` 后都「被修改」

`git status` 常驻五个 modified：`linux/flutter/generated_plugins.cmake`、
`linux/flutter/generated_plugin_registrant.cc`、`windows/flutter/` 同名两个、
`macos/Flutter/GeneratedPluginRegistrant.swift`。

排查结论：**内容逐字节相同，只有行尾不同**（`git diff --numstat` 为空、
`--ignore-cr-at-eol` 无输出；剥掉 CR 后与索引内容完全一致）。成因是 `.gitattributes`
里 `* text=auto` + 本机 `core.autocrlf=true`：这些文件在索引里以 CRLF 存储、按 CRLF
检出，而 Flutter 每次都用 LF 重新生成它们——没有专门规则，就永远对不上。

修复：在 `.gitattributes` 为这五个文件钉 `text eol=lf`（与仓库既有的
`*.dart`/`*.json` 等 LF 约定一致），再 `git add --renormalize` 让索引与工作区一致。
**索引内容零变更**（纯行尾规范化），随后 `flutter pub get` 不再产生任何 diff。

### 验证

- 模拟全新 clone（删掉合并后的 `app_{zh,en}.arb`）后 `dart run scripts/contract/bootstrap.dart`
  **exit 0**；跑完后工作区除本文件与 `bootstrap.dart` 外无残留 diff。
- `flutter analyze` 无问题；`flutter test` 全通过；`tool/luminous_lints` 49 项测试通过。
- 明确记录一项**既有、与本次无关**的门禁失败：`dart run scripts/docs/verify.dart --verify`
  报 `docs/reference/Glossary.md: unreferenced`。经 stash 对比确认在未改动的树上同样失败
  （该文件自 2026-09-01 起未再修改），故未在本次一并处理。

## fix(docs): 修复 POSIX 路径归一化导致 CI 三处失败，并修好 Glossary 失效链接

上一条记录末尾悬置的 `Glossary.md` 未引用问题已随本节一并处理；此处同时记录用 `gh` 核查
CI 后发现并修复的三处失败。

### 一、CI 三处失败的确切原因（`luminous-ci`，main，run 36410889133）

该次运行 `3827 tests passed, 3 failed`。3 处失败**都由同一个缺陷引起**：

- `test/scripts/docs_links_test.dart` 两例：链接被判为「no matching file」
- `test/health_data/mapper_test.dart` 一例：时区断言

**（1）POSIX 绝对路径被剥掉前导斜杠（真实缺陷，非仅测试问题）**

`_normalizePath` 逐段组装路径时，空段（含前导 `/` 产生的首段）一律丢弃，于是
`/tmp/vault/a.md` 变成 `tmp/vault/a.md`；而 `resolveRelativeLink` 的 vault 归属判定是
`normalized.startsWith('$base/')`，`base` 来自 `docsDir.path`（POSIX 下**带**前导斜杠）。
两侧形状不一致 → 判定失败 → 所有 vault 相对链接都被报成断链。

Windows 因为绝对路径形如 `C:/...`（本就无前导斜杠）而恰好不受影响，所以本地全绿、CI 全红。
**这不只是测试环境差异**：在 Linux/macOS 上 `docs:links` 会把每一个 vault 相对链接都误报，
本地开发与 pre-push 都会踩到。

修复：归一化时保留前导分隔符。为能在任意平台钉住该行为（Windows 永远走不到这个分支），
把归一化以 `normalizeDocPath` 暴露出来并单独断言 POSIX 形状——**该断言在还原修复后确实失败**
（已验证），而仅靠临时目录的端到端断言在 Windows 上是空转的。

**（2）时区相关断言**

`mapToCreateInput` 对睡眠区间调用 `toUtc()`，而用例把期望值硬编码为
`2026-07-13T05:00:00.000Z`——这是 UTC+8 机器上的结果；CI 跑 UTC，实际得
`13:00:00.000Z`。生产代码正确，**是用例写了与机器时区绑定的字面量**。
改为由同一批本地输入经 `toUtc()` 推导，跨时区稳定。

### 二、`Glossary.md` 未引用 —— 实为大小写不匹配的失效链接

并非「文档没人引用」，而是 `docs/README.md` 链到 `reference/glossary.md`（小写），
而 git 跟踪的实际文件名是 `reference/Glossary.md`（大写 G）。Windows 文件系统大小写不敏感，
本地看不出问题；Linux 上该链接是断的，`--verify` 也因此认为 `Glossary.md` 无人引用。
按实际文件名修链接即可，`docs:verify` 随之通过。

### 验证

- `flutter analyze` 无问题；`flutter test` 全通过；`dart run scripts/docs/verify.dart --verify`
  与 `dart run scripts/docs/links.dart` 均通过（后者曾因上述缺陷在 Linux 上误报）。
- 新增的 POSIX 归一化断言经「还原修复 → 用例失败 → 恢复修复 → 用例通过」双向验证，
  确认它真能拦住该回归，而不是在 Windows 上空转。
