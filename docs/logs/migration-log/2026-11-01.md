# 2026-11-01

## feat(generative): finding 改用后端稳定 id 作为引用键

### 为什么

生成式 UI 的 `finding` item 只接受 `findingId`，agent 只能选展示哪一条，文案由
后端原文透传。A7a 阶段后端 findings 没有稳定 id，客户端先用 `ReviewInsightKind.name`
对齐；Lucent 现已给 `ReportFindingDto` 加上 `id`（稳定规则标识），本次改为用真实 id。

### 落地

- `features/review/domain/entities/dashboard.dart`：`ReviewFinding` 增加 `id`。
- `features/review/data/repositories/lucent_dashboard.dart`：映射后端 `dto.id`。
- `features/generative/domain/services/item_catalog.dart`：新增
  `generativeFindingIds` 词表（`hydration_low` / `medication_stable` /
  `sleep_insufficient`），与后端 `FINDING_IDS` 一一对应。
- `app/composition/generative/catalog.dart`：`_FindingSlot` 按 `finding.id` 查找，
  不再拿 `kind.name` 比对。
- `features/generative/presentation/providers/surface_state.dart`：`DataScope`
  补上 finding 条目。

### 顺带修掉一个 A7a 遗留的真 bug

`findingPolicy` 把 `findingId` 声明为 `DataScopeKind.finding` 的引用键，准入要求
引用值存在于 scope 里，但 `generativeDataScopeProvider` **从未声明过 finding 条目**。
结果是任何合法的 `finding` 组件都会被判「引用了不存在的 id」，整次生成失败。本次
补上该条目后，真实 id 才能通过准入。

### 验证

`flutter analyze` 干净；`test/generative` 与 `test/review` 通过；新增三条断言
（词表为 ASCII 下划线命名、每个真实 id 都能通过准入、用 kind 冒充 findingId
会被拒）。全量 `flutter test` 中 `date_picker_test` 两条失败，成因是
`forui 0.27.5` 日历在 1.3x 缩放下的 RenderFlex 溢出，与本次改动无关
（改动文件不含 date/theme/forui，最近两次相关提交均早于本次工作）。

## feat(review): A5-2 单维/多维/legacy 并入

### 为什么

组件化计划的 A5-2 要求把 review 的周期视图（原「legacy」页面）拆成组件并入目录、
随后删除兼容路由。后端 `GET /reports/dashboard` 已返回 `metrics`/`trends`/`findings`/
`patterns`，无需新端点。

### 落地

- **新增 `metric.grid`**（`sections/overview/metric_grid.dart`）：一次看全所有维度、
  不横向滚动。与 `coverage.strip` 的分工是排版而非数据——两者读同一份 `metrics`，
  所以用户把 strip 换成 grid 不会改变任何数字。用 `Wrap` 按列宽换行而不是嵌套
  `GridView`：组件挂在 `ComponentHost` 的纵向滚动容器里，第二个滚动轴会抢手势。
  进 available、**不进默认布局**（默认必须与组件化前逐字节一致）。
- **周期组件改为一等公民**：`components/legacy.dart` → `components/period.dart`，
  `sections/legacy/` → `sections/period/`。id 去掉 `.legacy` 后缀——
  `readiness.period` / `findings.period` / `ai_summary.period` / `patterns.period` /
  `history.suggestion`。组件面板里的名字从「旧版发现」改为「周期发现」。
  理由：review 同时有**事件视角**（`event.*`/`overview.*`）与**周期视角**
  （`*.period`），两者是并列产品形态，不是新旧替代。
- **删除兼容页**：`pages/legacy_dashboard_compat.dart`、
  `widgets/views/legacy/dashboard_view.dart`、`/review/legacy` 路由（两个 routes
  文件里的常量）、More sheet 的「历史报告」入口、相关测试用例与死文案键。

### 破坏性变更

用户失去 More sheet 的「历史报告」入口。已确认替代路径完整：该页渲染的 5 个
section 全部已注册为可编排组件，四张导出卡（分享管理 / PDF / 打印）在当前
Review 页 More sheet 里都已可用，用户可在编排页自行添加。

### 验证

`flutter analyze` 干净；`flutter test test/review test/core/composition test/generative`
全绿；`--clean-layers` 仍是 26 条存量（本次 0 条新增）。

## feat(medicine): 接通 10 个关系图端点，新增 10 个药理分析组件

### 为什么

Lucent 早已提供九个 `medicines/relations/*` 端点与 `medication-overview`，前端一行没调。
这些端点回答的是「为什么冲突」而不是「有没有冲突」：机制通路、共同靶点、四跳级联、
最短路径、酶诱导×底物——平铺的相互作用表结构上表达不了这些。组件化编排（A2–A4）就绪后，
用户可以自己把它们挂成「用药安全工作台」。

### 契约前提（Lucent 侧，同批改动）

十个端点的 `200` 此前只有 `description`、没有 schema，导出物里没有 `content`，
生成客户端把返回值落成 `Response<void>`——**前端就算接了也拿不到字段**。因此先在 Lucent
补齐信封 schema（`{ status, <数据键?> }`）并 `registerResponseSchema`，再重新生成客户端。
详见 Lucent `docs/logs/migration-log/2026-11-01.md`。

### 落地

- `domain/entities/relations.dart`：九个查询的实体 + `GraphQueryResult<T>` 信封 +
  `MedicationOverview`。`GraphQueryStatus` 含 `unknown`（服务端新增状态时按「无法回答」）。
- `domain/services/graph_drug_set.dart`：从用药条目派生 DrugBank id 集合的**纯规则**。
  只收 `DB\d{5}`、去重、排序（稳定 family key）、上限 10，并保留「在册药数」。
  刻意不认识 health_context——`domain/` 只能 import 本 feature 的 domain。
- `data/datasources/medicine_relations_remote.dart` + `mappers/medicine_relations.dart`：
  十个端点各一个薄映射；失败态数据键为 null，**不** `?? const []`。
- `data/repositories/relations.dart`：传输失败折成 `Left`；图不可用的三态是**成功答案**，
  留在 `Right`（它不是「加载失败请重试」，做成分支会让两种语义长成同一张错误卡）。
- `presentation/providers/relations/graph.dart`：`graphDrugSetProvider` 先读快照缓存再
  await；九个查询按入参做 family，挂两个 surface 只发一次请求。
- `presentation/widgets/sections/graph/`：`graph_card.dart` 统一三态渲染，
  `drug_set_sections.dart`（五个无参）、`selector_sections.dart`（五个需入参）。
- `presentation/components/catalog.dart`：十个 `dose.*` id 注册进 registry 与 `owned`。
- 新文案 46 条并入 `lib/l10n/src/medicine_{zh,en}.arb` 片段后 merge + gen-l10n。

### 降级语义（本组组件最不能出错的点）

`ok` + 空数组 = **图上确实没有**（中性措辞）；`notConfigured` / `unavailable` /
`timeout` = **我们无法回答**（警告卡，明写「这不是『没有相互作用』」）。
失败**不返回 `null`**：`ComponentHost` 把 `null` 连间距一起移除，区块消失会被读成
「没有相互作用」。`notConfigured` 不给重试按钮——重试永远不会成功。

另：只有带 DrugBank 编号的药能参与分析，所以组件同时显示「在册 N 种 / 参与分析 M 种」，
避免用户把部分覆盖当成全量结论。

### 默认布局

十个组件**全部不进 medicine 默认布局**，默认页与改造前完全一致。原因：五个需要入参
（避开哪个酶 / 起止药 / 靶点基因）无法自动派生，默认挂上只会是一排空态；且这组卡片
依赖 health_context 快照，默认挂上等于让每次翻页多一条依赖链。「安全工作台」是用户
编排出的一页，不是开发者预设的一页。

### 验证

- 新增 26 个用例全绿（`graph_drug_set_test` / `medicine_relations_mapper_test` /
  `graph_components_test`），覆盖：失败态不塌成空数组、未知 status 按无法回答、
  三态渲染不同、覆盖度文案、十个 id 已注册且不在默认布局。
- `test/medicine` 全量通过（改造前后无回归）；`flutter analyze lib test` 无问题。
- `--clean-layers` 无新增违规：本轮引入的 `domain_purity` 与 `directory_file_cap`
  已在提交前修掉（规则下沉到 provider、provider 移入 `relations/` 子目录）。
