## feat(generative): finding 改用后端稳定 id 作为引用键

### 为什么

生成式 UI 的 `finding` item 只接受 `findingId`，agent 只能选展示哪一条，文案由
后端原文透传。A7a 阶段后端 findings 没有稳定 id，客户端先用 `ReviewInsightKind.name`
对齐；Lucent 现已给 `ReportFindingDto` 加上 `id`（稳定规则标识），本次改为用真实 id。

### 落地

- `features/review/domain/entities/dashboard.dart`：`ReviewFinding` 增加 `id`。
- `features/review/data/repositories/lucent_dashboard.dart`：映射后端 `dto.id`。
- `features/generative/domain/services/item_catalog.dart`：新增
  `generativeFindingIds` 词表（`hydration_low` / `medication_stable` /
  `sleep_insufficient`），与后端 `FINDING_IDS` 一一对应。
- `app/composition/generative/catalog.dart`：`_FindingSlot` 按 `finding.id` 查找，
  不再拿 `kind.name` 比对。
- `features/generative/presentation/providers/surface_state.dart`：`DataScope`
  补上 finding 条目。

### 顺带修掉一个 A7a 遗留的真 bug

`findingPolicy` 把 `findingId` 声明为 `DataScopeKind.finding` 的引用键，准入要求
引用值存在于 scope 里，但 `generativeDataScopeProvider` **从未声明过 finding 条目**。
结果是任何合法的 `finding` 组件都会被判「引用了不存在的 id」，整次生成失败。本次
补上该条目后，真实 id 才能通过准入。

### 验证

`flutter analyze` 干净；`test/generative` 与 `test/review` 通过；新增三条断言
（词表为 ASCII 下划线命名、每个真实 id 都能通过准入、用 kind 冒充 findingId
会被拒）。全量 `flutter test` 中 `date_picker_test` 两条失败，成因是
`forui 0.27.5` 日历在 1.3x 缩放下的 RenderFlex 溢出，与本次改动无关
（改动文件不含 date/theme/forui，最近两次相关提交均早于本次工作）。

## feat(review): A5-2 单维/多维/legacy 并入

### 为什么

组件化计划的 A5-2 要求把 review 的周期视图（原「legacy」页面）拆成组件并入目录、
随后删除兼容路由。后端 `GET /reports/dashboard` 已返回 `metrics`/`trends`/`findings`/
`patterns`，无需新端点。

### 落地

- **新增 `metric.grid`**（`sections/overview/metric_grid.dart`）：一次看全所有维度、
  不横向滚动。与 `coverage.strip` 的分工是排版而非数据——两者读同一份 `metrics`，
  所以用户把 strip 换成 grid 不会改变任何数字。用 `Wrap` 按列宽换行而不是嵌套
  `GridView`：组件挂在 `ComponentHost` 的纵向滚动容器里，第二个滚动轴会抢手势。
  进 available、**不进默认布局**（默认必须与组件化前逐字节一致）。
- **周期组件改为一等公民**：`components/legacy.dart` → `components/period.dart`，
  `sections/legacy/` → `sections/period/`。id 去掉 `.legacy` 后缀——
  `readiness.period` / `findings.period` / `ai_summary.period` / `patterns.period` /
  `history.suggestion`。组件面板里的名字从「旧版发现」改为「周期发现」。
  理由：review 同时有**事件视角**（`event.*`/`overview.*`）与**周期视角**
  （`*.period`），两者是并列产品形态，不是新旧替代。
- **删除兼容页**：`pages/legacy_dashboard_compat.dart`、
  `widgets/views/legacy/dashboard_view.dart`、`/review/legacy` 路由（两个 routes
  文件里的常量）、More sheet 的「历史报告」入口、相关测试用例与死文案键。

### 破坏性变更

用户失去 More sheet 的「历史报告」入口。已确认替代路径完整：该页渲染的 5 个
section 全部已注册为可编排组件，四张导出卡（分享管理 / PDF / 打印）在当前
Review 页 More sheet 里都已可用，用户可在编排页自行添加。

### 验证

`flutter analyze` 干净；`flutter test test/review test/core/composition test/generative`
全绿；`--clean-layers` 仍是 26 条存量（本次 0 条新增）。

## 桌面端五个 tab 默认布局改为双列并排

### 背景

桌面端（宽度 ≥ `Breakpoints.desktop`）的 surface 网格是两列，但 `regular`
尺寸在这两列下**跨满两列**（`ComponentLayout.spanOf`）。五个 tab 的默认布局
此前清一色是不带 `size` 的 `ComponentPlacement`，即默认 `regular`，
于是桌面端实际渲染成一条满宽单列——视觉上就是「手机界面等比放大」。

### 变更

只改各 feature 的 `presentation/components/catalog.dart` 默认布局，把可配对的
卡片改为 `ComponentSize.compact`，使其在桌面两列下各占一列：

- `today`：问候、主/次建议、指标摘要、健康事件、体征观察。
- `record`：日期、快捷录入、筛选、时间线。
- `medicine`：药品箱、用药记录、安全引擎、快捷操作。
- `review`：覆盖率概览、值得注意、事件四段（发生了什么/关键变化/已完成/下一步）、
  单维与多维趋势。
- `mine`：个人提醒、归档摘要、隐私提示、提醒设置、账号安全。

保留整行的只有语义上必须是通栏的组件：登录预览横幅、快捷操作条、周期开关、
同步横幅、账号 hero、事件头部、历史列表。

移动端不受影响：`mobile` 只有一列，`spanOf` 对所有尺寸都返回 1。

### 验证

- `flutter analyze` 对这五个 catalog 文件无问题。
- `dart format` 已应用。
- 未跑测试：worktree 中 `sqlite3` native-assets 会请求 `pubspec.yaml` 固化的
  本地镜像 `127.0.0.1:8787`，该服务未启动，`flutter test` 在构建 native
  assets 阶段即失败。这是仓库既有的离线镜像措施，与本次改动无关。
- 实际的半宽视觉效果尚未人工确认。
