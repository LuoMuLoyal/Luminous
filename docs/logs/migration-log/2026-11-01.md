# 2026-11-01

## feat(generative): finding 改用后端稳定 id 作为引用键

### 为什么

生成式 UI 的 `finding` item 只接受 `findingId`，agent 只能选展示哪一条，文案由
后端原文透传。A7a 阶段后端 findings 没有稳定 id，客户端先用 `ReviewInsightKind.name`
对齐；Lucent 现已给 `ReportFindingDto` 加上 `id`（稳定规则标识），本次改为用真实 id。

### 落地

- `features/review/domain/entities/dashboard.dart`：`ReviewFinding` 增加 `id`。
- `features/review/data/repositories/lucent_dashboard.dart`：映射后端 `dto.id`。
- `features/generative/domain/services/item_catalog.dart`：新增
  `generativeFindingIds` 词表（`hydration_low` / `medication_stable` /
  `sleep_insufficient`），与后端 `FINDING_IDS` 一一对应。
- `app/composition/generative/catalog.dart`：`_FindingSlot` 按 `finding.id` 查找，
  不再拿 `kind.name` 比对。
- `features/generative/presentation/providers/surface_state.dart`：`DataScope`
  补上 finding 条目。

### 顺带修掉一个 A7a 遗留的真 bug

`findingPolicy` 把 `findingId` 声明为 `DataScopeKind.finding` 的引用键，准入要求
引用值存在于 scope 里，但 `generativeDataScopeProvider` **从未声明过 finding 条目**。
结果是任何合法的 `finding` 组件都会被判「引用了不存在的 id」，整次生成失败。本次
补上该条目后，真实 id 才能通过准入。

### 验证

`flutter analyze` 干净；`test/generative` 与 `test/review` 通过；新增三条断言
（词表为 ASCII 下划线命名、每个真实 id 都能通过准入、用 kind 冒充 findingId
会被拒）。全量 `flutter test` 中 `date_picker_test` 两条失败，成因是
`forui 0.27.5` 日历在 1.3x 缩放下的 RenderFlex 溢出，与本次改动无关
（改动文件不含 date/theme/forui，最近两次相关提交均早于本次工作）。
