# Product Tab Component Blueprint

本文件只回答一个问题：`Today / Record / Medicine / Review / Mine` 五个 tab 在 1.0 应该各自负责什么、展示什么、不展示什么。代码和路由在迁移完成前仍可能使用 `Report` 命名。它是 [[Product_Information_Architecture]] 的组件级展开，不重复解释产品愿景本身。

## 文档目标

- 固定五个 tab 的职责边界，避免后续继续互相抢内容。
- 把 `Today` 收紧为主动建议引擎主界面。
- 把 `Review` 收紧为健康事件优先的回顾视图。
- 把低置信度内容从 `Today` 的待办语义中剥离出去。
- 给 UI 和实现一个 1.0 组件清单，而不是抽象口号。

## 五个 Tab 的总分工

- **Today** — 行动面板：回答“我现在最该处理什么？”
- **Record** — 事实面板：回答“今天到底发生了什么？”
- **Medicine** — 药物工作台：回答“和药有关的风险、计划、解释是什么？”
- **Review** — 回顾面板：回答“这次健康事件发生了什么，结果怎样？”
- **Mine** — 边界与身份面板：回答“系统依据哪些信息来理解我？”

## Today

**职责**

- 唯一的主动干预主战场。
- 只承接经过统一裁决后的主动建议卡、摘要和轻量动作。
- 不承担原始记录录入，不承担长篇历史回顾。

**首屏组件清单**

- 主卡区：最高优先的 1 张主动建议主卡；必须显示证据、建议、动作、边界。
- 次卡区：最多 2 张次级主动建议卡；只保留值得当日处理的内容。
- 今日摘要区：1 个简短摘要模块；用来解释“今天发生了什么”，不是代替主卡。
- 观察项区：只显示低置信度、暂不单独出卡的观察项摘要；不进入待办语义。
- 轻动作区：去确认、去记录、去查看解释、去创建/调整提醒、去完善档案。

**次级入口 / 子页面**

- 主动建议卡详情页
- 证据解释页
- 提案确认页
- 当日建议历史页
- 通知 / 提醒详情页

**禁放内容**

- 深度录入表单
- 原始记录时间线主视图
- 完整药物查询工作台
- 长篇周报 / 月报内容
- 大量“全部建议”平铺
- 低置信度内容的待办化列表

## Record

**职责**

- 原始事实写入与回看。
- 负责记录，不负责最终分析结论。

**首屏组件清单**

- 快速记录区：症状、用药、饮水、饮食、睡眠、情绪 / 备注。
- 自然语言入口：文本输入、候选记录确认。
- 日期条 / 时间范围入口：当天 / 指定日期 / 日期范围切换。
- 记录筛选区：类型筛选、日期筛选。
- 记录时间线区：原始记录卡片、记录详情入口。

**次级入口 / 子页面**

- 新建记录页
- 编辑记录页
- NLP 候选确认页
- 记录详情页
- 记录关联视图

**禁放内容**

- 首屏主动建议主卡
- 药物风险最终裁决
- 周报 / 趋势主视图
- 以 AI 为主角的通用聊天入口

## Medicine

**职责**

- 药物安全与用药执行工作台。
- 负责药品、提醒、风险解释、覆盖范围和不确定性。

**首屏组件清单**

- 当前用药盒：当前药品列表、药品状态概览。
- 今日用药区：今日服药计划、已确认 / 未确认状态。
- 安全检查摘要区：已确认风险、已确认安全但非绝对安全、未覆盖 / 不确定。
- 快捷动作区：加药、查药、创建 / 调整提醒、查看风险解释。

**次级入口 / 子页面**

- 药品搜索页
- 药品详情页
- 新药加入前风险检查页 / sheet
- 全量风险检查页
- 提醒编辑页
- 用药日志页

**禁放内容**

- 泛化生活方式趋势主卡
- 无规则支撑的药物判断
- 通用 AI 自由问答主界面
- 长篇周报内容

## Review

**职责**

- 以健康事件为主单位的回顾视图。
- 负责事件总结、结果确认和有证据的解释，不负责当天行动裁决。

**首屏组件清单**

- 最近健康事件区：进行中事件与最近已结束事件，不以 readiness 锁住整页。
- 事件事实区：时间、症状变化和涉及药物。
- 完成情况区：计划服药槽位的已确认、跳过和未确认；不生成综合健康评分。
- 结果确认区：事件结束时询问“好转 / 差不多 / 加重”，其他追问可选。
- 下一步区：仅展示证据支持的继续观察、补充信息或寻求专业帮助建议。
- 单维趋势折叠区：仅在数据覆盖足够时展示，并标明来源和覆盖率。

**次级入口 / 子页面**

- 健康事件详情页
- 轻量周回顾页
- 单维趋势详情页
- 历史建议详情页
- “更多”中的导出预览与对外分享前预览页

**禁放内容**

- 首屏最高优先行动卡
- 高频实时提醒
- 深度录入入口
- 药物风险工作台
- 跨维度综合健康评分
- 默认展开的 PDF、打印或医生分享入口

## Mine

**职责**

- 身份、边界、授权、偏好。
- 负责说明系统依据哪些信息理解用户，以及用户允许系统做到什么程度。

**首屏组件清单**

- 档案状态主卡：当前档案是否基本就绪、哪些关键字段缺失、去完善主 CTA。
- 健康档案区：基础信息、过敏史、当前用药背景、健康上下文。
- AI 与隐私区：AI 授权、脱敏 / 隐藏字段、分享边界。
- 通知与提醒区：提醒偏好、通知升级规则、免打扰。
- 账号与安全区：登录状态、安全设置、退出登录。

**次级入口 / 子页面**

- 健康档案编辑页
- 过敏史编辑页
- 当前用药背景页
- AI / 隐私设置页
- 通知设置页
- 账号与安全页

**禁放内容**

- 主动建议主卡
- 原始记录时间线
- 长篇趋势分析主内容
- 药物风险结论主视图

## 跨 Tab 组件归属规则

- **主动建议卡**：主归属 `Today`；`Review` 只展示与健康事件有关的历史结果，不展示当日行动版。
- **观察项**：主归属 `Today` 摘要区、`Review` 回顾区；不能进入 `Today` 待办语义。
- **原始记录卡**：主归属 `Record`；`Today` 只能引用摘要，不直接承载完整时间线。
- **药物风险解释**：主归属 `Medicine`；`Today` 只放高优先摘要和跳转入口。
- **事件回顾 / 单维趋势**：主归属 `Review`；`Today` 只能放回顾已生成的入口和结果摘要。
- **提案式执行确认**：可从 `Today` / `Medicine` / `Mine` 发起，但都进入统一提案确认语义，不允许静默执行。

## 1.0 必做组件

- Today 主卡区
- Today 次卡区
- Today 今日摘要
- Today 观察项摘要
- Record 快速记录区
- Record 自然语言候选确认
- Record 时间线
- Medicine 当前用药盒
- Medicine 今日用药区
- Medicine 安全检查摘要
- Review 最近健康事件区
- Review 事件事实与完成情况区
- Review 结果确认区
- Mine 档案状态主卡
- Mine 健康档案区
- Mine AI 与隐私区

## 可延后组件

- Record 关联视图深挖
- Medicine 全量用药日志分析
- Review 单维趋势深层 drill-down
- 导出后的轻量分享链路
- 更复杂的建议反馈统计面板
- 更复杂的跨组件联动可视化

## RAW

按现在这套产品定义，五个 tab 最好不是“功能分类”，而是五个不同的问题入口：
今日：我现在最该处理什么
记录：今天到底发生了什么
用药：和药有关的风险、计划、解释是什么
回顾：这次健康事件发生了什么，结果怎样
我的：我是谁、系统能用哪些边界信息
我建议这样定。
今日
职责：唯一的主动干预主战场。只负责“现在最该处理什么”。
展示什么：
1 张最高优先主卡
最多 2 张次卡
今日摘要
少量轻动作入口
必要的观察项摘要
应该展示的内容：
明确风险卡
疑似漏服/计划未处理卡
明显恶化趋势卡
低风险行为建议卡
每张卡的证据、动作、边界
不该展示：
深度录入表单
大量历史列表
长篇报告内容
低置信度内容的待办化堆积
一句话：Today 不是信息流，是裁决后的行动面板。
记录
职责：原始事实入口。负责写入和回看，不负责做最终判断。
展示什么：
快速记录入口
自然语言转候选记录入口
当天/按日期的记录时间线
多类型筛选
原始记录详情
应该展示的内容：
症状、饮水、饮食、睡眠、用药、备注
候选记录确认
时间线和筛选
必要的“记录不足”提示
不该展示：
主动建议主卡
药物风险结论页
周报式趋势主视图
一句话：Record 负责事实，不负责结论。
用药
职责：药物工作台。负责药品、提醒、安全解释和覆盖边界。
展示什么：
当前用药盒
用药提醒计划
今日用药状态
新药加入前后的风险检查
风险解释与覆盖范围说明
应该展示的内容：
已确认风险
已确认安全但非绝对安全
未覆盖/不确定
药物详情、说明书要点、禁忌、交互检查结果
提醒创建/调整提案
不该展示：
泛化的生活方式趋势主卡
无规则支撑的药物判断
通用聊天式 AI 主界面
一句话：Medicine 是安全边界最硬的专业区。
回顾
职责：健康事件优先的回顾视图。负责说明事件结果，不负责当天决策。
展示什么：
最近健康事件
症状和用药事实
计划服药槽位的已确认/跳过/未确认
好转/差不多/加重的结果确认
有足够覆盖率时的单维趋势
应该展示的内容：
这次事件发生了什么、关键变化和下一步
未确认与漏服、缺失与零值的边界
历史建议是否被执行、用户认为是否有帮助
“更多”中的就诊摘要 / 导出预览
不该展示：
首屏最高优先任务
高频实时提醒
用来替代 Today 的行动入口
跨维度综合健康评分
一句话：Review 回答的是“这次发生了什么、结果怎样”，不是“现在怎么办”。
我的
职责：身份、边界、授权、偏好。
展示什么：
健康档案
过敏史
当前用药背景信息
AI/隐私授权
通知与提醒偏好
账号与安全
档案完整度
应该展示的内容：
哪些信息缺失会影响建议质量
隐私与脱敏控制
提醒与通知策略
账号、登录、安全设置
不该展示：
主动建议主卡
大量原始记录时间线
深度趋势分析主内容
一句话：Mine 负责定义系统能依据什么来理解你。
一条总规则
这五个 tab 最容易混的地方是：
今日 抢了 Review 的回顾内容
记录 抢了 今日 的建议内容
用药 抢了 今日 的优先级主卡
我的 变成杂物间
所以最稳的边界是：
今日 = 行动
记录 = 事实
用药 = 药物安全
Review = 回顾
我的 = 个人边界与设置
