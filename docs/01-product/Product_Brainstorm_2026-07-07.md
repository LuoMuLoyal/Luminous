# Product Brainstorm — 2026-07-07

基于 [[Product_Vision]] 全部子文档的头脑风暴，记录功能建议与调整方向。本文是产品探索文档，不是执行计划；选中执行的具体项会移入 `plans/` 或 `Next_Plan`。

## 愿景回路

核心闭环：`记录 → 结构化 → 总结/提醒 → 安全解释 → 报告`

当前 MVP 已跑通基础闭环，以下建议聚焦回路上的薄弱环节。

---

## 新增功能建议

### 1. 记录连续性激励（Streak & Adherence）

- 契合点：成功标准要求「用户连续 7 天记录至少 2 类健康信息」，但当前无产品机制激励
- 方案：
  - Today 页新增「本周记录热力图」（简单日历点阵，不是游戏化徽章）
  - 记录密度不足时 Today AI 总结明确提示「本周记录不足 N 天，趋势分析不可用」
  - 不做积分/排行榜/勋章——与低干扰可信调性冲突
- 不做：社交分享、成就系统、打卡积分

### 2. 智能提醒优先级调度

- 契合点：愿景提到「在合适时间主动提醒」，当前提醒是机械时间触发
- 方案：
  - 基于记录上下文调整优先级：饮水连续偏低 → 提前提醒；当天已大量饮水 → 降级
  - 漏服提醒增加「上次服药时间」上下文
  - 学习用户有效提醒窗口（快速确认 vs 延迟确认的差异）
- 边界：不自动改服药时间、不自动调整剂量
- 依赖：Lucent 提醒规则需支持 `priority_adjustment` 字段

### 3. 就诊摘要模板化

- 契合点：愿景提到「生成给门诊、药师或医生看的近期摘要，用户可预览并选择隐藏敏感内容」
- 方案：
  - Report → 导出 → 就诊摘要（新增第三种导出类型）
  - 用户选择时间范围 + 隐藏字段（过敏史/症状描述/心理状态/备注/图片）
  - 结构化输出：基本信息 → 近期症状 → 用药清单 → 过敏史 → 近期异常指标
  - 支持 PDF 和纯文本（方便微信发给医生）
- 不需要新后端合同：Lucent 已有 daily records + current medicines + health context + data export API
- 隐私门控：生成前预览，导出前二次确认

### 4. 症状-用药关联时间线

- 契合点：「把用户每天分散的健康记录连接起来，主动发现值得注意的变化」
- 方案：
  - Record 时间线新增「关联视图」筛选：同一日期范围内症状 + 用药 + 饮水 + 睡眠横向对照
  - Today 总结中 AI 发现的关联（如「头痛当天饮水偏少 + 睡眠不足」）可点击展开查看支撑数据
  - 只做时间共现展示，不做因果推断
- 实现路径：纯前端 UI 改动，数据已有，需 Record 时间线支持多类型混合渲染模式

### 5. 红旗信号规则提示（轻量版）

- 契合点：愿景将红旗信号列为「规则库完成后做」，当前完全缺失
- 方案：
  - 后端维护固定规则表（高烧 ≥39°C 持续 2 天、严重过敏反应描述、呼吸困难关键词）
  - 记录命中规则时 Today 页顶部显示固定安全文案卡片（非 AI 生成）
  - 卡片内容固定：「检测到您记录了 XXX，建议尽快寻求线下医疗帮助」+ 一键拨打 120 / 查看附近医院
- 不做：AI 自行判断紧急程度、分诊等级、疾病名称
- 前置条件：Lucent 侧需要 red-flag 规则表 + 固定安全文案审校

### 6. 快捷记录 Widget

- 契合点：个人用户的碎片化记录是目标用户核心场景
- 方案：
  - Android 桌面 Widget：一键记录饮水（+1 杯 / +250ml）
  - iOS Lock Screen Widget：快速查看今日服药状态
  - 长按 App 图标快捷菜单：记录饮水 / 记录症状 / 查看今日提醒
- 时机：1.1.0 候选功能，不阻塞 1.0.0 发布

### 7. Apple Health / Health Connect 数据桥接

- 契合点：Next_Plan 已列为「延后但有用」，解决记录密度核心痛点
- 方案：
  - 读取 Apple Health（iOS）和 Health Connect（Android）的步数、睡眠、饮水量
  - 作为「系统记录」标注来源，与手动记录区分
  - AI 总结时优先使用手动记录，系统记录作为补充上下文
- 不做：双向同步（只读不写）、心率/血压等需要医疗设备的指标
- 前置条件：产品决策确认数据来源可信度和隐私合规

## 现有功能调整建议

### A. Today 页信息密度收窄

- 问题：Today 同时承载 AI 日总结、优先事项、主动建议、快速操作，信息密度过高；愿景说「今日不做深度录入，只承接主动提醒和轻量动作」
- 调整：
  - Today 只保留 3 个区域：① 今日最重要的 1 条建议/提醒 ② AI 日总结（折叠态） ③ 快速操作入口
  - 「优先事项列表」移到 Record 或作为 Record 筛选条件
  - 记录不足时显示「记录不足，无法生成今日建议」而非空态 spinner

### B. Assistant 嵌入式重构

- 问题：当前 Assistant 是独立工作区，但愿景中 AI 核心角色是「理解、总结、解释、提醒文案层」
- 调整：
  - AI 从独立 Tab 变为嵌入式：Today 总结旁「问 AI 细节」、Medicine 安全检查旁「让 AI 解释」、Report 趋势旁「AI 解读」
  - 独立 Assistant 页面保留，定位从「主功能」调整为「高级用户自由探索入口」
  - 从「用户主动找 AI」变成「AI 在用户需要时出现」

### C. Record 快速入口动态排序

- 问题：8 种记录类型入口平铺，选择成本高
- 调整：
  - 根据使用频率动态排序，最常用的 3 个在前，其余折叠为「更多」
  - 新用户默认只显示：饮水、症状、睡眠
  - NLP 自然语言入口作为第一优先入口
  - 图标和文案反映当前状态（「+1 杯水」而非「饮水记录」）

### D. Report 门控透明度

- 问题：数据不足时显示空态或占位，用户不理解为什么没有报告
- 调整：
  - 空态明确说明「需要至少 7 天连续记录才能生成周报」
  - 显示记录进度条：「本周已记录 4/7 天，再记录 3 天即可生成趋势分析」
  - 导出功能不可用时说明原因，而非隐藏入口或显示 loading

### E. Mine 设置层级整理

- 问题：Mine 承载过多低频功能，层级不够清晰
- 调整：
  - Mine 页只保留 4 个一级入口：① 健康档案 ② AI 与隐私 ③ 通知与提醒 ④ 账号与安全
  - 开发者选项和功能开关合并到「高级」
  - 健康档案新增「档案完整度」提示：过敏史未填写 / 当前用药为空 → 提醒完善（影响安全检查覆盖范围）

### F. Medicine 安全检查三层展示

- 问题：安全检查结果可能让用户误以为「没有提示 = 安全」
- 调整：
  - 三层展示：① 已确认风险（红色） ② 已确认安全（绿色） ③ 未覆盖/不确定（黄色，必须显示）
  - 结果为「未发现风险」时附加「仅覆盖了 X 条规则，不等于绝对安全」
  - 新增药物 pre-check sheet 明确列出检查范围（过敏交叉 / 当前用药交叉 / 说明书禁忌）

## 验证现有边界（建议不做）

| 考虑过 | 不做原因 |
|---|---|
| 社区/论坛 | 与个人健康自我管理定位冲突，增加内容审核负担 |
| 健康商城/药品推荐 | 与「不做自动处方」边界冲突，引入利益冲突 |
| AI 语音对话 | AI 定位在理解总结解释层，语音对话不增加核心价值 |
| 家庭共享 | 明确 Not MVP，数据隐私和权限模型复杂度极高 |
| 量化自我/生物黑客 | 目标用户是注重日常健康的普通人，不是数据极客 |

## 优先级建议

按照「先证明一个日常高频闭环，再扩展」原则：

### P0 — 1.0.0 发布前

- Medicine 安全检查三层展示（F）— 直接影响可信度和安全边界
- Report 门控透明度（D）— 影响用户对产品的信任理解

### P1 — 1.0.0 内

- Today 信息密度收窄（A）— 影响 MVP 演示第一印象
- Record 快速入口动态排序（C）— 降低记录门槛
- Mine 档案完整度提示（E）— 档案空直接影响安全检查覆盖

### P2 — 1.1.0

- 就诊摘要模板化（3）— 已有数据基础，前端组合渲染
- 症状-用药关联时间线（4）— 纯前端改动
- 记录连续性激励（1）— 直接对应成功标准

### P3 — 1.2.0+

- 红旗信号规则提示（5）— 需后端规则表审校
- 智能提醒优先级调度（2）— 需 Lucent 提醒规则扩展
- Apple Health / Health Connect 桥接（7）— 解决记录密度核心痛点
- 快捷记录 Widget（6）— 降低记录摩擦
- Assistant 嵌入式重构（B）— 深度架构调整，需稳定后进行
