## 每日总结

每日总结是 Luminous 从“记录工具”变成“健康助手”的关键能力。

示例输出：

```text
今日饮水记录偏少，晚间记录了咖啡因，可能影响睡眠。
明日建议适当增加饮水，晚间尽量减少咖啡因摄入。
如果头痛或胃部不适持续，请及时咨询医生或药师。
```

每日总结原则：

- 只总结用户已经记录或授权的数据。
- 优先指出 1 到 3 个最重要的变化，不写长篇泛泛建议。
- 建议要低风险、可执行，例如饮水、休息、清淡饮食、减少晚间咖啡因。
- 不从粗粒度饮食描述推断精确热量、蛋白质、碳水或脂肪结论，除非用户明确记录了这些数据。
- 涉及症状持续、严重不适或药物风险时，引导咨询医生或药师。
- 不写诊断结论。

## 主动建议卡

主动建议卡是 Luminous 1.0 的核心产品对象，也是 `Today` 首屏真正要解决的问题。

每张主动建议卡都必须包含：

- **证据**：为什么会出现这张卡，来自哪些记录、上下文、规则命中或计划状态。
- **建议**：系统认为用户现在最该注意什么。
- **动作**：去记录、去确认、去查看解释、去创建提醒、去完善档案等明确动作。
- **边界**：哪些结论不确定、哪些信息缺失、什么时候该线下咨询。

不满足动作或边界要求的内容，不应单独出卡。

## 主动建议引擎的触发源

1.0 的主动建议卡只允许基于以下四类证据触发：

- 用户结构化记录。
- 用户明确授权的健康上下文。
- 规则引擎 / 药品数据源命中结果。
- 已存在的提醒计划与执行状态。

以下内容不能作为主判断链路的直接触发源：

- 模型自由联想。
- 未审校的外部网页结论。
- 没有记录支撑的经验性健康建议。
- 地图、附近线下支持、通用网络搜索或外部环境信号。

## 主动建议卡的类型

1.0 只允许有限卡种，不能让模型自由创造新卡类型：

- **风险卡**：明确规则、药物、症状风险。
- **依从卡**：漏服、未确认、计划未执行、关键记录缺失。
- **趋势卡**：睡眠下降、饮水持续不足、咖啡因上升等连续变化。
- **行为建议卡**：低风险生活方式建议。
- **说明卡**：覆盖范围、不确定性、为什么出现这张卡。

## 触发时机

主动建议引擎分成两条触发链：

- **事件触发**
  - 新增药物
  - 命中用药规则
  - 到时未确认服药
  - 新记录直接触发明确风险
- **定时触发**
  - 当日总结
  - 跨天趋势
  - 连续饮水不足
  - 睡眠下降
  - 咖啡因累计偏高

## 出卡门槛与观察项

- 明确规则风险、疑似漏服、已到时未处理的计划事件，可以立即出卡。
- 饮水不足、咖啡因偏多、睡眠下降这类趋势 / 行为建议，需要连续记录或跨天趋势后才出卡。
- 单条模糊线索、证据不足或暂时没有明确动作方向的内容，不单独出卡，只作为 `观察项` 进入摘要或报告。
- 多个弱信号可以组合成更强卡，但只能按预定义、可解释、可落到明确动作的组合规则合成，不能让模型自由拼接。

## 冷启动与个人基线

- 趋势 / 行为建议默认以用户个人基线变化为主，通用阈值只做保守补充。
- 冷启动阶段不出强趋势卡；只允许出规则 / 安全类卡、计划事件卡，以及极保守的记录引导卡。
- 基线必须按维度分别形成，不能用一个全局“已完成冷启动”状态替代：
  - 睡眠基线只看睡眠记录
  - 饮水基线只看饮水记录
  - 饮食 / 咖啡因基线只看相关摄入记录
  - 用药依从按计划事件单独判断

## 提案式执行与反馈反哺

- 主动建议卡可以带动作，但 1.0 的写操作一律走 `提案式执行`。
- Assistant 可以生成可执行提案，但任何写操作都必须由用户显式批准后执行。
- 用户面对主动建议卡时，至少有以下结构化反馈结果：
  - 接受并执行
  - 稍后处理
  - 不适用
  - 不想再看到这类建议
- 用户反馈必须真实影响后续出卡，而不是只做记录：
  - `接受并执行` 可以提高同类卡的后续积极度
  - `稍后处理` 只做短期延后
  - `不适用` 应在一段时间内降权
  - `不想再看到这类建议` 应进入强抑制，除非出现更高严重度的新证据

## 生命周期、弃权与通知升级

- 每类主动建议卡都必须有明确的生成、激活、消退和失效规则。
- 证据失效后，卡片不能继续占据 `Today`。
- 证据冲突、证据不足或只能讲一个“也许有帮助”的故事时，系统应弃权，不出主动建议卡。
- 绝大多数主动建议只存在于 `Today`；只有少数高优先级、强时效卡可以升级成通知，例如：
  - 已到时未确认的用药计划
  - 明确规则风险
  - 用户已经订阅的计划事件

## 每周趋势分析

每周分析用于帮助用户看到变化，而不是制造焦虑。

示例输出：

```text
本周饮水量比上周更多，继续保持。
本周平均睡眠时间比上周减少 11.2%，建议下周优先观察入睡时间和白天疲劳感。
本周有 3 天在晚上记录咖啡因摄入，可能与睡眠下降有关。
```

每周分析原则：

- 只比较有足够记录的数据。
- 明确“比上周增加/减少多少”，不要只说“变好了/变差了”。
- 把建议限定在生活方式和自我观察。
- 不把趋势直接解释成疾病。
- `Report` 是主动建议引擎的回顾视图，用来展示每周报告、趋势图、导出预览和打印预览；真实导出和分享必须等报告与隐私合同稳定。

## 主动建议与提醒系统

主动建议系统是 Luminous 相比普通健康 App 的核心差异，但它不等于“见到一点信号就提醒”。

普通健康产品大多依赖用户主动搜索。Luminous 应该在用户没有主动提问时，根据证据发现问题，并只在值得干预时出卡。

可做的提醒类型：

- **饮水提醒**：连续饮水不足或当天饮水明显偏少时，提高提醒优先级。
- **饮食提醒**：基于用户明确记录的饮食时间、饱腹感或不适，提示清淡饮食、观察胃肠反应等低风险建议；不替用户决定是否延后进食。
- **睡眠提醒**：连续晚睡、睡眠下降、晚间咖啡因增加时，提醒观察睡眠。睡眠合同未稳定前只做占位或静态演示。
- **用药提醒**：到点未打卡时提醒用户确认是否已服药。
- **新药风险检查**：用户新增药物后，主动检查已有来源可支持的说明书、过敏史、当前用药和已审校规则；跨来源匹配、重复成分和未审校相互作用不作为确定结论。
- **报告提醒**：每周生成摘要后，提醒用户查看本周变化。没有真实报告合同时只做静态演示。
- **服务连接提醒**：后续如要恢复附近线下支持发现，必须先有稳定数据合同或地图能力；这不属于当前 MVP 承诺。

需要避免的提醒：

- 不要替用户决定疾病诊断。
- 不要替用户决定是否停药、加药、换药。
- 不要在漏服后直接自动改用药方案。
- 不要用恐吓式语言制造健康焦虑。
- 不要把低置信度推断包装成确定事实。
- 不要在缺少饮食、睡眠、药物或症状数据时生成看似个性化的建议。
