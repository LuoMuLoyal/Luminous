### 问题 1：LegalDocType.fromPathSegment 可优化为 Map（✅ 已修复，无需操作）

- **核实**：`lib/features/legal/domain/entities/doc_type.dart` 已使用 `_byPathSegment` Map 实现 O(1) 查找，`fromPathSegment` 方法直接 `return _byPathSegment[value]`。注释标注 `/// O(1) lookup map`。此建议已落地。

### 问题 2：SuggestionJsonCodec 序列化兼容性（⚠️ 已修复）

- **问题**：`suggestion.dart` 的 `_fetch()` 方法在网络失败时尝试从缓存读取（stale-while-error），但 `bundleFromJson(cached)` 调用无 try-catch。如果缓存格式不兼容（如 app 更新后字段结构变更），反序列化会抛出未处理的 `TypeError`/`CastException`，导致 provider 进入不可恢复的错误状态。
- **修复**：`suggestion.dart` 的缓存反序列化路径包裹 try-catch：反序列化失败时记录 warning 日志（`talkerProvider`），调用 `dao.clear()` 清理过期缓存，然后 rethrow 原始网络错误（保持与"无缓存"场景一致的行为）。
- **测试**：`suggestion_provider_test.dart` 新增 `clears stale cache when deserialization fails and rethrows` 测试，验证网络失败 + 缓存格式不兼容时 `dao.clear()` 被调用。

### 问题 3：DesktopTabShell 构造函数参数多（❌ 不修复）

- **核实**：`DesktopTabShell` 实际有 8 个参数（+ `super.key` = 9），在 Flutter `StatelessWidget` 中完全正常。Builder 模式在 Flutter widget 中反惯用，引入反而增加复杂度。

### 问题 4：isPublicRoute 硬编码只包含 /legal（✅ 已修复）

- **问题**：`router.dart` 的 redirect 守卫中 `isPublicRoute = location.startsWith('/legal')` 硬编码了 `/legal` 前缀。变量名暗示通用性，但未来新增公开路由（如帮助页、关于页）时容易遗漏更新。
- **修复**：提取 `_publicRoutePrefixes` 常量集合（`const <String>['/legal']`），`isPublicRoute` 改为 `_publicRoutePrefixes.any((prefix) => location.startsWith(prefix))`。注释说明添加新公开路由时更新此列表。

### 问题 5：高对比度模式颜色硬编码（✅ 已修复，无需操作）

- **核实**：`bootstrap.dart` 的 `_applyHighContrast` 函数已使用 `HighContrastColors` 常量类（`lib/core/design/high_contrast.dart`），不再有硬编码 `Color(0xFF...)`。`HighContrastColors` 的注释明确说明颜色有意不从主题系列生——高对比度模式是无障碍覆盖，使用跨系列一致的极值。

### 1. 桌面月历交互解耦（3.2.1）

- **问题**：`RecordMonthCalendarPanel` 的 `onMonthChanged` 回调在 `_DesktopRecordDashboard` 中被直接绑定到 `onDateSelected`（`dashboard_view.dart:172`），用户点击月历左右箭头切换月份时，`_changeMonth(delta)` 构造 `DateTime(year, month±1, 1)` 并调用 `onDateSelected`，导致：(1) 选中日期被强制跳到新月份的 1 号，用户原本选的日期丢失；(2) 触发 dashboard provider 重新拉取新日期的数据，产生不必要的网络请求；(3) 用户无法浏览其他月份的日历而不改变当前查看的数据。
- **修复**：
  - `RecordMonthCalendarPanel` 从 `StatelessWidget` 改为 `StatefulWidget`，新增 `_viewedMonth` 本地状态。
  - `_changeMonth(delta)` 仅 `setState` 更新 `_viewedMonth`，不再调用 `onDateSelected`；可选的 `onMonthChanged` 回调仅通知父组件查看月份变化（dashboard_view 中不再传该回调）。
  - 新增 `_buildViewedDays()` 方法：当 `_viewedMonth` 与 `selectedDate` 同月时，使用父组件传入的 `days`（含服务端标记）；否则通过 `_buildPlainMonthDays()` 本地生成该月日历网格（无标记，仅高亮选中日）。
  - `didUpdateWidget` 在 `selectedDate` 跨月变化时（如通过 header 日期选择器或移动端 date bar 切换）自动同步 `_viewedMonth`，保持日历与选中日期一致。
  - `dashboard_view.dart` 的 `_DesktopRecordDashboard` 中 `RecordMonthCalendarPanel` 调用移除 `onMonthChanged: onDateSelected` 绑定，月历切换完全由 panel 内部状态管理。
  - **结果**：用户可在桌面月历中自由浏览前后月份的日历视图而不丢失当前选中日期，只有点击具体日期格子才会触发 `onDateSelected` 切换数据。

### 2. 平板中间档限宽（600–1200px）

- **问题**：`ResponsiveContentFrame` 仅在 `width >= Breakpoints.desktop`（1200px）时应用 `layout.maxContentWidth` 约束，平板档（960–1199px）内容 `maxWidth` 为 `double.infinity`，导致内容在平板/中小桌面窗口上全宽拉伸。虽然 `LayoutScaleResolver` 已为平板档定义 `maxContentWidth: 1040`，但未被 `ResponsiveContentFrame` 使用。
- **修复**：`responsive_content_frame.dart` 的 `ConstrainedBox` 约束条件从 `width >= Breakpoints.desktop` 改为 `width >= Breakpoints.tablet`，使平板档（960px+）内容居中并限宽至 1040px，桌面档（1200px+）限宽至 1400px，移动档（< 960px）保持不限宽以支持边缘到边缘的自然布局。
