# 迁移日志 2026-09-20

## docs: README 与产品文档对齐当前实现（知识检索与推理分层）

### 背景

对 Luminous 根 README 与 `docs/product/` 做了一次事实核对，发现两类问题：

1. 根 README 有两处**失效引用**——`CONTEXT.md`（产品语言文件已不存在，术语事实源实际是
   `docs/reference/glossary.md`）与 `.github/workflows/flutter-ci.yml`（实际工作流为
   `luminous-ci.yml` / `luminous-cd.yml`）。CI 范围描述也与当前工作流不符。
2. 产品文档完全没有反映已经落地的**知识检索与推理分层**：英文侧 DrugBank 关系数据走
   本体增强生成（类型化多跳关系）、中文散文走 LightRAG、中文产品表走 SQL 键查，三者强制
   分离；以及"结论必须可溯源""缺断言 ≠ 临床上不存在""服务不可用不得静默降级"这些已经
   在代码和 `Lucent/docs/reference/assistant-safety.md` 中固化的边界。

### 变更

- `README.md`
  - 简介改为完整的伙伴定位（低负担稀疏记录 → 个人上下文 → 日/周/月变化 → 有证据的建议，
    证据不足弃权），用药安全与健康事件作为证据要求最高的一条主线而非产品天花板。
  - `Baseline` 补五 Tab 各自职责，并把全 app 强制的四条产品约束写入：缺失=未知（不得由
    缺席记录推断"没吃药/没喝水"）、每个结论带覆盖率且证据不足时弃权、AI 只做理解/总结/
    解释/提醒文案不做诊断处方与风险判定、Assistant 写入必须走提案确认。补本地持久化为
    Drift + pending-sync 队列。
  - `Community` 的产品语言链接改指 `docs/reference/glossary.md`。
  - CI 段改为实际工作流文件名与当前范围（ARB 合并、生成物 bootstrap、客户端构建、
    生成文档校验、analyze、test --coverage、main 分支 release APK）。

## 每日审查落地（2026-09-18 / 09-19 报告）

### 背景

按 `plans/Luminous-review-09-18.md` 与 `plans/Luminous-review-09-19.md` 逐条核对报告
结论与真实代码，**报告建议不作为事实**：先复现再修改，报告中与代码不符的条目保留原状并在
下节记录证据。

### 变更（每项一个原子提交）

- **同步层失败落库异常兜底（09-18 W2）**：`core/database/sync/worker.dart` 的
  `markPermanentlyFailed` / `markFailed` 调用原先直接暴露在 `on DioException` 之外，
  DAO 抛错会冒泡出 `_replayEntry`、中断整轮 flush，且该条目停留在 `isSyncing = true`
  而同时从重试队列与永久失败列表中消失。新增私有 `_recordFailure` 收敛三处写库调用：
  写库失败时记 `talker.error`（带 stackTrace）并继续处理后续条目；恢复路径仍是
  `PendingSyncDao.resetForRetry`。
- **溯源引用丢弃分支可观测（09-19 warning）**：`features/assistant/data/repositories/lucent.dart`
  的 `_mapCitations` 三条丢弃分支（非列表、非 Map 项、缺 `id`）各补一条 `appTalker.debug`，
  附原因与原始值。容错语义不变（坏引用不打断工具卡）——原先只是静默跳过，后端改字段名
  时客户端没有任何信号。
- **混合检索工作区信任档（09-18 S1）**：`presentation/utils/ui_formatters.dart` 的
  `_lightragTierOf` 原先按后端给的表顺序取第一个命中，`qa` 排在 `leaflet` 之前就会
  把说明书内容降级为开放语料、**丢掉**安全相关提示。改为扫描全表取**最低**信任档，与
  缺表时的 `medicalQa` 默认保持同一 fail-safe 方向；`0` 表示未识别、不参与比较，
  旁边有真实表时不干扰结果。
- **数据窗口日期字面量解析（09-18 S6）**：`features/review/presentation/widgets/sections/noteworthy.dart`
  的 `_formatWindowDate` 原先用 `DateTime.tryParse` + `DateFormat`，对 ISO 形态
  （`2026-08-17T00:00:00.000Z`）会按设备时区渲染，UTC 之前的时区显示成 8月16日。
  改为按契约读前导 `YYYY-MM-DD` 日期字面量；占位符（`----.--.--`）与越界月/日
  回落到原始字符串，不产生空标签或 `DateTime` 归一化后的错日。
- **用药概览取值抽函数（09-18 S4）**：`features/today/.../view_models.dart` 的三层嵌套
  三元抽为早返回的 `_medicationOverviewValue`，顺序与语义完全不变（degraded → 无用药
  计划 → 比率）。
- **DAO 失败写入路径合并（09-18 S5）**：`core/database/daos/pending_sync.dart` 的
  `markFailed` / `markPermanentlyFailed` 原先各自复制一份 companion 写入，只有
  `retryCount` 不同。抽出私有 `_writeFailureState`（`retryCount` 由调用方以
  `Expression<int>` 传入），两路径此后不会在记录字段上漂移。

### 报告条目经核对后未改动

- **09-18 W1（`PageScaffold` 底部 inset 吞掉 home-indicator）**：不成立。`removeViewInsets`
  只清 `MediaQuery.viewInsets`，而 `SafeArea` 读的是 `MediaQuery.padding`，两者相互独立；
  已用 widget 探针验证 `removeBottom: true` 后 `padding.bottom` 仍为 34、`viewInsets.bottom` 归零。
  唯一的 `useSafeArea: false` 调用点（`barcode_scanner.dart`）本就自带底部 `SafeArea`。
  审查建议的「`useSafeArea: false` 时不要 strip inset」反而会重新引入本次修复要消除的
  「keyboard inset 被算两遍」溢出，故不采纳。
- **09-18 W3（`ShaderMask` 全屏页合成锯齿）**：无实际触发面。`HorizontalScrollFade` 仅两处
  调用点（review 覆盖率条、record 筛选 chips），都在常规页面，不与相机/扫码全屏页组合；
  报告所述现象无证据，不建议为此改动已工作的绘制路径。
- **09-18 S3（旧 l10n key 已无人引用）**：不成立。`settingsNotificationsAdvanceOff` /
  `settingsNotificationsAdvanceMinutes` 仍被 `features/settings/presentation/pages/notification.dart`
  使用（摘要行与提前量选择器），删除会直接破坏设置页文案。
- **09-18 S2（免责声明逐条展开）**：现象属实（每段助手消息一个 bar），但这是当前交互的
  有意设计——每段免责声明对应各自消息，报告本身也只列为轻量 UX 议题，未改。
- **09-18 S7（`retryable` 缺 `@Default`）**：不需要改。`ProblemDetails` 与
  `PendingSyncErrorDetails` 的 `retryable` 是可空字段，后端 `problem-catalog.ts` 的
  `build()` 对已注册 code 始终写出显式布尔值；`null` 只出现在迁移前的历史持久化行上，
  而 `worker.dart` 的 `details.retryable == false` 判断对 `null` 已正确回落到重试预算
  分支。强行加默认值反而改变历史行的语义。
- **09-19 契约溯源**：`generated/lucent_api` 的来源即为
  `Lucent/docs/reference/generated/openapi.json`（由 `pnpm export:openapi` 产出），
  已在 `AGENTS.md` 固化为唯一契约链路，无需另记备忘。

## 规则推理工具名文案（跟随 Lucent `reason_over_rules`）

### 变更范围

后端新增规则推理工具 `reason_over_rules`，本仓补它的展示名：

- `lib/l10n/src/assistant_{zh,en}.arb`：新增 `assistantToolReasonOverRules`
  （"DrugBank 规则推导" / "DrugBank rule inference"）；随后 `arb_tools.dart merge`
  + `flutter gen-l10n` 重生成，生成物未手改。
- `lib/features/assistant/presentation/utils/ui_formatters.dart`：工具名→文案映射。

缺这个映射不会报错，而是走 `_ => toolId` 兜底 —— 工具来源条上直接显示
`reason_over_rules` 这个原始 id。

文案刻意与"本体推理"区分：本体推理读的是图上**写了**的边，规则推导是**推出**图上
没写的边，依据在两个三元组的连接上。两者若用同一个说法，用户会把推导读成事实。

- `flutter test`：全过。
