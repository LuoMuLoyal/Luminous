# 2026-09-12

## docs(design): 动画体系调研与选型——全局分级动画 Motion Hierarchy

纯调研落地,不改任何代码。

### 背景

用户反馈:进入/退出登录页有动画,但其他区域几乎无动画 —— tab 切换、设置页点击进入
子页、路由进入/退出都缺过渡;要求按分级(motion hierarchy)调研"官方 vs 社区包"
后选型,让软件更流畅。

### 调研过程(两份并行 subagent 调研 + 本地审计)

1. **本地代码审计**(本仓库):`lib/app/router_helpers.dart` 已有 `fadePage` /
   `tabFadePage` / `slidePage` / `sidePanelPage`;`MotionTokens` / `DurationTokens`
   已建(4 曲线 + 8 时长);`flutter_animate` 4.5.2 已依赖但仅 ~6 处使用;显式
   `AnimationController` 3 处;`Hero` 零使用;无 `AnimatedList`;Forui `FTheme`
   自带 `FThemeMotion` 主题切换动画(200ms);flow_ui 0.1.0 自带流式/呼吸动画。
2. **官方调研**(Flutter 3.38+ 源码与文档、go_router 17.x、M3 motion 规范):
   - `StatefulShellRoute.indexedStack` 官方明确**分支切换无过渡**,须自定义
     `navigatorContainerBuilder`(官方示例 custom_stateful_shell_route.dart),
     M3 称此模式为 Fade through(淡入+轻微缩放,≈300ms)。
   - 子页面路由首选默认 `MaterialPage` + `PageTransitionsTheme`(平台原生、零配置);
     特殊页才用 `CustomTransitionPage`。
   - `PageTransitionsTheme` 默认:Android=PredictiveBack(回退 FadeForwards,450ms)、
     iOS/macOS=Cupertino、Windows/Linux=Zoom(快照,Web 自动禁)、兜底 Zoom。
   - M3 分级:navigation 300–600ms / transitions 200–400ms / micro-interactions
     100–200ms;easing:standard=`(0.2,0,0,1)`、emphasized=`Curves.easeInOutCubicEmphasized`。
   - Hero 跨 StatefulShellRoute 分支不工作(独立 Navigator,#192043)。
   - reduce motion:`MediaQueryData.disableAnimations` 引擎驱动,框架动画自动压缩;
     iOS reduceMotion 暂不互通(#190287 在途)。
3. **社区包调研**(pub.dev/GitHub 实时数据):
   - Flutter 生态正迁向独立 `material_ui` 包(3.47 起),项目**已依赖 material_ui
     1.x**,与 `forui 0.26`、`animations 3.0.0` 同源。
   - `flutter_animate` 4.5.2 维护停滞(2024-11 起),CurvedAnimation 泄漏 bug 未修;
     活跃 fork `flutter_animate_plus` 是升级预案。
   - 推荐:tab 过渡**不引包自写**(navigatorContainerBuilder 20 行);可选引入官方
     `animations 3.0.0`(SharedAxis/FadeThrough;注意 OpenContainer 与 go_router
     不兼容 #121929,勿用于路由);明确不引入 page_transition / motion(GPL-3)/
     rive / lottie / go_router_animated_branch。

### 结论(选型)

三层动画体系,不引大包:

1. **导航过渡**:tab 切换自写 `navigatorContainerBuilder` fade-through(280–300ms
   emphasized);子页面路由先增强现有 `slidePage` 补 `secondaryAnimation` 反向过渡,
   再评估收敛到 `PageTransitionsTheme` 平台默认;设置页桌面 master-detail 加
   `AnimatedSwitcher`。
2. **内容/列表过渡**:flutter_animate 交错进场(限核心列表页)+ `AnimatedSwitcher`
   数据刷新 + Hero 限同分支。
3. **微交互**:优先 Forui 自带(FTappable/FPopover/FTooltip motion +
   `FAccessibilityMotion` 自动降级),flutter_animate 补充自由编排。

无障碍:框架动画自动响应 disableAnimations;自写显式动画统一经 AnimationController
并判断 `MediaQueryData.disableAnimations`;flutter_animate 使用处需补该判断(现状未做)。

## feat(shell,settings): Tab 切换 fade-through + 设置页桌面 master-detail 切换动画

动画体系阶段 2(核心痛点)落地。纯前端动画,无后端/契约/l10n 变更。

### Tab 切换(M3 fade-through)

- **根因**:`StatefulShellRoute.indexedStack` 官方明确"分支切换不做过渡"
  (各分支独立 Navigator,`PageTransitionsTheme` 管不到);`tabFadePage` 在分支
  常驻后不再重放,故五 Tab 切换是瞬间跳变。
- **方案**:按官方 custom_stateful_shell_route 示例,`router.dart` 改用一般
  `StatefulShellRoute` + 自定义 `navigatorContainerBuilder`,新增
  `ShellTabBranchContainer`(`lib/features/shell/presentation/tab_branch_container.dart`):
  - 切 Tab 时新分支淡入 + 轻微缩放(0.98→1.0),旧分支淡出(260/200ms,
    `MotionTokens.emphasized`)。
  - **保持 IndexedStack 语义**:所有分支常驻挂载(状态保留);非当前分支
    `Offstage`(对 finder/测试 offstage,与原来一致);隐藏分支
    `TickerMode(enabled: false)` + `IgnorePointer`。
  - 动画时长有界,`pumpAndSettle` 可收敛(全量测试验证)。
- `motion.dart` 新增 M3 对齐 token:`MotionTokens.emphasized`(=
  `Curves.easeInOutCubicEmphasized`)、`emphasizedDecelerate`(=
  `Cubic(0.05, 0.7, 0.1, 1)`)、`DurationTokens.tabFadeThrough`(260ms)/
  `tabFadeThroughOut`(200ms)/`masterDetailSwitch`(220ms)。

### 设置页桌面 master-detail

- `settings/presentation/widgets/master_detail.dart` 右侧 pane 包
  `AnimatedSwitcher`(220ms,`emphasizedDecelerate` 入场,`KeyedSubtree` 按
  `_selectedIndex` 触发),左栏点选切换分组时淡入淡出,替代原 `setState` 直接换 body。

### 测试

## fix(auth,mine,record,review): 去掉叠加淡入与卡片上浮,登录页改对称淡入淡出

承接动画体系落地后的手感反馈:登录页进入"停顿 + 僵硬"、退场动画消失、卡片上浮观感不佳。

### 根因

1. **双重淡入相乘**:路由 `fadePage` 是纯 `FadeTransition` 400ms,而 `AuthFormPanel`
   自己还叠了 `flutter_animate` 的 fadeIn 180ms。两者相乘后前 ~150ms 有效透明度仅
   ~20%,旧页面却仍 100% 显示 → 视觉上就是"停顿后突然淡入"。
2. **退场消失**:上一轮把 `fadePage` 换成官方 `FadeThroughTransition` 是误用 ——
   它的**退场只占反向着色的前 30%**(220ms × 30% ≈ 66ms),pop 时登录页几乎瞬间消失,
   且交接处有一段两侧都不可见的空档 → 僵硬。
   fade-through 适合"同一 widget 内的内容互换"(`PageStateSwitch`、tab 分支容器,
   进出两侧由同一个 switcher 管理),不适合路由 push/pop(只有一侧归我们管)。

### 变更

- `lib/app/router_helpers.dart`:`fadePage` 改回**对称淡入淡出**
  (`FadeTransition` + `animation.drive(CurveTween(snappy))`);进场 300ms、
  退场 240ms,退场全程可见。用 `drive` 而非内联 `CurvedAnimation`,避免其构造时
  向路由动画注册 status listener 而不释放。
- `lib/core/design/tokens/motion.dart`:auth 过渡 400/280 → 300/240;删除
  `authContentRise`(淡入移除后仅剩上浮,现已全部去掉)与 `widgetEntrance`
  的旧名 `widgetFadeIn`。
- `lib/features/auth/presentation/widgets/shared/mobile_shell.dart`:
  `AuthFormPanel` 去掉入场动画(不再上浮、不再二次淡入);随之移除整条
  `enableFormAnimation` 管道(`AuthShell`/`MobileAuthShell`/`DesktopAuthShell`/
  `AccountManagePage`/`AccountSettingsPage`/`security_center` 的传参),
  避免留下死参数。
- `mine` / `record` / `review legacy` 三个 dashboard:移除 `Animate` 入场
  (原 `SlideEffect` 上浮 + `FadeEffect`),保留纯 `SkeletonScope`。
- `test/auth/widgets_test.dart`、`test/mine/account_settings_page_test.dart`:
  移除已删除参数调用点(共 9 处)。
- `lib/app/router.dart`:补注释记录 tab 分支**按需加载**的取舍
  (`preload: true` 已试过并放弃 —— 首次切换的构建成本被挪到启动,冷启动变重)。

## perf(design,ui): 按 profile trace 修掉骨架 shimmer 的每帧 saveLayer 与图标的 42ms 解码阻塞

### 数据来源

用户提供的 DevTools 性能快照(profile 构建,Android,Flutter 3.47.1,GLES 后端,
60Hz,592 帧 / 23.4s,覆盖"启动 → 切 tab → 进/退登录页 → 回今日 → AI 对话弹登录提示")。
快照内的 `traceBinary` 是 Perfetto protobuf(`Trace{repeated TracePacket=1}`;
TracePacket 10=sequence、11=track_event、12=interned_data、60=track_descriptor;
TrackEvent 1=timestamp_delta_us、9=type、11=track_uuid、23=name),本地无 schema,
按字段号手工解码后按 track 配对 slice 起止得到时长。

### 关键发现(修正了此前的判断)

| 指标 | 实测 |
|---|---|
| UI 线程帧耗时(`Frame`) | p50 1.17ms / p90 2.64ms / max 15.56ms,**超预算 0/592** |
| Raster(`GPURasterizer::Draw`) | p50 15.31ms / p90 18.23ms / p99 29.66ms,**超预算 153/591(25.9%)** |

1. **瓶颈在 raster,不在 Dart 侧** —— 本轮新增的过渡都在 UI 线程(1–2ms),不是主因;
   raster 中位数已占满 16.67ms 预算,任何额外 raster 开销都会掉帧。"首次切 tab 卡顿"
   的那一帧是 UI 15.6ms + raster 29.7ms,UI 未超预算而整帧被 raster 拖垮。
2. **骨架 shimmer**:`InlineSkeletonCircle` / `InlineSkeletonSection` 各自包一层
   `Shimmer.fromColors`,每个 `Shimmer` = 一个 `ShaderMask` = **每帧一次
   `saveLayer`**。实测启动期 `Canvas::saveLayer` ≈ 22 次/帧、raster p50 15.7ms;
   内容加载后降到 1–5 次/帧、raster p50 3.7ms。
3. **登录页进入**:`ImageCache.putIfAbsent` **41.8ms** + `listener` 41.7ms
   (`AssetBundleImageKey`),叠加 `ConcurrentMark` 31.3ms 与 3 次 `flutter/assets`
   读取(8–13ms)。根因是 `app_icon.png` 为 **1024×1024(解码位图 4MB)**,
   而调用点只渲染 24–64 逻辑像素。
4. 登录页本身渲染便宜(raster p50 3.7–5.5ms),说明 auth 过渡实现无问题。

### 变更

- `lib/core/widgets/common/feedback/skeleton.dart`:新增私有 `_ShimmerScope`
  (InheritedWidget);`SkeletonShimmer` 在已处于作用域内时直接返回 child,
  `StateSkeletonView` 也提供作用域。嵌套 shimmer 不再各建一个 mask →
  每帧 saveLayer 从 ~22 降到 ~1。
- `lib/core/widgets/common/control/brand_icon.dart`(新增):`BrandIcon`
  统一渲染 `assets/icon/app_icon.png`,按 `size × devicePixelRatio` 作为

## fix(core,assistant,settings,design): reduce motion 收敛,并定性"稳定后仍在调度帧"

### reduce motion

  设置要避免的每帧动画),退化为静态块;`SkeletonShimmer` 与 `StateSkeletonView` 两处。
- `above_composer.dart`:assistant「正在切换会话」的旋转指示在开启动画缩减时不再套
  `flutter_animate` 的 `.rotate()`(它是一层额外的 `RotationTransition` + `repeat()`),
  指示本身保留、只是不动。

### 定性"切 tab 后 3s 仍有帧被调度"

逐帧探针(开 `debugPrintScheduleFrameStacks`)显示恒定 1 个 transient 回调,即一个 Ticker
永久自续。二分法:把 5 个分支换成静态占位、其余(shell chrome / 分支容器 / Forui 组件 /
测试宿主)全部不变时 `transientCallbackCount` 立刻为 **0**;单独探 Forui 组件也不复现。
结论:来源是**加载态**的无限动画(`Shimmer`、Forui `FProgress`),数据加载完成即停,
**不是泄漏**;测试里 mock 数据不解析,故看起来"永不停止"。

### 由同一探针记录到的 Forui 事实(未修,记为已知缺口)

`FProgress`/`FCircularProgress` 自带 `repeat()`,且经 `FAccessibilityScope` 读的是
**平台** `AccessibilityFeatures`,不是 MediaQuery —— 应用内「减少动画」开关对它无效
(平台级无障碍开关可以)。框架的 `AnimationController` 也刻意不压缩 `repeat()` 动画
(`AnimationBehavior.preserve`)。要真正覆盖它需要单独包一层 `FAccessibilityScope(data:)`。

  测试由子节点决定,点击落不到检测器;且 Profile 侧草稿为空时传入的空 `Uint8List` 让分支走错,
  表现为点头像完全无响应。手势下沉到 `AvatarView.onTap`(`HitTestBehavior.opaque`)。
- **单一操作入口改成居中弹窗**:头像本体与编辑角标打开同一个 `showAvatarActionsDialog`(原
  `showAvatarActionsSheet`)。改为 `showAppDialog` 居中弹窗而非底部 sheet:标题居中,选项平铺
  在同一面上、以 `AppDivider` 分隔,不再有 `FTile` 自带的逐项卡片边框与底部拖动条。
  「查看头像」是弹窗第一项,仅在存在头像时出现;`AvatarAction.view` 由调用方接
  `showAvatarViewer` / `showAvatarBytesViewer`(后者为本轮新增的草稿查看入口)。
  `AvatarActionView` 因此不再有独立的 `onView` 回调——头像体没有自己的动作,点击永不含糊。
- **上传入口语义修正**:「移除头像」不再依赖 `hasAvatar` 条件隐藏——无头像时它是无操作项,
  隐藏只会让弹窗只剩一个选项。
- **只读查看器保留**:全屏查看(`avatar_viewer.dart`)是 Phase 2 的交付物,继续保留;本轮为它
  补了 `showAvatarBytesViewer`,本地草稿(裁剪后 bytes)未上传也能看大图。
- **死代码与孤儿 ARB 清理**:删除 `account_manage_helpers.dart` 的 `ProfileSection`(无生产
  调用方),以及只服务它的 8 条串(`authProfileSectionTitle`/`authProfileSectionDescription`/
  `authAvatarLabel`/`authAvatarHint`/`authAvatarPreviewEmpty|Ready|Invalid`/`authProfileSaveAction`)。
